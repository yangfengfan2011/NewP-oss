# Audit 模块边界 v1

## 1. 模块定位

`Audit` 模块负责平台的最小审计能力。

它解决的问题是：
- 哪些操作需要被记录
- 哪些访问需要被记录
- 平台如何统一写入审计事件

它不负责：
- 报表平台
- 大屏可视化
- 历史日志的全量迁移

## 2. 当前边界

### 纳入范围

- 操作日志模型
- 访问日志模型
- 审计事件写入接口
- 宿主接入点
- 最小查询接口

### 排除范围

- 复杂分析与统计
- 大规模日志归档平台
- 审计报表设计器

## 3. 输入与输出

### 输入

- Host 中间件或过滤器产生的访问事件
- 模块业务操作产生的审计事件
- 配置变更、授权失败等关键平台事件

### 输出

- 审计写入结果
- 审计查询结果
- 标准化审计事件结构

## 4. 推荐内部结构

- `Audit.Contracts`
  - 审计事件模型
  - 审计写入接口
  - 审计查询接口

- `Audit.Core`
  - 事件组装
  - 事件规范化
  - 审计级别或类型分类

- `Audit.Infrastructure`
  - 审计持久化
  - 查询实现
  - 与宿主接入

- `Audit.Web`
  - API
  - 最小查询页或管理页

## 5. 与其他模块的边界

### 对 Host

- Host 负责接入通用访问审计点
- Host 不负责实现审计存储

### 对 Authorization

- 权限拒绝事件可以交给 Audit 记录
- Audit 不负责权限判断

### 对 ConfigCenter

- 配置变更事件可以交给 Audit 记录
- Audit 不负责配置状态管理

## 6. 旧平台参考来源

当前最值得参考的旧模块：
- `Source\7_Business\05_OperateLog\*`
- `Source\7_Business\00_Utility\Hoteam.InforCenter.OperateLog.Utility`

参考原则：
- 参考操作日志与访问日志的最小字段
- 不直接复制旧存储结构和历史查询界面

## 7. 最小可交付版本

V1 最小可交付版本应包含：
- 访问日志写入
- 操作日志写入
- 审计查询接口
- 与 Host / Authorization / ConfigCenter 的最小接点

## 8. 风险与提醒

- 容易把 Audit 做成报表项目，导致范围膨胀
- 如果没有统一事件模型，后续模块会自己写日志
- 如果把查询和分析一次性做太重，会拖慢主干推进
