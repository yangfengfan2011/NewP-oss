# 身份安全事件是事务内持久事实

账号创建、ENAME 修改、启停、删除、凭据修改或重置以及本地管理员初始化，都必须在 Identity 内写入带 EID 的不可修改安全事件，并与对应状态变更在同一事务中提交。操作者由 `ActorKind = User | LocalMaintenance | System` 和可空 `ActorAccountEID` 表达；事件同时记录固定事件类型、原因、时间、目标 User EID 与 TraceId，不复制可漂移的操作者名称，也绝不记录明文凭据。管理员发起的账号停用、启用、删除和凭据重置必须提供 Trim 后 1–500 个字符的原因，允许多行，本地管理员维护命令同样适用；ENAME 修改和用户自助修改凭据使用固定系统原因，不要求用户填写。ENAME Trim 后必须为 1–128 个 Unicode 字符，相关字段越界统一返回 validation ProblemDetails。成功登录与退出由 Authentication 的会话创建和撤销事实表达，失败登录只进入结构化安全日志与限流指标，三者都不复制为 Identity 安全事件。安全事件首阶段永久保留，不提供删除接口或自动清理；Identity 账号详情提供只读、倒序分页的安全事件区域，Deleted 墓碑详情复用该视图，首阶段不建设独立的全局事件页面。以后 Audit 只能消费或展示 Identity 已持久化的事件，投影失败不改变原始安全操作的结果。现有 Audit 仓储仍是可选的内存实现且产品端点被冻结，因此不能成为这些安全事实的真源。
