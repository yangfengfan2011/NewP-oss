# Authorization 模块边界 v1

## 1. 模块定位

`Authorization` 模块负责新平台的权限与授权能力。

它解决的问题是：
- 平台内有哪些权限点
- 谁拥有这些权限点
- 后端如何做授权判断
- 前端如何做菜单、路由、页面级权限控制

它不负责：
- 完整身份认证流程
- 用户生命周期管理
- 组织树管理
- 多租户完整隔离

## 2. 当前边界

### 纳入范围

- 权限点定义模型
- 角色模型的最小子集
- 角色与权限点关系
- 授权检查接口
- 后端声明权限点的方式
- 前端权限守卫接入点
- 与菜单/路由声明的衔接点

### 排除范围

- 用户管理模块完整实现
- 组织与岗位体系
- 三权分立或复杂授权审批流
- 外部统一身份认证深度集成

## 3. 输入与输出

### 输入

- 模块声明的权限点
- 当前主体的授权信息
- 菜单和路由上的权限要求

### 输出

- 是否有权访问接口
- 是否有权展示菜单
- 是否有权进入页面
- 权限检查失败的标准化结果

## 4. 推荐内部结构

- `Authorization.Contracts`
  - 权限点描述
  - 授权检查接口
  - 授权结果模型

- `Authorization.Core`
  - 权限解析
  - 授权决策
  - 角色与权限关系的应用逻辑

- `Authorization.Infrastructure`
  - 授权数据存取
  - 缓存
  - 与宿主接入

- `Authorization.Web`
  - API 接口
  - 宿主注册
  - 前端契约输出

## 5. 与其他模块的边界

### 对 Host

- Host 只负责接入授权中间件、权限检查管道和声明聚合
- Host 不应自己实现授权规则

### 对 ConfigCenter

- Authorization 可以读取配置，但不拥有配置中心
- 与权限有关的开关应通过配置接口读取

### 对 Audit

- 授权检查结果可以输出审计事件
- 但 Authorization 不直接实现审计写入细节

### 对未来 Identity / Organization

- 当前只预留接入点
- 不把用户、组织、岗位的完整模型提前塞进来

## 6. 旧平台参考来源

当前最值得参考的旧模块：
- `Source\7_Business\15_ModulePermission\*`
- `Source\7_Business\27_ThreeRoleAuthPlatform\*`

参考原则：
- 参考权限点结构和授权流程
- 不原样搬迁旧对象模型
- 不原样沿用旧数据层

## 7. 最小可交付版本

V1 最小可交付版本应包含：
- 权限点声明机制
- 角色-权限关系的最小实现
- 后端接口授权检查
- 前端菜单/路由权限守卫
- 最小测试覆盖

## 8. 风险与提醒

- 如果过早把组织、用户、租户一起并入，会显著扩大范围
- 如果把授权逻辑写进 Host，会破坏模块边界
- 如果没有统一权限点声明机制，后续模块会各自为政
