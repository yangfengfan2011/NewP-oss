# Authorization

Authorization 上下文拥有角色、用户角色关系、功能点索引和角色功能授权，把已认证主体、完整活动功能目录与端点执行绑定解析为服务端访问决策。它不拥有登录凭据、Cookie、业务数据或前端可见性状态。

## Language

**认证（Authentication）**：
验证请求由哪个主体发起，并建立服务器可信的主体标识。认证成功不表示主体有权执行任意业务操作。
_Avoid_: 授权、角色检查、登录后全放行

**已认证主体（Authenticated Subject）**：
由认证机制建立、具有稳定 subject ID 的请求主体；判权只使用服务器可信标识，不接受请求体或查询参数提供的用户 ID。
_Avoid_: 当前用户参数、前端用户对象、角色名

**Endpoint Access Rule**：
一个服务端 endpoint 的终态访问分类：公开、仅认证、Host policy、显式功能位置或拒绝。模块业务 endpoint 和 Standard CRUD 不允许缺少终态规则。
_Avoid_: 前端路由 guard、Controller 内手写 if、默认登录即可

**授权决策（Authorization Decision）**：
一次可信主体、已登记功能位置及其绑定行为的结果：Granted、Denied 或 Indeterminate。Indeterminate 表示依赖故障，必须 fail closed，但不伪装成业务拒绝。
_Avoid_: bool 默认 true、前端可见性、异常即放行

**本地管理员（Local Administrator）**：
沿既有初始化机制建立的受保护角色及其主体。角色获得当前完整功能目录的显式授权，仍执行正常功能判权；普通管理入口不能修改其受保护定义或分配。
_Avoid_: root、权限通配符、角色名硬编码放行

**当前主体功能投影（Current Subject Feature Projection）**：
返回给 Shell 的当前已认证主体有效功能位置，用于菜单、Tab 和动作体验；它不替代服务端 endpoint 授权。
_Avoid_: 任意用户权限查询、授权事实源、Cookie 权限快照

**功能授权点（Feature Authorization Point）**：
角色直接授予的功能单位，包括导航、Tab 和动作；页面承载内容，不是单独勾选的功能授权点。
_Avoid_: 独立业务权限代码、页面权限、接口权限

**功能授权树（Feature Authorization Tree）**：
按导航、Tab 与动作的声明位置组织功能授权点的树；标准页面和自定义页面的功能采用同一授权模型。
_Avoid_: 页面实现注册表、接口调用树、角色继承树

**授权位置（Authorization Placement）**：
功能授权点在所属入口及声明结构中的位置；不同位置的动作分别授予，即使名称或业务实现相同。
_Avoid_: 按钮显示名称、屏幕坐标、共享实现身份

**入口依赖（Entry Dependency）**：
一个功能授权点所依赖的本分支入口授权；角色授权集合必须满足该依赖，其他分支的入口不能替代。
_Avoid_: 隐式连带授权、任意可达路径、跨角色依赖补齐

**入口归属（Entry Ownership）**：
页面内容及其读取所属的导航或 Tab 授权位置；没有独立可见入口的详情直链也有明确归属，弹窗沿用发起位置。
_Avoid_: 来源页、浏览器访问历史、独立页面权限

**节点类型分组（Node Type Group）**：
功能授权树内用于区分不同树节点类型操作的展示分组，本身不单独授权；具体业务记录不是该分组的子授权点。
_Avoid_: 记录授权、每条记录的权限节点

**授权管理员（Authorization Administrator）**：
通过角色显式获得授权管理动作的可信主体，按获授动作在全局范围内管理角色功能或用户角色关系；该资格不专属于 LocalAdmin，也不自动包含未授予的其他管理动作。
_Avoid_: 角色名特判、只能授予自身已有功能、自动获得全部管理权限

**功能点索引（Feature Point Index）**：
正式功能目录的持久化索引投影，用于关联角色授权和识别目录变化；它不拥有独立的业务权限含义或可编辑的功能定义。
_Avoid_: 第二份权限目录、功能声明真源、完整页面结构副本

**功能授权工作台（Feature Authorization Workbench）**：
供授权管理员选择角色、查看完整功能树并配置该角色功能授权的独立入口；只读访问与保存授权分别授予。
_Avoid_: 角色详情授权弹窗、角色基础信息编辑、用户角色分配

功能位置的身份、入口依赖和切换边界见 [ADR-0048](../../adr/0048-functional-authorization-uses-entry-positions.md)。

### 按钮动作权限（岗位编辑已采用，其余入口迁移中）

本节目标及其与现有执行合同的替代范围见 [ADR-0057](../../adr/0057-buttons-declare-object-actions-and-business-inputs-own-targets.md)。岗位列表与查看 Drawer 的编辑、工作区上下移已分别采用自身的 object/actions 声明；其他按钮及所有查询来源继续使用各自现行协议，不因声明解析失败切换路径。

Kernel 从按钮结构派生身份、业务绑定和合法功能位置，运行时投影由平台生成。SDK 传递 `X-NewP-Button` 与 `X-NewP-Feature`，服务端 `IButtonExecutionAccess` 核对活动声明、真实端点业务绑定和正式目标，全部要求允许后调用业务；新旧身份混写、缺失、未知或串用均拒绝。未配置数据要求的已登记业务按钮同样有身份，不自动追加对象动作。岗位详情编辑沿真实 List 到 Detail 引用展开独立 detail.pageActions 位置；列表与详情各自传递实际按钮身份和功能位置，交叉串用拒绝。已有列表资格不隐式授予新增详情动作。

`IObjectActionAccess.CheckAsync(objectName, objectId, actions)` 是 Authorization 拥有的通用接口，不要求执行合同；逐动作复用完整读取约束、动作启停和原对象裁决，全部允许才成功，依赖故障传播。岗位编辑在原事务内保护读取旧值，以路由目标与旧值 EID 核验后进入该管线；写后读取仍只决定详情或成功回执。下文执行合同说明适用于尚未迁移的入口与独立读取来源。

自定义业务通过 `IButtonBusinessHandler<TInput,TState,TResult>` 提供正式输入规范化、原保护边界、同一规范目标及实际业务；`IButtonBusinessExecutor` 在边界内自动检查后才执行业务。真实端点以处理器类型绑定，业务身份复用 RequireFeature，启动时核对注册与活动按钮，不增加权限合同或逐调用者许可清单。无 dataAccess 的生效按钮仍须有真实身份，但不自动追加对象动作；有要求却无目标则拒绝。

正式出现位置可作为可重新验证的读取上下文交给资源原约束，不是允许标志。工作区排序的完整父位置在原图锁内解析，资源约束复用原空间/链验证并核同一 FolderId；普通对象访问仍排除空间根。通用授权不认识 Workspace 类型，规则 read、动作启停和依赖故障仍沿同一访问引擎。

**按钮动作权限声明（Button Action Permission Declaration）**：
按钮自身对对象类型及所需动作权限的唯一声明，由平台对本次业务操作的实际目标自动判权。它不重复定义主体授权，也不按业务复杂程度区分按钮类型。
_Avoid_: 独立执行权限清单、按钮类型模式、客户端允许结果

**正式业务目标（Formal Business Target）**：
正式业务输入契约明确为本次操作目标的规范对象或对象集合，平台对这些目标逐个检查按钮声明的动作权限，其他对象由业务按需要检查。目标定义属于业务输入契约，不形成独立权限配置，按钮判权与业务执行使用同一目标。
_Avoid_: 页面展示对象推断、权限专用目标参数、请求中任意同名标识

**业务主动判权（Business-Initiated Permission Check）**：
业务实现根据自身语义选择是否进行、针对哪些对象和动作、在何时进行的权限检查。它使用通用判权能力，不要求额外的按钮权限声明。
_Avoid_: 所有业务必须判权、复杂按钮模式、隐式继承按钮允许结果

### 数据范围授权（已确认目标，按 #227 分片交付）

以下术语属于 [正式规格 #227](https://github.com/yangfengfan2011/NewP/issues/227) 的已确认目标，来源讨论 [#226](https://github.com/yangfengfan2011/NewP/issues/226) 已关闭；职责边界见 [ADR-0052](../../adr/0052-data-scope-authorization-keeps-management-and-action-boundaries.md)。

**数据范围授权（Data Scope Authorization）**：
决定某主体的某个动作可以作用于哪些资源对象的授权，不替代认证、功能授权、系统强制隔离或业务必需约束。
_Avoid_: 功能入口授权、列表筛选、字段授权

**数据授权动作（Data Authorization Action）**：
数据范围裁决所针对的独立动作定义，可被多个功能入口引用，与功能授权点的声明位置分别表达对象操作含义和入口资格。其启用状态只决定是否执行该动作自身的数据范围裁决，不表示业务动作或功能入口停用。
_Avoid_: 按钮位置、对象操作扩展点、资源名称、功能入口启停

**数据权限绑定（Data Permission Binding）**：
入口对正式执行合同的明确引用，由前后端共同使用同一次装配的有效要求；同一执行可在不同功能位置分别绑定。它不授予功能入口资格，也不替代对象的完整访问约束。
_Avoid_: 公共业务操作权限项、功能授权位置、前端授权结果

**执行合同（Data Execution Contract）**：
执行 owner 对目标角色、执行阶段、对象形状、必要数据要求及有限替代组合的固定声明。入口绑定不能删除或替换必要要求。
_Avoid_: 客户端授权结果、业务操作权限目录、通用策略语言

**有效要求（Effective Data Requirement）**：
正式装配将执行合同与合法入口附加要求组合后的结果；保留角色、阶段与各项交集、有限分支的结构，由前后端共同消费。
_Avoid_: 动作字符串集合、点击允许凭证、跨请求授权缓存

Example 标准 CRUD 已使用执行合同：创建针对服务端归一化后的候选，编辑的准备读取与提交前旧值判权分阶段表示，删除保留最终读取和 delete。固定下限由 Standard CRUD 提供者定义，owner Capsule 仅绑定执行身份与实际资源；真实端点在装配时核对 provider，入口不能用直接 actions 改写下限。列表与详情声明引用各自读取执行，数据库侧过滤继续由原读取计划负责。存在声明不意味着额外点击预检；正式请求独立核对声明、功能位置及实际目标。写后独立读取只决定返回详情还是成功回执，不推翻已提交的创建或编辑。

共享写入器对未迁移调用继续消费正式 `DataExecutions` 与显式 `ObjectOperationWriteSource.Declared`；岗位编辑使用平台建立的 `ObjectOperationWriteSource.Button`，不再维护独立 update 执行合同或固定 edit 下限。HTTP 来源核对真实入口；尚未迁移的旧内部 Declared 来源核对固定调用者、执行、资源及目标，仍在原候选或受保护旧值位置判权；不存在缺声明选择旧路径、逐调用者 legacy 登记或无执行器构造。Workspace 组合写与 Part、Document 真副本分别在原外层和 owner 判权位置消费正式要求，不用外层允许替代内层裁决。Workspace 私有详情分别使用明确的 entry、固定 API 或可信内部来源，未登记的普通详情调用拒绝。

标准数据包由真实 Blueprint producer 生成 list、create、update，以及实际 DetailView 的 read 合同；无 DetailView 时 descriptor 显式将 read 指向同一 update.prepare，缺少 read 映射仍拒绝，不在端点或服务中猜测别名。已有 enable/disable 复用原 UpdateAsync 及其 update.submit 要求，authorize 非呈现功能动作通过资源短引用消费 Authorization 唯一下限；不生成新按钮或新能力。未迁移的 `dataAccess` 继续引用 execution/resources 及被允许的 additionalActions；岗位编辑只使用 object/actions，同一声明新旧形态混写拒绝。执行 LegacyActions 写法仍拒绝。

底层调用由 `DataScopeDecisionBoundaryTests` 扫描实际 IL 调用位置，变量、常量和具体实现调用均可见。允许的实际位置为统一执行器、Authorization 通用对象动作接口、完整读取边界和独立写后观察，并逐位置说明动作来源；完整读取 resolver 同时核真实接口、DI 和 fixed internal 合同的引用，不能新增任意允许清单。Workspace 权限目标的完整读取保留原 Link 可读 404、独立 data-read 403、根约束的顺序与 SQL；纯外部 AddReference 使用自己的固定 API parent/target 要求，不能借界面声明。

通用对象授权能力的固定下限由 Authorization 的活动 provider 贡献，Example、Organization 四资源、账号、角色、Part 和 Document 只绑定各自资源。Workspace 的异构 LID 入口使用执行 owner 模式，明确引用 Folder、Part、Document 资源集，不能冒充其中每个资源的 owner；全部资源均核对活动目录及模块依赖。单资源 owner 通过 `resourceKey` 短引用，执行 owner 集合通过 `resources` 短数组引用固定能力，两者互斥；消费者不能改写能力的要求、阶段、形状或分支。通用 Authorization 端点只消费自己明确登记的能力，仍核实际资源 owner 与原 authorize 功能位置；Workspace 集合来源只能为所属 Folder 的通用管理使用，不能借到 Part/Document 的独立管理入口。

Part、Document 和 Workspace 的既有只读权限页及行入口分别携带自己的查看声明，保持原完整 read，不新增 authorize 功能或数据资格。owner 的 explanation、catalog、字面 subjects/user 也接受管理来源的辅助 view 角色，仍只执行原 read；其他主体候选、eligibility、完整配置及保存执行 read + authorize。通用对象管理端点的所有辅助读取保持 read + authorize，Example 的既有“查看授权”也不降格。单对象与批量保存沿原图锁、全部 ACL 锁和事务重验，成功后自身失权不追加回读。共享输入按声明身份隔离草稿、取消及未知提交状态；批量准备允许合法空筛选，但空结果也先核声明、功能位置与允许零目标的准备角色，保存和显式核对保留原非空集合守卫。

对象权限查询、单／批量管理、候选准备与父授权初始化只保留显式来源接口，null 或空来源在配置读取与锁之前拒绝。执行接口不提供迁移期默认实现，生产服务组合必须提供真实执行器。纯 API 与可信内部执行使用各自固定绑定，不能作为界面缺声明的回退。Workspace 的无界面候选、空间根详情、兼容位置与 AddReference API 核真实 RouteEndpoint、HTTP method、endpoint module、活动 provider/资源及依赖；查询在原 SQL 位置取得同一计划，对象动作在原裁决位置消费角色。

回滚须同时恢复一致的合同、声明、服务调用与装配版本；保留原权限配置、审计与已发布迁移，不恢复缺声明放行或仅功能授权的旧数据路径。

可信内部对象执行只接受正式 internal 合同及精确固定调用者，复用同一角色裁决器。资源 owner 可在原读取阶段完成后提供受控当前事实；执行器核对同一请求、主体、目标、阶段及来源引用，不接收允许布尔值或跨请求结果缓存。Document 文件摘要反馈、正式下载、文件 owner 下载校验和锁内释放各自建立本阶段事实；上传、取消和首次／幂等确认保持原凭据与事务证明，不新增对象 read。

归属转交以中央固定 `entityOwnership.transfer` 下限在原 owner 检查后的 edit 位置消费 prepare／submit 要求，读取依赖仍由同一 edit 动作的 RequiresRead 执行，不另加对象读取。Part／Document 归属维护使用固定 query/read、visibility/read（404）及 target/edit（403）角色，Workspace 的有限 owner 执行在原 Link 查询和 edit 位置消费要求，已有固定内部 Link read 保留；资格与接收人最小目录仍按原 AdminOnly／功能守卫，不增加业务对象读取。通知仍是接收人的私有记录，目标与发送者名称在原分组批量读取点使用精确固定内部来源，不把通知登记为新 ACL 资源。

多对象角色保留集合整体基数、按资源选择的有限替代动作和服务端选择的有限阶段分支。可信解析器由执行合同选择并返回真实目标及业务事实，客户端不能提交允许结果；完整读取在该解析位置执行一次，再对解析出的真实对象判动作。结果按原输入顺序逐项消费，业务 owner 可在下一对象判权前保留原业务错误。资源目录按当前资源的结构化要求校验动作适用性，不把兼容动作摘要展平后交给所有资源。

标准列表、详情、Position options 及 Example、人员 current/all 导出引用固定读取合同。Organization 的四个自定义候选来源和关系树也引用各自正式读取执行，在原 SQL 位置取得同一最终计划；候选与当前值集合分开，组织树保留不可读父节点截断。查询定义集合通过原查询计划在数据库侧过滤，再计数、排序和分页；显式当前值集合独立表示，保留原分片读取与不可读名称 `***`。声明来源包含实际 provider、执行和合法功能位置；导出不能借用列表声明，详情只接受正式 read 或已登记编辑准备读取来源。读取上下文由服务端创建，不接受 JSON 自报。完整详情从已读取快照进入编辑，不切换读取身份或追加准备 GET；列表抽屉原有编辑准备读取仍消费 update.prepare，提交另行消费 update.submit。

关联显示、账号摘要、审计名称和 Workspace 既有 Properties、编辑取值、单对象复制准备的内部详情读取，使用精确调用者、执行及资源的固定内部绑定，在原 SQL 位置取得计划或批量可读 ID；它不代替原业务来源资格、图锁或动作裁决，也不能补救 HTTP 缺声明。批量适配器只在实际调用时解析同作用域执行器，避免展示目录与可信解析器的构造依赖闭环，不缓存允许结果。

Workspace、Part、Document 的普通履历入口、列表、详情、预览、导出和打印现已引用 owner 固定完整 read 执行，不在入口重复 `actions: [read]`。点击预检与服务端执行共同消费同一有效要求，预检不产生授权凭据；服务端仍重验完整对象与来源。数据动作目录和资源适用集合不再包含 `history`；原履历功能点、导航、Tab 与端点功能资格保持不变。

Organization 的初始化、人员启停及永久账号绑定按具体服务端执行保持原 AdminOnly／功能资格，沿原业务、账号及会话事务执行；不新增数据声明、对象 read/edit 下限或强制点击预检。授权管理的主体目录继续按管理资格读取，不套业务候选的 read 过滤。

账号与角色的既有非呈现 authorize 来源及通用对象授权管理读写采用同一 read + authorize 管理要求；没有独立只读查看入口的资源不新增按钮或资格。角色标准查询、账号角色输入的角色选项及功能授权工作台目录／详情保持原数据读取计划；工作台通过其真实自定义 PageRef 的正式来源进入，同一执行以有限 catalog／detail 分支保留 query 和 object 形状。账号 snapshot 与安全事件摘要透传本详情 root read 声明，摘要查询身份包含声明 ID。原 GET /authorization/roles 全局管理目录、账号候选、已配置角色、功能／规则配置和角色管理命令保持各自原功能资格；Identity 原 AdminOnly 及已关闭 Role 删除入口不变，不因原数据读取拒绝增加管理门槛。

**规则授权（Rule Authorization）**：
以条件及其层级限定适用对象，并由匹配主体授权项表达动作意见的授权配置。
_Avoid_: 主体基础资料、对象 ID 清单、展示顺序

**对象授权（Object Authorization）**：
针对明确资源类型及对象身份配置的主体动作授权，其明确结果优先于同一对象、同一动作的规则授权结果。
_Avoid_: 功能授权点、只有裸 ID 的授权、每个对象一棵规则树

**对象授权管理资格（Object Authorization Management Eligibility）**：
管理某个对象整份授权配置的独立资格，要求相应功能资格及该对象的最终读取和授权动作允许；可管理自身及他人的授权项、调整优先级和转授授权动作，不以操作者自身已有业务动作权限为上限。
_Avoid_: 对象编辑资格、授权项创建者所有权、只能授予自身已有权限、整类规则管理资格

**创建人授权主体（Creator Principal，已确认目标，待实现）**：
指向被授权对象自身创建人的动态主体。把该授权项用于新对象时，按新对象的创建人判断，不固化为来源对象创建人的用户身份。
_Avoid_: 来源创建人快照、固定用户授权

**对象权限查询（Object Permission Inquiry）**：对可浏览对象查询指定用户的动作权限及受控依据的只读操作。对象的“权限”页签随对象浏览可用，不另需授权管理或权限分析资格，也不授予修改授权的权力。
_Avoid_: 对象授权编辑、仅限本人查询、额外权限分析资格

**规则管理资格（Rule Management Eligibility）**：
由独立功能授权授予的规则维护资格，LocalAdmin 具备，普通用户也可获授；它与具体对象上的授权管理资格分别授予。
_Avoid_: LocalAdmin 专属身份、对象编辑资格、对象授权的自动附带资格

**数据范围豁免（Data Scope Exemption）**：
LocalAdmin 不受规则授权及对象授权限制，且无需执行该层条件的特定资格；它不豁免其他访问与业务约束，也不豁免授权配置的有效性校验。
_Avoid_: 普通授权管理员资格、功能权限绕过、任意故障放行

**授权主体目录（Authorization Subject Directory）**：
在相应授权管理资格与系统强制隔离约束下，提供配置所需主体身份、名称和必要层级的最小目录；它允许识别业务页面不可读的主体，不授予主体业务记录的读取权。
_Avoid_: 业务 Lookup、完整主体档案、对象读取授权

**读取条件（Read Condition）**：
授权条件中明确用于读取范围裁决的部分；未提供读取条件不等于授权条件执行故障。
_Avoid_: 完整业务判断、缺失即恒真、故障即未配置

**读取依赖（Read Dependency）**：
某个动作要求目标对象的最终读取权限同时允许的前置关系；动作同意不自动补授读取权限。
_Avoid_: 自动补权、入口依赖、所有动作的隐含共同前提

**公司主体（Company Subject）**：
按人员当前公司归属匹配该公司全部人员的授权主体，不另外区分公司本级与下级部门人员。
_Avoid_: 直属公司人员、租户、公司节点可见性

**部门主体（Department Subject）**：
按人员当前部门归属匹配的授权主体；授权项选择仅本部门或同时包含其下级部门，默认仅本部门。
_Avoid_: 部门资源的数据条件、公司全体人员、组织准入

## 对象直接项与完整访问边界

- 直接项的规范选择器身份是 `Type + SubjectId + MatchOptions`。`IncludeDescendants=false` 与缺省/null等价，true 是另一范围选择器；因此同部门本级和包含下级可分别配置。优先级、动作、绝对期限及技术 `entry.Id` 是选择器的配置内容或存储身份，不进入选择器身份。完整替换拒绝重复规范选择器；仅重新生成技术ID、调整顺序或显式unset不构成语义修改，不写入或登记假事件。审计仍保存实际配置行身份，不改写旧记录。
- 期限只属于直接项 DTO，规则输入仍拒绝未知期限字段。非空期限沿平台 Instant 输入规范化为UTC秒，null永久；等于截止仍有效，超过后allow/deny都不贡献意见，再回到规则和既有默认。SQL读取范围、标量、read依赖和解释使用同一观察值，所有优先级比较前先排除到期项。
- `IDataScopeEvaluationScope.BeginOperation` 提供一次逻辑操作的UTC观察，内层复用，HTTP是旧native消费者的默认边界。只有已提交成功后的对外读取用 `BeginReadAfterWrite` 开启新观察，整个读取/显示/摘要共享新值；取消和异常释放范围。它不缓存身份、规则或授权结果。
- 既有通用对象授权GET/Explain及保存继续要求authorize。新增可浏览查询由真实owner入口提供：Workspace先解析LID和完整位置，再交同一查询服务；其他owner沿自身正式入口。被分析账号显式传入裁决，不替换操作者。旧未声明新接口的native资源不因此取得新查询出口。
- 显式`ReadConstraintKey`与owner静态绑定在活动候选确认前验证，不构造scoped实现；请求在资源目录准备后解析同一scoped约束。该约束与data read相交，覆盖旧管理出口，不回调底层GetReadPlan，避免Folder范围递归；空间根参与遍历，但不是普通对象授权目标。
- 动态直接项 `creator`、`owner`、`ownerDepartment` 不接收客户端主体ID，分别关联目标真实 `CreatedBy`、`OwnerId`、`OwnerDepartmentId`。可用性由正式 ENTITY 的平台审计/归属投影标记派生，不限于首批三个模型；未选归属字段的 ENTITY 只提供实际拥有的类型。规则主体目录不增加这些相对类型。匹配复用既有账号/部门事实，所属部门包含下级仍须显式选择；缺失或未知事实不匹配，事实源故障继续传播。SQL相关 EXISTS 与单对象意见使用相同目标关联，不物化对象全集或逐行查目录。
- 通用单对象、owner单对象与批量手工写入由 `DataScopeObjectManagement` 的同一内部流程拥有：规范目标排序、取得全部ACL锁、重验全部完整read/authorize、校验并规范化全部配置，最后登记实际变化并保存。通用入口只前置功能资格，不在锁前重复数据判权；owner保有功能与完整来源责任，Workspace图锁仍先于ACL锁。无资格时不公开配置校验细节，成功后自身失权不改报失败。既有单对象与批量Contracts保持不变。
- 手工写入使用既有 `IEntityAuditValueProvider.BeginOperation` 覆盖事务执行器返回前的实际SaveChanges，含嵌套保存；实际新增/更新的配置行、动作行和业务记录共享可信stamp，下一次顶层操作取新值，无变化不记事件。父授权初始化继续消费owner外层事务和stamp，不进入手工写入资格流程。保留该provider原有嵌套语义，不把它与授权观察时刻的内层复用混为一谈。
- 真实业务owner通过 `IDataScopeObjectInitializer.InitializeFromParentAsync` 为同资源的新对象初始化父直接项。调用方持有本次业务事务及可信stamp，核证父完整位置的edit和新对象create；初始化不额外要求父authorize或新对象read，不另建审计作用域或提交。初始化锁定父与新对象配置，要求两者不同且目标配置为空，沿同一规范化、验证和存储核心保存；主体项及动作行使用新的技术ID，保留绝对期限、动态选择器、匹配选项、优先级和动作意见。它只供受控owner调用，不向HTTP暴露跳过资格参数；父来源资格在持有配置锁时由owner最终重验。
- 同一受控owner可用 `InitializeFromParentsAsync` 读取并比较全部新父的完整配置语义，排除技术项ID、对象身份和无意见项；全部相同才初始化一次并返回实际采用父对象，供owner登记真实关联事实。当前Workspace单根新图保证同源配置；不同配置按不变量失败关闭，此契约不提供HTTP来源选择能力。
- 资源owner可用 `DataScopeResourceActionBinding` 显式选用已登记全局数据动作，由同一准备期资源目录验证资源、owner、唯一性和动作身份；对象目录、解释、完整替换和实际动作裁决消费同一适用集合。未声明的旧资源保持原全局目录合同，原四参资源构造与解构保留；不按动作定义的模块或首批业务模型名推断适用性，也不静默改写旧配置。

- 批量直接项通过 `IDataScopeBatchAuthorization` 一次提交全部规范资源/EID。默认U保留未指定选择器，并完整替换指定选择器的意见、优先级、匹配选项和绝对期限；R完整替换所有直接项，空资源组须显式确认。资源分组严格匹配实际目标及正式适用动作，不修改规则树或系统来源。owner先锁定并重解完整来源，批服务按资源/EID稳定顺序取得全部ACL锁后重验全部read/authorize；资格、配置、基础设施或取消任一失败均不产生部分成功，实际变化与各对象审计共享本次事务及可信stamp，无变化不记事件。Workspace的LID只校验真实位置与private来源，ACL仍是Folder/Part/Document真实对象身份。
- 显式整组当前配置核对沿同一来源和锁序，全组当前read/authorize都成立才返回直接配置；它不写ACL/审计，也不证明原未知请求曾提交或未提交。客户端未知状态属于当前主体/页面实例，关闭弹层不会允许重放；核对后仍须用户显式开始新操作并清空原模板，不以当前相等或资格拒绝推断先前结果。

## 角色管理与事务性功能配置

角色维护的确定性业务拒绝由 `RoleValidationException` 表达，HTTP 只将此类拒绝翻译为既有 400 Problem Details，保留原文案；持久化、审计来源等依赖故障及取消继续传播，不伪装成请求校验失败。角色删除的 HTTP 禁用规则保持不变。角色、成员和功能配置的可预期拒绝共同继承 `AuthorizationValidationException`，由 `AuthorizationProblem` 保留 HTTP 状态与原诊断并附加稳定 `code`、`reasonKey`、原值 `args` 及适用字段事实；词条由 Authorization authoring 拥有。前端 `authorizationRequest` 复用 SDK 错误提取，组件在呈现时按活动语言解析，同一错误及保存成功消息切换语言不重放操作。功能目录消费编译链保留的词典键，角色名称、功能位置和选择集合保持原值。

- 角色列表与详情普通字段复用 Standard CRUD 的查询与显示计划，但 Authorization 不映射通用写入端点。角色创建和编辑仍须保护 LocalAdmin、角色代码与系统字段，遗留内部删除还承担历史引用测试，因此普通写入由 RoleService 直接持有，不为形式统一注册对象行为或纯转发类；角色删除 HTTP 继续明确拒绝。
- 角色功能授权和普通账号角色分配是 Authorization 拥有的两个完整业务用例。Controller 分别直接调用 RoleFeatureAssignments 与 IUserRoleAssignments；它们不经 RoleService 转发，也不拆成关系逐行 CRUD。两者继续复用平台事务、可信审计和同一授权模块持久化边界。
- 角色读取、创建、编辑、角色功能配置和用户角色分配分别按声明位置判权。普通主体可以显式获得这些管理动作，获授动作在全局范围生效，不以操作者自己的功能集裁剪可配置目录。拥有一个管理动作不自动获得其他动作。
- LocalAdministratorCatalog 收敛受保护角色定义及模块内存中的规范身份比较；共享 Contracts 只公开 Host 与模块共同使用的稳定角色代码。FeatureCatalogSynchronizer 在完整候选准备后同步功能点与 LocalAdmin 全集。管理员不通过角色名绕过正常功能判权，也不重建旧 Permission 目录。
- FeatureCatalogSynchronizer 在事务成功后发布不可变活动目录。历史或失效功能行不能成为授权源；停用角色可以配置，但不进入有效授权。
- RoleFeatureAssignments 统一读取目标角色的当前活动功能集合，并在角色主键写锁内读取实际旧集合、校验完整新集合及本分支入口依赖，通过平台事务统一保存关系和 role.features.changed 审计。相同集合或排列变化不产生分配记录，不引入 Revision 或自动重放。
- Authorization 只引用 Audit.Contracts，由 Audit 登记稳定 authorization.role 目标和字段差异；不形成反向模块加载依赖。缺少 recorder 或登记、写入、保存、确定未提交的提交失败都不会返回成功。当前角色名称由 Authorization 批量提供，删除目标后记录保留 ID。
- 角色列表与详情复用 StandardCrudService 的 Entity display 计划：用户字段批量解析，时间按请求 locale/timeZone 显示，原始审计值保持不变。角色页面未声明删除动作，遗留删除 HTTP 入口继续明确拒绝。
- 独立工作台拥有数据库分页角色选择、完整虚拟功能树和当前角色草稿。节点独立勾选，分支全选是显式操作；搜索保留祖先，筛选保留隐藏选择。保存一次提交完整集合；切换角色和离开页面均保护未保存草稿，失败保留草稿，未知写入结果先查询实际状态。
- 工作台查看和保存分别授权。原角色列表及详情快捷入口只跳转并选中角色，采用目标导航资格，不生成额外授权点或第二套编辑状态。角色基础信息与用户角色输入继续使用共享 CRUD 动作宿主。

## 普通账号角色分配

- 普通管理通过 Identity 稳定账号目录校验全部目标；Disabled 可引用，Deleted 和受保护账号拒绝。现有 LocalAdmin 角色成员独立受保护，整组越界整体失败；内部初始化路径保持。
- Authorization 用户角色替换使用事务级账号应用锁，覆盖首次空集合。锁内读取实际旧关系、完整校验全部角色并登记 user.roles.changed；关系和记录由平台事务统一提交，异常不自动重放。停用角色允许配置但不产生有效权限。
- 差异以规范角色 EID 的 reference 前后值表示增加或移除，目标为 identity.account EID。Identity 和角色目录批量解析当前名称，缺失时保留历史 ID。集合相同或顺序变化不登记。
- 正式角色详情及行操作中的账号角色动作复用共享弹层；账号有界搜索、角色数据库分页，页外已配置选择保留到完整集合保存。

## 当前授权消费与界面同步

- 单次正式判权先将完整位置解析为活动功能点 EID，再以当前主体、用户角色、启用角色和功能授权的一次数据库关联存在性查询判断；不逐角色查询，也不读取用户全部授权来判断单次动作。Shell 的完整功能位置投影是独立读取需求。
- 移除全部启用角色来源才算撤权。同一认证 Cookie 的后续请求使用新授权，已经通过判权的在途请求允许提交，不添加提交前复判或服务端权限版本。
- Shell 页面导航重取当前主体；浏览器刷新沿用启动认证读取。共享请求收到明确 401/403 后触发同一认证 owner 刷新，菜单与按钮只消费返回投影。权限集合变化重建主体查询 scope；写拒绝同时清空旧查询，读拒绝清空自身失败结果，避免重复的读拒绝/刷新循环。本地 query scope 计数只用于缓存失效，不是授权事实或跨请求版本。
- 认证/授权依赖故障保持原始失败及现有认证不可用边界，不将 503 等故障解释成撤权。明确业务拒绝不重放，网络异常或成功写响应无法读取时提示先查询实际结果；只有业务执行前稳定防伪失败仍允许一次令牌恢复。

## 旧授权退出与回退

旧 Permission 和 RolePermission 存储模型仅为既有迁移历史兼容及切换清理保留。完整功能目录、端点绑定及 runtime staging 准备成功后，功能目录同步事务清理旧分配与旧目录；准备失败不清理，事务失败整体回滚。旧行是否存在表示清理是否仍待完成，清空后的启动不再对旧表执行写入，也不清空已经重新配置的普通角色功能授权。

旧权限目录、角色权限读写、任意用户权限查询和旧判权消费者退出正式接口；认证响应和 Shell 使用功能位置投影。用户、角色、用户角色关系、业务数据、审计及迁移历史保持。普通角色切换后通过工作台重新配置，不反推或迁移旧权限含义。

回退须同步恢复目录、前后端授权消费和模块接入。代码回退不能恢复已清空的旧授权，恢复旧机制后仍须重新配置；不改写业务数据、审计或迁移历史。

### 数据范围界面与错误呈现

规则、条件、主体和对象授权共享界面在渲染时消费活动词典，语言变化不重置草稿、分析用户或写入状态。Authorization 拥有 `DataScope` 的公共交互和动作词条；主体、当前身份值和业务条件的贡献模块分别提供 `DataScope.SubjectType_<key>`、`DataScope.Context_<key>`、`DataScope.Business_<key>` 的完整词条，带点的目录键按既有词典根与无点局部键拆分。业务规则名称、主体名称及身份原值不翻译。资源与字段标签仍来自正式 View；枚举身份来自同一 metadata manifest 下 Model 的显式 `dataSource`，仅翻译后端 `enumValues` 已提供的值，不扩充候选。

数据范围配置错误继续返回 HTTP 400 与既有 `DataScope.InvalidConfiguration`，`reasonKey`、`args` 和 `fieldErrors` 保留模块拥有的具体原因。嵌套条件使用 `nodeId`、`conditionPath` 与原始字段／操作符参数定位，不解析诊断文本。对象资格仍按原有 403／404 降级，读取故障和未知写入结果不自动重试；人员采用同一共享对象授权传输与编辑生命周期。回退本地化时同时恢复错误投影、词典和消费者，不重放保存，也不改变授权配置或裁决。
