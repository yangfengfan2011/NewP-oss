# Required 字段使用显式写入与迁移生命周期

字段“必填”同时涉及最终持久化非空、创建输入、更新输入、服务端生成和旧数据演进；用一个布尔值表示全部含义会让表单、写入校验与数据库约束彼此漂移。平台决定把这些语义分开：存储必填表示成功持久化后的值不得为空；创建输入必填只约束由调用方拥有的创建值；Standard CRUD 普通更新保持 PATCH 语义，字段可以省略并保留旧值，但显式提交空值必须拒绝，合并后的候选仍须满足存储不变量；服务端拥有的必填值不要求调用方提交，必须在持久化前由可信 owner 生成。

表单或应用默认值只服务新建交互或应用写入，一次性迁移回填值只服务已有行，二者都不是数据库永久 `DEFAULT`。当前平台不支持数据库永久 `DEFAULT`，Model、Provider Target、migration 和实际 schema 都不得依赖它为新记录补值。模块拥有字段为何必填、值由谁提供以及旧行应取得什么值；平台拥有这些静态声明的投影、写入顺序、最终不变量、迁移门禁、事务、历史、失败和重试语义，不能替模块猜测业务值。

新增 required 字段时，新表或空表可以直接创建非空列；有既有行时，必须按三个有序前向 migration step 执行：先新增 nullable 列，再只对缺失旧值执行一次性回填，最后验证不存在空值并收紧为 required。已有 nullable 字段改为 required 时，若已无空值可直接执行验证与收紧；若仍有空值，先执行一次性回填再收紧。每个 step 独立进入线性 migration history，并由 Host 顺序执行；任一步失败都保持 Host Not Ready，已提交前缀不自动回退。不能把回填与收紧塞进一个依赖“先执行 DML、后检查”的隐式步骤。

Required 字段回填属于模块自有 migration 的受限一次性数据动作：只能修改该 migration owner 拥有的目标，必须显式、确定、可审查、可在迁移事务内执行，并与相应 history 一起提交。平台不为此增加独立 CLI，也不建立通用数据转换平台；具体 migration 可以显式指定回填值或受限的确定性逻辑，测试可以手动准备旧行和指定测试值，但最终 Gate 必须能自动重放旧数据、回填、空值检查和收紧全过程。跨 owner 修改、不可确定的运行时猜值、仅靠人工改库通过 Gate、把回填值保留为数据库永久 `DEFAULT`，都必须拒绝。

如果模块无法给出语义正确的回填值，字段必须继续保持 nullable，或者在实验基线期按 ADR-0042 显式放弃并重建可丢弃数据；平台不得伪造值、自动降级约束或把表单默认值当作历史事实。需要依赖部署配置、外部系统或复杂业务编排才能确定旧值时，应由独立设计确认其 owner、冻结时点与失败恢复，不能把任意回调暴露为公共 migration interface。

## 实施状态

本 ADR 的有界最小纵向能力已由 ExampleRecord 验证：Model 存储可空性与 create/edit required 投影为 Standard CRUD 规范字段策略，旧 RequiredFields 只保留稳定错误展示；创建候选与 PATCH 合并后的更新候选都会检查调用方拥有的存储不变量；SQL Server 模块 migration 可以使用受 owner、目标列、阶段和 CLR 类型约束的标量回填 operation，并由 Host 在同一线性历史中依次执行 nullable 扩展、NULL-only 回填和 required 收紧。该能力不提供任意 SQL、回调、独立 CLI、跨 owner 更新或数据库永久 `DEFAULT`；非 SQL Server provider、复杂确定性逻辑和全仓既有 descriptor 的采用仍须作为后续显式范围处理，不能从本次可行性验证外推为已经完成。
