# NewP Shell 视觉基础设计

**日期：** 2026-04-05

## 概述

本设计定义了 `NewP` 的第一阶段视觉基础。目标不是做最终抛光，而是在第 3 阶段和第 4 阶段继续推进时，先阻止 UI 风格继续漂移，并建立一个同时适用于内部平台开发与外部数字化管理产品使用场景的稳定 Shell。

整体视觉方向应当是克制、专业、耐用。它应该让人联想到工业软件和企业数字基础设施，而不是营销站点，也不是那种花哨但信息密度低的后台模板。

## 产品定位

`NewP` 同时承载两种模式：

- 供内部团队扩展、配置和治理模块的平台
- 供终端客户进行业务操作的数字化管理产品

因此，Shell 既不能按纯开发者工具来设计，也不能按纯面向消费者的仪表盘来设计。它必须支持这两种视角，同时允许在客户部署中隐藏面向平台的一侧。

## 设计目标

- 在更多模块页面继续扩张风格漂移之前，先建立统一 Shell
- 保持均衡的信息密度：可读、舒适，但仍适合长时间高频使用
- 让产品传达出稳定、可控和值得信任的感觉
- 在不复制 Shell 的前提下，同时支持 `business` 与 `platform` 两种视角
- 允许通过静态配置开关，在面向客户的部署中隐藏平台能力

## 非目标

- 最终品牌抛光
- 复杂动效系统
- 花哨的插画系统
- 深色模式
- 整体组件库的大规模重做
- 在这一阶段对每个模块页面进行像素级优化

## 视觉方向

### 品牌线索

当前提供的 Hoteam logo 已经给出了方向：

- 主色相：企业蓝
- 强调色相：工业橙
- 背景：浅色中性表面
- 气质：务实、克制、清晰

### 关键词

- 稳定
- 清晰
- 克制
- 专业
- 可信
- 可扩展

### 密度

界面应采用 `均衡的中等密度`。

这意味着：

- 比传统厚重型后台系统有更多留白
- 比现代低密度产品营销式 UI 更有纪律和结构
- 表格与表单页在日常工作中依然要保持高效率

## 体验模式

增加一个静态 Shell 体验配置，包含三个值：

- `hybrid`
- `product`
- `platform`

### 默认行为

- 内部环境和开发环境默认使用 `hybrid`
- 面向客户的部署一般使用 `product`

### 含义

- `hybrid`：同时展示业务入口和平台入口
- `product`：隐藏平台入口和平台优先导航
- `platform`：突出平台治理和扩展相关工作

这个模式应控制 Shell 入口、首页区块以及导航可见性，不应要求单独构建或分叉代码。

## 布局架构

### 登录页

采用 `左信息 / 右登录` 的布局。

左侧：

- logo
- 一句简短的平台说明
- 两条简洁价值点：
  - 数字化管理产品
  - 可扩展的平台底座

右侧：

- 登录卡片
- 用户名输入框
- 密码输入框
- 主登录按钮
- 行内错误区

登录页应显得正式、产品化，而不是一个临时开发工具页面。

### 全局 Shell

Shell 应保持传统企业软件结构：

- 顶部 Header
- 左侧 Sidebar
- 中央内容区

Header 包含：

- 产品名称
- 当前用户
- 环境或体验模式徽标
- 退出登录动作
- 当模式允许时，提供顶层 `business / platform` 视图切换

Sidebar 包含：

- 基于当前视图的上下文导航
- 清晰的选中状态
- 稳定的间距和层级

内容区包含：

- 页面标题区
- 页面操作区
- 内容面板或表格区

## 首页结构

首页应采用 `双入口门户` 模型。

首屏包含：

- 一张 `Business Portal` 卡片
- 一张 `Platform Portal` 卡片

每张卡片包含：

- 一句简短说明
- 3 到 5 个高频快捷入口
- 一个清晰的 CTA，进入对应视图

在两张卡片下方：

- 最近模块
- 常用操作
- 可选的快速状态摘要

这个结构可以让内部用户快速进入两类工作模式，同时在 `product` 模式下也依然便于客户理解。

## 设计系统 v1

### 色彩角色

- primary：企业蓝
- accent：工业橙
- text-primary：深色中性文本
- text-secondary：中性中灰文本
- border：柔和偏冷中性色边框
- page background：浅色中性灰背景
- surface background：白色或接近白色的表面背景

橙色应谨慎使用：

- 高亮
- 强调标记
- 小范围选中强调
- 需要时用于警示

大面积蓝色表面也应克制。大多数页面应保持浅色、中性、清爽。

### 字体

使用适合中文与企业软件可读性的稳定无衬线字体栈。优先保证清晰，而不是品牌化张扬。

层级包括：

- 页面标题
- 区块标题
- 正文文本
- 数据 / 表格文本
- 辅助文本

避免过大的标题和偏营销风格的松散留白。

### 首批需要标准化的核心组件

- 按钮
- 文本输入框
- 下拉框或筛选条
- 卡片
- 表格
- 标签页
- 徽标 / Badge
- 空状态
- 行内错误状态

### 组件特征

- 小到中等圆角
- 克制的阴影
- 可见的边框
- 使用主蓝色表达清晰焦点态
- 尽量减少装饰性外框

## 当前优先样式页面

现在先处理：

- 登录页
- 全局 Shell
- 首页双入口门户
- 共享按钮、输入框、卡片、表格外壳、标签页、Badge

在继续功能开发时同步推进：

- 权限相关列表与管理页面
- 配置中心页面
- 审计列表页面

后续再做抛光：

- 高级动效
- 品牌化插画处理
- 更丰富的空状态
- 长尾页面级细节优化

## 实施边界

这次视觉基础建设不应：

- 引入重量级 UI 框架迁移
- 重设计模块行为
- 阻塞后端第 4 阶段工作
- 单独创建一个仅面向客户的 Shell

它应当：

- 建立共享设计令牌
- 优化 Shell 结构
- 创建清晰的门户型首页
- 让模块页面在视觉上一致到足以继续安全开发

## 成功标准

当满足以下条件时，这份设计可以认为成功：

- 登录页看起来是产品化且有明确设计意图的
- Shell 能清楚支持业务视图与平台视图
- 首页能立即传达系统的双重属性
- 常用控件共享同一种视觉语言
- 面向客户的部署可通过静态配置隐藏平台入口
- 后续新增模块页面时，不需要每次都重新发明一套样式
