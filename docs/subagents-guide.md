# 通用 Subagents 触发模板

本文档说明如何在任务中使用 subagents 进行并行协作。

## 核心原则

- 主线程保留架构判断和最终决策权
- 子代理并行补足探索、审查、文档核对、测试修复
- 在不扩大范围的前提下，提高任务推进速度

## 何时适合触发 subagents

满足以下至少 2 条时建议触发：
- 当前任务已经有明确边界
- 主线程已知道自己要产出的结果是什么
- 任务中存在可并行的只读探索或审查工作
- 任务不是纯单文件小改
- 任务存在"摸底 + 审查 + 实施 + 验证"这几类天然可拆分的子工作

## 可用的 Subagents

### 1. platform_explorer
- 只读扫描目录、项目、入口文件
- 列出影响范围
- 找关键类、关键接口、关键配置

### 2. contract_reviewer
- 审查模块边界
- 审查 Host / Kernel / Module / SDK 是否越界
- 审查契约设计是否可扩展

### 3. docs_researcher
- 核对版本行为
- 核对框架配置
- 确认某项实现是否符合当前技术栈

### 4. test_fixer
- 跑 build / test
- 修复编译、类型、lint、测试问题

## 严格并行规则

- 主线程负责最终方案与最终改动
- 子代理尽量只做只读探索、契约审查和文档核对
- 真正写代码的线程尽量只有一个
- 不允许两个 live thread 同时修改同一批文件
- 不允许子代理绕开 `scope-v1` 擅自扩大范围

## 执行顺序

1. 主线程明确目标和边界
2. 子代理只读探索
3. 子代理契约审查
4. 主线程汇总，做最终方案
5. 主线程实施代码或文档修改
6. test_fixer 在最后统一验证与修复
7. 主线程输出最终摘要
