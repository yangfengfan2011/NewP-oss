# 标准列表页模板能力一致性 Review

## 1. Review 范围

本 review 只回答一个问题：

**“标准列表页模板能力”这一新增平台设计，是否与当前主线设计、仓库架构约束以及组织模块人员中心试点保持一致。**

本次 review 不进入：

- 代码实现
- 详情页模板化扩展
- 人员中心完整功能实现复核

## 2. 基线文档

本 review 以以下文档为基线：

1. `docs/designs/platform/metadata-driven-backoffice-ui-design.md`
2. `docs/designs/platform/list-management-layout-demo-design.md`
3. `docs/designs/platform/standard-crud-contract-design.md`
4. `docs/designs/modules/organization-person-center-pilot-design.md`
5. `docs/designs/platform/standard-list-page-template-design.md`
6. `AGENTS.md`

## 3. 总体结论

本次 review 的总体结论是：

**标准列表页模板能力设计与当前平台主线整体一致，可以作为下一阶段实施计划的直接输入。**

原因是：

- 它没有推翻三层元数据边界
- 它没有把行为逻辑重新塞回 metadata
- 它没有绕开模块接入契约把业务页抬进 Shell
- 它把首轮目标收敛在“列表页模板能力”，没有把范围膨胀成整套后台页面重做

## 4. 一致项

### 4.1 与元数据边界一致

该设计仍然遵守当前主线：

- `view metadata` 声明页面结构
- `model metadata` 声明字段静态语义
- 模板代码内核负责真实装配与布局

这与仓库“强约束元数据 + 清晰代码内核”的要求一致。

### 4.2 与列表页静态布局主线一致

模板设计复用了既有列表页布局结论：

- 页面头部
- 轻筛选条
- 表格主体
- 底部分页/导出
- 可选高级筛选抽屉

它不是另起一套视觉结构，而是把既有设计稿收口为共享模板实现。

### 4.3 与模块边界一致

模板能力建议落在 `frontend/packages/ui`，而不是直接放进 Shell。

这符合仓库约束：

- Shell 只负责布局、Provider、菜单聚合、路由聚合与受控注册
- 共享页面模式块应优先放在共享层

### 4.4 与人员中心试点一致

该设计没有把人员中心试点替换掉，而是调整了试点实现路径：

- 试点目标仍然是人员中心列表页/详情页等真实业务链路
- 但列表页应优先落到平台模板上
- 详情页仍保留当前 `detail view` 路线，不在首轮扩成平台模板

这与“单轮只聚焦一种能力”的项目约束一致。

## 5. 当前需要显式记录的边界

### 5.1 首轮模板能力不是低代码解释器

需要明确：

- 首轮模板只统一列表页骨架
- 首轮不要求所有查询字段、列和动作都自动渲染
- 业务页仍可保留字段与列的渲染映射

否则容易再次滑向“大而全页面解释器”。

### 5.2 首轮不应同时拉入详情页模板

当前设计已经把详情页模板化排除在首轮主目标之外。这个边界必须在实施计划中继续保持，否则计划会明显扩张。

### 5.3 首轮不应顺手改 Shell

若模板实现过程中出现“必须改 Shell 才能接入”的倾向，应视为偏离本设计。

正确方向应是：

- 模板落在共享层
- 模块页通过受控方式消费模板

## 6. 阻断项与非阻断项判断

### 6.1 当前阻断项

当前未发现新的设计级阻断项。

### 6.2 当前非阻断项

以下事项当前不是阻断项，但实施时需要如实说明：

1. 首轮模板 API 可能先保持偏轻量，后续再补强自动渲染能力
2. 人员中心详情页仍会保留部分专用结构，不纳入本轮模板化收益
3. 列表页模板接入后的视觉优化仍需通过组织模块试点验证，不应直接对外宣称“所有模块立即可复用”

## 7. 建议的下一步动作

当前最推荐的下一步是：

1. 以 `standard-list-page-template-design.md` 作为平台设计基线
2. 重写实施计划，使其先建设模板能力，再迁移人员中心列表页
3. 对人员中心原试点设计做最小回填，明确列表页应优先接入平台模板

## 8. 结论

本次一致性 review 的最终结论是：

1. 标准列表页模板能力设计与当前平台主线一致
2. 该设计没有破坏 metadata 边界、模块边界或 Shell 边界
3. 该设计可以作为新的实施计划输入
4. 人员中心应继续保留“首个真实试点”定位，但试点路径应升级为“模板能力优先”

## 9. AI-First 最小检查清单

### 入口在哪里

- 设计入口：`docs/designs/platform/standard-list-page-template-design.md`
- 试点入口：`docs/designs/modules/organization-person-center-pilot-design.md`

### 边界在哪里

- 只做列表页模板
- 不做详情页模板扩展
- 不改 Shell 内部结构

### 如何验证

- 检查设计是否仍遵守三层元数据边界
- 检查模板是否放在共享层
- 检查试点是否仍保持在组织模块内

### 失败信号是什么

- 模板设计变成页面解释器设计
- 实施前提变成必须改 Shell
- 首轮目标被扩成列表页加详情页整套模板化

### 如何回滚

- 删除本设计与对应计划
- 保留原人员中心试点设计路径
- 不影响既有主线设计文档
