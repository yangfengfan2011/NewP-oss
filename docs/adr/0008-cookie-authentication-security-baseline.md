# Cookie 认证写请求采用统一安全基线

所有浏览器可访问且依赖认证 Cookie 的 `POST`、`PUT`、`PATCH` 和 `DELETE` 请求都必须经过 Host 统一的防伪令牌验证，登录和退出也不例外；前端通过统一请求封装取得并发送令牌，不允许各模块自行选择是否保护。登录入口同时使用配置化的远端 IP 固定窗口限流和全局并发上限：默认每个 IP 每分钟最多十次登录请求且不排队，全局最多并发执行二十次密码验证；超限返回 `429 Too Many Requests` 和 `Retry-After`。本阶段不引入账号锁定，也不按任意 ECODE 创建无限限流分区。Host 只接受显式配置的可信代理或网络提供的转发头，其他请求一律使用直接连接 IP，限流不得信任任意客户端提交的 `X-Forwarded-For`。

登录失败对 ECODE 不存在、密码错误、账号停用或账号删除统一返回相同的 `401` 响应，不泄露账号真实状态；只有凭据已经验证成功时，客户端才能获知当前会话因临时凭据而受限。失败尝试只进入不暴露账号存在性的结构化安全日志和限流指标，不写入 Identity 安全事件或其他永久领域记录。相比只依赖 `SameSite` Cookie，这一基线覆盖跨站写入、暴力尝试和账号枚举，同时不进入本轮明确暂缓的权限设计。
