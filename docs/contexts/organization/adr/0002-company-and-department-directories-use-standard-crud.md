# 公司和部门作为独立 Standard CRUD 目录

本文的独立菜单与“不建设组织树”呈现决定由已确认的 [ADR-0046](../../../adr/0046-view-composition-uses-tree-and-tab-hosts.md) 目标设计替代，首个组合切片已提供组织树与节点基本信息、直属部门标签；统一入口与完整结构操作仍在后续切片范围。本文的独立资源、组织领域规则、业务查询与存储归属继续有效；以下保留原决定的适用背景，不应再据其呈现非目标拒绝已确认的树与标签页设计。

Organization 将公司与部门分别作为独立的 Standard CRUD 资源管理，而不恢复自定义组织树页面。公司是顶层组织主体；部门不可跨公司移动，只能在所属公司内形成可调整上级的无环层级。两个资源使用各自的列表、创建和编辑 Drawer 以及条件删除动作，不建设完整详情页、导出或独立启停命令。

公司编码全局唯一且不可修改，公司名称全局唯一；部门编码在公司内唯一且不可修改，部门名称在同一上级下唯一。公司和部门使用保留前导零的字符串排序码，按完整字符串字典序排序。新建资源默认启用；公司仍有启用部门时不得停用，部门仍有启用子部门时不得停用。停用不级联且保留既有人员归属，但停用资源不得用于新增或改变组织归属。公司只有在没有部门和人员引用时才能删除，部门只有在没有子部门和人员引用时才能删除；数据库使用 Restrict 关系保护可表达的引用不变量，应用层负责启用状态与无环校验。

Organization 拥有公司、部门的业务校验、生命周期、依赖 Lookup 与目录读取契约；Standard CRUD 只拥有共享列表、表单、动作执行和反馈。旧数组型管理 API 一次性切换为规范分页 CRUD 接口，不保留双读、双写或响应 fallback，也不为部门依赖 Lookup 扩大 Standard CRUD 公共协议。公司与部门使用 View、Create、Update、Delete 权限，启停归入普通 Update；不增加 Revision、版本字段或自动重放。

## 非目标

- 不建设组织树、拖拽排序、跨公司子树迁移或组织历史。
- 不把公司解释为租户、客户或法人实体，也不把部门解释为用户组或授权组。
- 不提供详情路由、导出、批量操作、独立启停命令或旧 API 兼容期。
- 当前没有旧数据，不提供数据清洗、回填或兼容迁移，也不自动删除任何 catalog。

## 回退

在尚无业务数据时，回退必须把公司和部门的 Model/List View、导航与词典、前后端 binding、CRUD 与 Lookup 接口、权限、持久化约束和测试作为同一边界恢复，并在经过 ownership 校验的空 catalog 上重新执行完整 migration stream。产生业务数据后不得通过删除表、放宽引用或恢复旧数组 API 回退；届时必须使用新的前向迁移和显式产品决策。
