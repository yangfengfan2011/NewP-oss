# Organization

Organization 上下文管理组织主数据与人员档案。它描述人员属于哪个组织，不拥有登录账号、凭据或授权分配。

Organization 是平台组合的必需基础成员，必须存在并有效启用；必需性由发布角色及唯一组合声明派生，不能缺失、停用、卸载或因祖先停用而被屏蔽。组合归属不改变其独立组件身份、模型 owner、数据及迁移流，也不改变 Identity／Authentication 的可信来源约束。当前唯一契约见 [Module Contract](../../architecture/module-contract.md#平台必需基础集合) 与 [ADR-0021](../../adr/0021-identity-and-authentication-are-required-builtins.md)。

组织结构页面现由 `platform.relations` 消费 Organization 的公司、部门关系配置，读取走 `/api/trees/organization.structure/*`；页面输入和业务写入仍由 Organization 解释。原有组织专用树 API（`/api/organization/tree/*`）已退役，结构页面不再注册专用前端 Provider；部门父级候选与防环校验仍由 Organization 独立查询提供。

组织树读取由本模块提供根、直属子节点、分页搜索和当前路径；节点上下文由模块解析为标准页面输入。树 SQL 按各节点显式资源键消费最终读取裁决，并只返回从真实根经过全部可读祖先抵达的节点；直接指定子节点、搜索和路径定位也受同一可达性约束。内部完整组织视图及平面列表、详情不继承树可达性。公司直属部门范围显式使用空上级，查询范围与用户筛选相交并在总数、分页前执行。组织管理统一入口组合组织结构与公司、部门、岗位、人员四个全局目录；全局部门通过显式解析器移除节点上下文与固定创建值，以 `queryScope: { kind: "global" }` 向本模块声明全局资源语义。空范围和不完整直属范围仍拒绝，全局范围不得混入直属字段。旧目录地址跳转到对应标签，人员完整详情由导航 metadata 独立声明。完整结构操作及搜索呈现见 [交付地图 #179](https://github.com/yangfengfan2011/NewP/issues/179)。

组织业务查询通过 `Organization.Contracts` 的 `IOrganizationQuery.ReadAsync` 取得同一份不可变当前视图，提供完整档案、当前账号的人员与组织链及批量名称解析。人员的当前公司、部门与上级链由 Organization 内部统一解析；正式查询读取已发布快照，提交资格比较在同一原快照上叠加本事务实际变更，不向外暴露缓存候选。缓存包含四类完整档案及停用记录；标准 CRUD 管理列表、详情和通用组织树保留固定数据库查询及分页。公司、部门、岗位和人员普通 CRUD 复用默认对象行为；人员启用、停用和永久账号绑定由 Organization 业务服务直接组合各自核心与平台事务，不声明对象动作或横切开放点。专用服务入口唯一拥有事务协调，在取得 Person 协调权后读取和校验事实；内部核心只登记变化并返回用例 DTO，不保留独立开事务路径。生命周期的执行失败由服务入口统一翻译，绑定核心保留 Identity 依赖专属错误翻译，取消与提交后缓存失败沿既有契约传播。两类入口都通过统一事务参与机制局部维护缓存，故障期间依赖请求暂不可用，恢复与维护边界见 [ADR-0050](../../adr/0050-organization-cache-holds-full-records-and-fails-closed.md)。公司、部门、岗位和人员的条件删除 adapter 各自保留业务谓词与失败解释，Organization 内部共享执行模块统一负责事务协调、实际持久化主键解析、原子物理删除和成功变更登记。

对象规则与公司业务目录中需要选择读取来源的事实由模块内部 `OrganizationEffectiveFacts` 集中处理：事务内使用当前 DbContext 的 SQL 事实，事务外使用已发布组织视图，缓存失败不回源。公司按标识、批量及编码读取与目标完整启用链共用该入口；部门存在性、同公司校验、防环、目录 Lookup 及管理分页继续固定 SQL，业务错误与校验顺序仍由人员、部门规则拥有。公共 `IOrganizationQuery` 始终表示已发布视图，不承载事务内候选。

人员和部门表单的公司、部门候选沿 Organization 自有 SQL 目录消费规范资源读取计划；部门上级候选先保留同公司、防环和后代排除，再在数据库分页前组合读取谓词。当前值由 Organization 内部共享解析模块独立分批读取，结果显式区分可读真实档案与只含 ID 的遮蔽关联，缺失项省略；不再以停用档案占位或维护并行遮蔽 ID 集合。部门当前值仅受同公司约束，不继承候选关键词、启用或层级排除条件。不可读项只经 Lookup 响应保留 ID 与 `***`，可读名称恰好为 `***` 时仍按真实启用状态选择。业务校验、完整组织视图及授权管理最小主体目录不消费该业务候选过滤。

人员和部门的既有列表/详情 Display 仍从完整组织视图批量取当前名称，外部输出另按公司、部门、岗位各自规范资源的最终可读 ID 集合裁决；部门的所属公司与父部门遵守同一规则。不可读目标只把显示值变为字面 `***`，原关系 ID 保留；目标缺失仍沿原空显示契约。人员既有账号绑定摘要保留人员自己的绑定事实及账号 ID，不可读账号不返回其代码、名称、状态或版本，页面以独立可读状态显示 `***`，不按名称字面量判断权限。授权执行故障向普通 GET 传播，内部组织事实和绑定命令不受显示投影裁剪。

公司目录的“初始化默认组织”动作通过正式初始化命令建立 No Infighting Company 及其系统管理组部门。初始化只在显式调用时执行，与默认部门的业务记录在同一平台事务中提交；安全重试无变化不追加成功事件，不清除、覆盖或重命名既有组织。默认编码、名称或保留部门身份冲突时明确拒绝，交由管理员检查已有档案。内置管理员通过保留的实际部门身份获得当前直接部门，不创建或绑定 Person；普通账号仍沿既有完整启用组织链准入。对象创建和存量补齐通过平台持久化归属目录读取可信账号及当前直接部门，未知或删除账号省略，缺失部门保持空值；部门名称对外显示继续交集部门读取裁决，目录故障传播。此观察是当前归属，不声称重建创建时历史，也不自动授予业务权限。

转交提交通过独立的 ITransactionalAccountOwnershipDirectory 在已有平台事务内读取当前账号及 Organization 自有 SQL 事实，不读取已发布组织缓存或向公共内核暴露私表。未知或已删除账号不返回，停用账号仍可解析，普通账号使用当前 Person 的直接部门，部门缺失保持空值；内置管理员仍核验正式默认部门的实际存在性，不创建 Person。该接口只保证本次事务内实际读取时的事实，不承诺组织变更在读取后至提交间全局串行，也不新增完整启用链、非空部门或接收者业务读取资格。

## Language

**人员档案（Person）**：
组织中的业务人员记录，拥有独立人员标识，并可在组织结构能力可用后建立组织归属；它不等于可登录的用户账号。
_Avoid_: 用户、账号、员工账号

**出生日期（Date of Birth）**：
人员档案记录的完整日历日期，年份是该事实的一部分；它不表示时间点，不按查看者时区转换，也不承担每年重复的生日提醒语义。
_Avoid_: 生日、出生时间、年龄

**入职时间（Employment Start Time）**：
人员档案当前或最近一次任职区间预定或实际开始的时间点；它使用 UTC 原始值，并按查看者的有效时区展示，但不自动改变任职状态或人员启用状态，也不构成任职历史。
_Avoid_: 创建时间、启用时间、任职状态

**离职时间（Employment End Time）**：
人员档案当前或最近一次任职区间预定或实际结束的时间点；它使用 UTC 原始值，并按查看者的有效时区展示，但不自动改变任职状态或人员启用状态，也不构成任职历史。
_Avoid_: 删除时间、停用时间、任职状态

**系统管理组（System Administration Department）**：
位于初始化公司下、名称为“系统管理组”的默认部门，内置管理员归属其中；“组”是部门的叫法，不表示独立用户组类型。

**公司（Company）**：
人员和部门所属的顶层组织主体；公司名称在 Organization 范围内唯一。
_Avoid_: 租户、客户、法人账号

**公司编码（Company Code）**：
在 Organization 范围内唯一标识公司的稳定业务编码，创建后不可修改。
_Avoid_: 公司名称、租户编号、公司 EID

**公司启用状态（Company Enablement Status）**：
公司自身是否启用的独立状态；按 [ADR-0049](../../adr/0049-ordinary-account-admission-requires-active-organization.md)，公司可直接停用并阻断其下普通账号准入，保留既有引用及下级对象自身状态。原“仍有启用部门时不得停用”的限制已取消。
_Avoid_: 删除状态、人员启用状态、账号状态

**部门（Department）**：
隶属于一个公司的组织单元，可具有同公司内的上级部门；部门名称在同一上级下唯一。产品讨论中的“组”指同一概念，统一使用“部门”作为术语。
_Avoid_: 独立用户组、权限角色、组角色

**部门编码（Department Code）**：
在所属公司内唯一标识部门的稳定业务编码，创建后不可修改。
_Avoid_: 部门名称、部门 EID、全局部门编号

**部门层级（Department Hierarchy）**：
部门通过可选的同公司上级形成无环层级；部门创建后不能迁移到另一公司，但可以在原公司内调整上级；按 [ADR-0049](../../adr/0049-ordinary-account-admission-requires-active-organization.md)，调整时目标公司、目标部门及全部上级部门必须启用，允许从停用范围移出。
_Avoid_: 组织树页面、授权层级、跨公司部门移动

**部门启用状态（Department Enablement Status）**：
部门自身是否启用的独立状态；按 [ADR-0049](../../adr/0049-ordinary-account-admission-requires-active-organization.md)，部门可直接停用并阻断本部门及全部下级部门的普通账号准入，保留既有引用及下级对象自身状态。原“仍有启用子部门时不得停用”的限制已取消。
_Avoid_: 删除状态、人员启用状态、账号状态

**排序码（Sort Order Code）**：
公司和部门用于形成稳定展示顺序的字符串编码。它由 1–32 个 ASCII 数字组成，保留前导零并按完整字符串字典序升序比较；重复排序码以公司或部门编码稳定排序，不能按整数解析、补齐或规范化。
_Avoid_: 排序数字、数值权重、自然数序号

**组织归属（Organization Affiliation）**：
人员档案可选的公司与部门组合。公司和部门可以同时为空；新增或改变归属时，两者必须成对出现，部门必须属于该公司，且二者都处于启用状态；[ADR-0049](../../adr/0049-ordinary-account-admission-requires-active-organization.md) 进一步要求目标部门的全部上级部门启用，并允许移出停用范围。公司或部门后来停用时保留既有归属，并允许人员维护与归属无关的信息；岗位不属于组织归属，人员可以独立选择岗位。
_Avoid_: 用户组成员关系、授权归属、原始组织 ID

**普通账号组织准入（Ordinary Account Organization Admission，见 [ADR-0049](../../adr/0049-ordinary-account-admission-requires-active-organization.md)）**：
普通账号进入系统所需的业务身份与组织条件：账号永久绑定人员，人员具有相互匹配的公司与部门归属，且账号、人员、所属部门、全部上级部门及公司均启用；任一对象停用均阻止进入系统。LocalAdmin 保留独立维护身份例外。
_Avoid_: 功能授权、数据隔离、账号启用状态

**岗位（Position）**：
Organization 范围内共享的全局人员分类，可供任意人员独立选择；它不隶属于公司或部门，也不等于授权角色。
_Avoid_: 部门岗位、角色、权限角色

**岗位启用状态（Position Enablement Status）**：
表示岗位当前是否允许分配给人员；停用岗位不会清除既有人员引用，既有引用仍可显示。
_Avoid_: 人员启用状态、账号状态、删除状态

**任职状态（Employment Status）**：
人员的任职类型，例如全职、兼职、合同工或实习；它不表达记录是否可用，也不等同于离职流程。
_Avoid_: 在职状态、启用状态、账号状态、离职状态

**人员启用状态（Person Enablement Status）**：
人员档案当前是否启用的独立状态；停用不改变任职状态，但必须同时停用通过人员账号绑定指向的用户账号，恢复人员则不会自动恢复账号。
_Avoid_: 任职状态、账号状态、删除状态

**用户账号（User）**：
由 Identity 拥有、可被认证机制识别的账号；Organization 最多通过显式关联引用其标识。
_Avoid_: 人员档案、员工

**人员账号绑定（Person-User Binding）**：
启用人员与用户账号之间由 Organization 拥有的永久一对一关系；账号可以在启用或停用状态下完成绑定，停用账号绑定后仍保持停用。绑定后双方都不能删除、解绑或改绑，人员停用会强制停用账号，但人员恢复不会自动恢复账号；Person.Name 与 User.ENAME 始终分别维护，不因绑定自动同步。
_Avoid_: 可解除关联、用户角色、组织成员关系、账号归属

**人员中心（Personnel Center）**：
围绕人员档案查询、查看和维护提供的管理入口，不代表完整组织树或身份管理系统。
_Avoid_: 账号中心、人力资源系统

**组织管理（Organization Management）**：
组合组织结构、公司、部门、岗位和人员管理内容的统一入口；入口组合不改变各资源的领域含义，也不表示岗位或人员属于组织树节点。
_Avoid_: 身份管理、组织模型、组织归属
