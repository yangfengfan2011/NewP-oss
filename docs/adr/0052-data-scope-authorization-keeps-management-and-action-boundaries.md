# 数据范围授权分别约束管理资格、当前动作与读取

状态：已接受的设计边界；#228–#231 已落地读取规则、主体、条件与规则树；#232 实现对象例外、可委派管理和正式动作定义；#233–#234 已接入人员及公司、部门、岗位的基础写入与对象管理。Lookup、树、Display 与导出消费按 #227 后续 child 交付。[正式规格 #227](https://github.com/yangfengfan2011/NewP/issues/227) 承接已关闭的[讨论 #226](https://github.com/yangfengfan2011/NewP/issues/226)及后续动作启停决议；规格发布不构成实施授权。数据范围授权决定动作可以作用于哪些对象；认证、功能授权、系统强制隔离和业务必需约束继续由各自边界承担。

## 动作启停

- 独立动作定义具有启用开关，默认启用，作用于引用该动作的全部资源与入口；所有内建及扩展动作均支持。开关与动作定义按既有 authoring 和正式装配生命周期生效，不另建运行时开关真源。
- 停用只跳过该动作自身的数据范围裁决及条件执行，已有规则、对象授权和动作三态配置保留，动作定义仍可引用；不禁用业务动作或功能入口，也不豁免配置保存校验。
- 读取依赖独立组合：编辑、删除或授权停用时，读取若仍启用且拒绝，依赖读取的操作仍不允许；读取停用时，该层读取结果不受限，读取依赖视为满足，但其他启用动作继续判定。
- 读取停用后，不再因该层读取拒绝过滤列表、候选或导出、遮蔽关联名称或截断业务树；认证、功能权限、业务查询条件、系统强制隔离及业务必需约束继续执行。
- 重新启用后按保留配置及当前主体关系、对象事实裁决，不重建授权项，也不恢复过去的权限结果快照。

## 管理与豁免

- 对象授权管理是一项独立资格。具备相应功能资格、对象最终读取权限和授权动作权限的主体，可以授予自己没有的业务动作；可授予范围不以操作者自身权限为上限。
- 该资格包含整份对象授权配置的管理权，可以修改自身授权、修改或撤销其他人配置的授权项，并在统一字段范围内调整任意主体授权项的优先级；不按配置创建者或是否涉及本人另设限制。
- 对象授权保存依据保存前的有效资格判定，允许保存后操作者失去读取或授权资格；后续请求使用新授权，误配置可由 LocalAdmin 恢复。
- “授权”动作本身可以转授。被授予者仍须具备相应功能资格及对象最终读取权限，不因对象授权而自动获得这些资格。
- 规则管理按独立功能资格判定，LocalAdmin 具备该资格，其他用户可通过功能授权获得；对象上的授权管理资格不自动产生规则管理资格。
- LocalAdmin 不受数据范围限制，包括规则授权和对象授权的拒绝；它无需执行该层条件，因此不受该层条件执行异常影响。授权配置保存时仍须校验，不能通过该豁免保存无效配置。
- 数据范围豁免不授予普通授权管理员，也不绕过认证、功能权限、系统强制隔离或业务必需约束及其故障处理。ADR-0048 中 LocalAdmin 通过显式功能授权正常判权的边界保持不变。
- 规则管理与对象授权管理使用配置所需的最小主体目录，可选择操作者在业务页面不可读的用户、角色、公司或部门，并显示身份、名称及必要层级；该范围也适用于已有授权项的主体名称。访问须具备对应授权管理资格并遵守系统强制隔离，不因此获得主体业务记录的读取权。

## 当前动作与后续访问

- 新建依据准备写入的完整对象判断新建权限，允许创建者随后无权读取该对象。成功后若不可读，只反馈创建结果，不返回对象详情，也不自动增加创建者授权。
- 普通编辑依据动作执行前的对象事实判断读取与编辑权限。授权通过后，不因本次编辑使对象移出操作者后续可读取或可编辑范围而否决该编辑，也不要求额外增加移交动作。后续读取或动作仍按届时事实独立判权。
- 编辑、删除和授权依赖对象最终读取允许；业务扩展动作显式声明是否依赖读取，由平台统一执行。该决定不引入任意动作依赖图。
- 具体业务动作的内部联动暂不纳入本次决定，不推导联动对象必须逐个判权或自动豁免的通用规则。

## 读取条件与主体

- 祖先规则没有读取部分时，在读取裁决中不贡献条件或意见，其后代仍按剩余读取条件参与裁决；其他动作继续使用完整条件及祖先路径。
- 例如“全部订单拒绝读取 → 正在流程中（无读取条件、读取不选）→ 本人负责（同意读取）”，本人负责但不在流程中的订单仍可由后代规则获得读取。无读取部分不会变成恒真条件再触发该节点的读取拒绝；混合 AND／OR 的精确化简仍需以可复跑案例固定。
- 公司主体匹配该公司全部人员，不展示没有实际差异的“包含下级”选项；部门主体支持仅本部门或包含下级部门，默认仅本部门。
- 空值只由“为空／不为空”条件显式匹配；其他比较（包括不等于、不属于）遇到空值均不命中，需要包含空值时显式使用 OR 组合。
- 文本比较沿用该字段既有数据库查询的比较规则，单对象判权与平面列表过滤必须保持一致；不新增授权专用的大小写规则。

## 首期接入与读取呈现

- 通用 Standard CRUD 的读取及基础写入统一接入；公司、部门、岗位、人员作为首批完整验证范围，并覆盖组织关系树、人员自定义候选查询、引用显示和既有导出。导出沿用最终读取范围与已有功能权限，不新增数据范围导出动作；专用业务动作及联动、附件和新增批量能力暂不纳入。
- 关联对象不可读时，保留原关联和已允许返回的关联 ID，名称统一显示为字面值 `***`，不返回关联对象详情；业务候选列表仅返回可读对象。不自动清空已有关系，也不因此增加编辑后的权限门槛。
- 业务关系树遇到不可读父节点即停止向下查找，不展示该分支的后代，也不将后代提升为根节点。树加载、展开、搜索及路径定位采用相同边界；该展示约束不扩展为平面列表或单对象读取的祖先权限依赖，也不同于授权规则树的读取条件投影。
- 单对象不存在或最终读取拒绝时，统一返回找不到；对象可读但编辑、删除或授权动作拒绝时，返回无权限。授权条件执行异常仍明确报告，不伪装成对象不存在或空结果，LocalAdmin 豁免保持。

## 配置保存与审计

- 规则管理界面支持新增、修改、删除、启停、父子层级、AND／OR 条件、主体、优先级和动作三态；对象授权界面支持当前对象授权项的增删改。首期不增加模板复制或批量导入。
- 一次保存以一棵根规则及其子树，或一个对象的整份授权配置为单位；整体成功生效，失败保留原有效配置。
- 规则及对象授权的新增、修改、撤销、启停进入事务性审计，记录操作者、目标及前后变化。首期不建立逐次判权或逐条查询结果的审计记录，执行故障沿用错误日志。

## 非目标与回退

本决策固定上述职责、首期接入和可观察行为；配置文件、接口、表结构、索引、缓存机制、具体交互布局和审计字段契约在正式规格与技术设计约束内确定。讨论已关闭并由规格承接，不表示功能已实施，也未拆分 child。

首个读取规则闭环的当前实现与回退边界记录在 Authorization Context。撤销通用读取接入会扩大到仅功能授权的范围；保留授权配置、审计及 migration 历史，不通过删库或改写已发布 migration 回退。
