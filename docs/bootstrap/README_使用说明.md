# Codex 平台重写启动包 v2 使用说明

这套材料用于帮助团队以更稳定的方式启动“旧平台重写为新平台”的工作，不是直接交给 Codex 的单条提示词，而是一套协作启动包。

## 适用场景

适用于以下前提：

- 旧平台不仅有 Web 代码，还有 API、服务、定时器、文件服务、Studio、WinApp 等宿主形态。
- 旧平台包含大量运行时元数据、配置资产和页面资产，不只是 C# 或前端代码。
- 团队准备重建新平台主干，但希望 Codex 能稳定参与盘点、契约、脚手架、模块实现和验证。

## 这套材料解决什么问题

相对“直接让 Codex 重写平台”，这套包强调：

- 先盘点旧平台资产，再形成处置矩阵，而不是直接冲进“重写代码”。
- 明确迁移对象不止代码，还包括元数据、数据、宿主、工具链和发布资产。
- 第一阶段聚焦主干、契约、Demo 与首批公共模块，不追求一次性做完全部旧功能。
- 提示词要求 Codex 输出可执行产物，而不是泛泛建议。

## 目录说明

- `prompts/`
  用于按顺序驱动 Codex 执行各阶段任务的提示词。
- `bootstrap/`
  用于解释启动包定位、使用方式和补充说明的文档。
- `templates/`
  如果后续补齐，可作为新仓库初始化时直接落地的模板来源。

## 推荐启动顺序

1. 先阅读本目录下的说明与提纲文档。
2. 执行 `prompts/01_旧平台全量资产盘点.md`。
3. 执行 `prompts/02_旧平台资产处置矩阵.md`。
4. 在新仓库先落地 `docs/architecture/scope-v1.md`，冻结第一阶段范围。
5. 执行 `prompts/03_新仓库骨架与基础规则.md`。
6. 执行 `prompts/04_后端模块契约与Host骨架.md`。
7. 执行 `prompts/05_前端Shell与前端SDK.md`。
8. 执行 `prompts/07_DemoModule端到端贯通.md`。
9. 再逐步推进公共模块和验证任务。

## 第一轮不要做什么

- 不要要求 Codex 一轮内“把整个平台重写完”。
- 不要在同一轮里混合改架构、改命名、加功能。
- 不要跳过盘点和处置矩阵，直接开始迁移。
- 不要让多个活跃线程同时修改同一批核心文件。

## 第一轮完成标准

- 新仓库已有主干骨架。
- 后端和前端都可以构建。
- 已定义模块契约。
- 已有一个 Demo Module 从注册到展示跑通。
- 已冻结 `scope-v1`。
- 已形成旧资产处置矩阵。
- 已选定首批进入重写范围的模块和资产类别。

## 当前建议的第一阶段范围

建议纳入：

- Host / Kernel / Contracts / SDK
- 前端 Shell
- Demo Module
- Authorization
- ConfigCenter
- Audit
- 一个轻量旧资产迁移 POC

建议默认暂缓：

- WinApp
- Studio
- 文件服务重写
- Files 深度迁移
- 工作流
- 报表与设计器
