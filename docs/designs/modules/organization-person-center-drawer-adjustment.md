# 组织模块人员中心抽屉交互调整说明

## 1. 背景

人员中心试点首轮在实现过程中暴露出两个偏差：

- 列表页把高级筛选做成了常驻右侧区，持续挤压表格主区域宽度。
- 列表主流程仍以详情页跳转为中心，不符合当前“列表停留、就地维护”的使用预期。

这两个点都与平台列表页 demo 的实际意图不一致。demo 中的高级筛选是按需打开的抽屉入口，而不是长期固定右栏；对象维护也允许使用 `drawer` 承载轻量查看与编辑。

## 2. 本次调整结论

本轮把人员中心列表页的主交互调整为：

1. 列表页继续保留“页面头部 + 轻筛选条 + 表格区”的主体结构。
2. 高级筛选默认隐藏，仅在 `advancedFilter.enabled = true` 时显示入口，并以抽屉方式按需展开。
3. 人员 `新建 / 查看 / 编辑` 改为抽屉承载，不再把详情页作为列表主流程。
4. 详情页路由暂时保留，仅作为兼容入口，不再代表当前推荐交互。

## 3. 元数据约束

为避免页面代码与 authoring 真源再次分叉，列表 view metadata 需满足：

- `editorMode = drawer`
- `advancedFilter.enabled = true` 只表示“显示入口并允许打开抽屉”，不表示“默认常显”
- `advancedFilter.sections` 只声明抽屉中的复杂条件，不回退成列表主区域的固定侧栏

## 4. 验证关注点

后续继续迭代时，默认先检查以下信号：

- 列表主区域是否仍保持为单主列，不被高级筛选长期挤压
- 未点击“高级筛选”前，右侧不应常显复杂条件
- 点击 `新建 / 查看 / 编辑` 后，是否打开抽屉而不是路由跳转
- 保存后是否返回列表上下文，而不是强制进入详情页
