# 认证会话使用服务端注册表

NewP 现在建设独立的 Authentication 上下文，以带 EID 的服务端认证会话作为 Cookie 身份的权威状态；同一账号可以拥有多个会话，Host 在每个受保护请求中验证会话及账号有效性，普通退出只撤销当前会话，账号停用或删除、管理员重置凭据则撤销全部会话，账号恢复不会让旧会话复活。登录验证成功后，Host 继续通过现有 Authorization 读取角色并写入认证主体，使 `AdminOnly` 维持现有 `LocalAdmin` 角色语义；本地管理员标记只用于保护 Identity 不变量和改善前端可见性，不能替代服务端角色判定。首阶段只提供建立、验证、撤销当前会话和撤销账号全部会话的深模块接口；会话持久化并跨 Host 重启保留，有效期配置化且默认固定八小时，不使用滑动续期或“记住我”，已撤销和过期记录保留三十天后清理。生产 Cookie 使用 `__Host-` 前缀、`HttpOnly`、`Secure`、`SameSite=Lax` 和根路径且不设置 Domain，本地 HTTP 开发才允许显式降级。“在线用户”只是活动会话查询投影，设备信息、心跳、手工踢出和管理页面延后建设。

认证 Cookie 只携带由密码学安全随机源生成的 256-bit 会话令牌，并继续由 ASP.NET Core Data Protection 保护；Authentication 注册表只持久化令牌哈希，Session EID 仅用于内部管理和事件关联，不得充当持有即认证的秘密。受保护请求必须解析 Cookie、计算令牌哈希并命中活动会话，再实时校验账号状态；Cookie 中的 User EID、账号状态或其他声明都不是有效性事实源。

首阶段会话只持久化 Session EID、User EID、令牌哈希、会话类型、创建时间、固定到期时间、撤销时间与撤销原因，不保存 IP、User-Agent、心跳或逐请求更新的最后活动时间。Authentication 提供内部批量清理能力，Host 后台服务在启动后及每天调用，分批删除已到期或已撤销超过三十天的记录；清理失败只记录告警并留待下次重试，不阻断登录或正常会话验证。

成功登录由认证会话的创建事实表达，普通退出由当前会话的撤销时间和固定撤销原因表达，不再把这两类事实复制为 Identity 安全事件。登录失败不创建领域记录，只产生不泄露账号存在性的结构化安全日志与限流指标；这些运行记录不改变 Identity 或 Authentication 的持久状态。

登录请求遇到网络中断或响应丢失时，前端不得自动重试，只能提示结果未知并允许用户手工再次登录；首个请求若已经提交会话但 Cookie 未到达客户端，该会话按固定八小时有效期自然到期，随后进入既定的三十天历史保留期。本阶段接受这种不可使用的孤立会话，不为登录增加专用幂等存储或隐式撤销其他有效会话。

用户自行修改密码时，即使已有正常或受限会话也必须再次验证当前凭据；验证成功后，凭据更新、全部旧会话撤销和当前客户端新会话建立必须原子提交，临时凭据会话由此转换为正常会话。管理员重置凭据不验证旧凭据，并撤销全部会话但不为用户建立新会话。相比只依赖长期 Cookie，这能落实下一次请求强制下线；相比立即建设完整在线管理功能，它保留最小且可扩展的会话 seam。

使用临时凭据成功登录后，Host 返回受限会话，`frontend/packages/core` 的认证级路由守卫强制进入 `/account/change-password`，且在凭据轮换成功前不加载菜单、活动业务模块或普通受保护路由；同属 core 认证层的最小页面只提供当前临时密码、新密码、确认密码和退出操作，并通过前端 SDK 调用 Identity。Identity 管理列表与详情仍由 `frontend/modules/platform/identity` 注册。浏览器后退、直接输入 URL 或隐藏前端控件都不能绕过服务端对受限会话允许端点的白名单。
