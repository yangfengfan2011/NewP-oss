# 角色按导航、Tab 和动作的声明位置授予功能权限

功能授权采用角色直接绑定现有功能点身份的模型，取消单独维护的业务 Permission 代码及功能到权限的映射。相同业务实现可能出现在不同入口，管理员需要分别控制这些位置，因此授权身份属于入口及声明位置，而不属于共享页面或动作实现。这是已确认的目标边界，尚未实施；完整目标与验收条件以 [Spec #200](https://github.com/yangfengfan2011/NewP/issues/200) 为准。

## 授权边界

- 功能目录按导航、Tab、动作组成授权树。页面仅承载内容，不作为独立勾选节点；页面访问和读取随所属入口授权。
- 标准页面由元数据提供功能声明，自定义页面同样提供可供服务端启动校验的轻量声明，并通过 SDK 绑定实现。自定义页面不要求标准 View 或布局；功能目录不能依赖浏览器访问页面后才出现，也不维护第二份权限清单。
- 不同声明位置的动作分别授权，即使名称或业务实现相同。树节点类型可以作为不单独授权的展示分组，例如公司节点操作、部门节点操作；运行时业务记录不进入功能目录。
- 服务端按可信主体与请求的已登记动作位置判权，只执行该位置绑定的业务操作。动作内部调用由实现负责，不另向管理员提供接口授权清单；保留的对外入口不能绕过动作判权。
- 已获得某位置授权的用户可以直接请求执行该位置的动作，不要求证明浏览器点击路径。动作仍受其业务参数和规则约束；位置授权不建立通用记录范围或字段授权。
- 角色保存的授权集合必须满足本分支入口依赖，缺失时提示补选并拒绝保存；其他分支入口不能替代。用户有效权限为其启用角色的授权并集。
- 纯容器只提供进入资格，不授予后代内容读取。没有获授权子项的容器不显示；默认 Tab 无权限时选择首个有权限的 Tab。内容读取由实际承载内容的导航或 Tab 授权。
- 重定向别名采用目标入口授权，不生成重复授权点。弹窗采用发起位置；独立详情直链显式声明所属入口，直接请求同样判权，不依赖来源页或访问历史。
- 修改显示名称、调整顺序保留身份和授权；跨分支移动或复制形成新授权点，旧位置授权不再生效，普通角色重新授予。新增功能默认不授予普通角色；全选只选择当时已有节点。

## 存储与查询

保留一份精简的功能点索引，将目录差异识别与可能更大的角色授权关系处理分开。这里的索引是声明目录的数据库投影，不是另一套业务权限；EID 仅是数据库关联键，授权语义仍由现有功能点的完整位置 Key 决定。

| 逻辑模型 | 主要业务字段 | 职责 |
| --- | --- | --- |
| 功能点索引 | EID、完整位置 Key | 标识已同步的功能点，支持目录比较和授权关联 |
| 角色功能授权 | RoleId、FunctionPointId | 表达一个角色对一个功能点的授予 |

表中省略平台固定字段及既有授予审计信息。用户、角色和用户角色关系复用现有模型。父子关系、名称和展示结构由已校验的完整目录提供，不复制进功能点索引。

完整位置 Key 唯一，角色功能授权具有 `(RoleId, FunctionPointId)` 唯一索引，并增加 `(FunctionPointId, RoleId)` 反向索引。前者支持角色查询和防重复，后者支持按删除功能点定位分配。数据库 Key 比较必须与目录采用一致的身份规则。

运行时将请求的完整位置 Key 解析为活动功能点 EID，再通过当前用户、用户角色、启用角色及该功能点授权的一次数据库关联存在性查询判权。不逐角色发查询，也不为判断单个动作读取用户的全部功能权限。前端完整授权投影是独立读取需求；角色配置只读取和修改目标角色的授权集合。

## 目录同步与性能验证

目录同步流程与触发时机分开，当前由服务启动触发；未来热加载可以复用同步能力，本次不实现运行时装载或切换机制。

先生成并验证完整目标目录，完成运行时产物及执行绑定的准备与校验，再读取数据库已同步的功能点索引，按完整位置 Key 在内存中计算差异。首次为空时写入全部功能点，后续只处理差异，未变化的功能点不重复写入。

正式同步在一个数据库事务内完成：按删除点 EID 批量清除关联授权，再删除失效索引，插入新增索引，并收敛 LocalAdmin 的完整功能授权；提交后发布活动目录并开放请求。目录生成或准备失败不进入清理，同步事务失败回滚。不能直接把破坏性删除放进当前早于 runtime staging 的权限同步阶段。

没有删除功能点时，不为删除检查扫描全部角色授权；有删除点时，通过反向索引在数据库定位并批量删除对应关系，不把全部授权关系拉入应用内存逐条与目录比对。大规模删除仍需承担实际受影响行的写入、事务日志和锁成本。

使用至少一组 5,000 个功能点、50 万条角色授权的真实 SQL Server 验证样本，分别测量无变化启动、删除功能、单次判权和角色保存。报告实际耗时、数据库读取量、查询次数及受影响行数，核对执行计划和必要的锁等待。样本规模不是未经验证的性能承诺，也不预设未确认的耗时门槛。

## 授权管理资格

角色管理、角色功能配置、用户角色分配等动作可以显式授予普通角色，分别按其在功能树中的位置判权，不再额外要求 LocalAdmin 身份。拥有某个管理动作不自动获得其他管理动作；获授动作的管理范围是全局的，不限定为操作者自身已有功能的子集。

这意味着能够配置角色功能并分配用户角色的可信管理员可以为自己或其他用户配置完整功能授权。该权力来自明确的动作授予，不依赖 LocalAdmin 角色名特判。LocalAdmin 仍负责初始化并保留既有自身保护，普通管理入口不改变其受保护定义及初始化机制。

## 独立功能授权工作台

Authorization 提供独立导航下的自定义功能授权工作台：左侧选择角色，右侧查看和配置该角色在完整功能树中的授权。该页面作为自定义页面声明、SDK 绑定、目录登记与服务端动作判权的真实业务采用者；标准页面动作仍需独立贯通验证。

- 左侧支持角色名称或代码搜索及分页，显示停用状态。停用角色可以配置，但明确提示当前授权不生效；LocalAdmin 展示完整授权且只读。
- 右侧显示当前角色、完整功能树、功能搜索、仅看已授权、展开／收起，以及已授权数量和本次新增／撤销数量。完整目录加载后供角色切换复用，切换只读取目标角色授权；树使用虚拟滚动，搜索保留祖先路径，筛选不能改变隐藏节点的选择。
- 节点独立勾选，选择父节点不自动授予后代。选择当前分支全部功能是明确的批量操作，只作用于当时已有功能；缺少本分支祖先入口时提示补选，依赖不完整不能保存。
- 勾选形成当前角色的未保存草稿，提供还原和显式保存；保存一次提交完整授权集合，沿用事务性写入与实际授权差异审计，不逐次勾选写入。
- 切换角色或离开页面时，未保存修改必须提供保存、放弃、取消的处理。保存失败保留当前角色和草稿；提交中防止重复写入与切换。页内选择角色也必须参与保护，不能只依赖路由离开拦截。
- 原角色列表和完整详情中的授权入口改为跳转工作台并选中对应角色，不保留原授权弹窗或第二套编辑状态。角色基础信息维护保留在原角色管理页面；快捷跳转采用目标工作台的授权身份。
- 工作台查看由其导航授权控制，修改由工作台位置的保存授权动作控制；未获保存动作的主体只能读取。入口读取覆盖角色选择、完整功能目录及当前角色授权，不以操作者自身已有功能裁剪可配置目录；服务端仍保护 LocalAdmin。

本决定以该自定义工作台替代 Authorization 当前由 Standard CRUD 动作弹层承载权限选择输入的目标交互。页面与业务状态由 Authorization 拥有，复用 SDK 受控接入和共享 UI，不把角色或功能树专属逻辑放入 Shell。

## 授权生命周期

角色功能或用户角色关系变化后，后续请求使用新的有效授权；已通过判权的在途动作允许完成，不增加提交前复判、自动回滚或重放。已打开界面沿用导航、刷新及明确授权拒绝后的权限更新机制，本次不新增实时推送。

功能点正式从完整功能目录删除后，其授权分配永久作废并清除；以后重新引入相同位置或标识，也不恢复普通角色旧授权。临时加载失败不构成目录删除，不能据此清理分配。删除整条分支时，其已删除的后代功能点同样适用此规则；仍存在的祖先入口授权不因此自动删除。

## 切换与回退

不迁移旧授权含义。切换时清空旧权限目录及角色权限分配，保留用户、角色、用户角色关系与历史审计。沿用 LocalAdmin 初始化机制，为其配置当前完整功能目录的授权，仍执行正常判权。清理是切换步骤，不得在每次启动时清空重新配置的普通角色授权。

回退须同步恢复目录、前后端授权消费和模块接入，业务数据与审计保留。已清空的旧授权不会随代码回退恢复；旧机制恢复后需要重新配置授权，不能自动将功能位置反推为旧权限。

## 非目标与既有契约

本次不增加授权管理的可管理角色、可管理用户或可授予功能范围限制，也不新增通用数据范围、记录或字段授权，不支持插件运行时热切换。

本目标将替代 Authorization 当前以业务 Permission 和 endpoint access rule 进行功能判权的模型；落地时须同步更新其现状文档。保留 ADR-0046 的页面与 View 分工、ADR-0036/0037 的前端动作和变更生命周期归属，以及组件化护栏的声明与行为绑定分工。
