# 第二阶段提示词执行说明

本文件用于说明第二阶段“最小可运行平台”应如何按顺序使用提示词。

第二阶段目标不是继续补文档，而是打通：
- 启动
- 登录
- 主界面
- Demo Module
- 最小 smoke 验证

## 一、推荐执行顺序

请按下面顺序使用提示词，不建议跳步：

1. `03_新仓库骨架与基础规则.md`
2. `04_后端模块契约与Host骨架.md`
3. `05_前端Shell与前端SDK.md`
4. `05_1_最小登录与身份能力.md`
5. `05_2_默认管理员与种子数据.md`
6. `05_3_登录后主界面与权限守卫闭环.md`
7. `07_DemoModule端到端贯通.md`
8. `07_1_最小可运行平台验证.md`
9. `12_验证与修复.md`

## 二、每条提示词负责什么

### `03_新仓库骨架与基础规则.md`

负责：
- 目录结构
- 文档
- 脚本
- 基础规则

不负责：
- 登录能力
- 模块闭环

### `04_后端模块契约与Host骨架.md`

负责：
- Host 启动入口
- 后端契约
- 认证上下文接入点预留

不负责：
- 完整登录实现

### `05_前端Shell与前端SDK.md`

负责：
- 前端 Shell
- 登录页位置
- 路由守卫接入位
- 当前用户状态接入位

不负责：
- 完整身份逻辑

### `05_1_最小登录与身份能力.md`

负责：
- 登录 API
- 当前用户 API
- 退出登录 API
- 最小会话方案

不负责：
- 完整用户中心

### `05_2_默认管理员与种子数据.md`

负责：
- 默认管理员账号
- 本地种子逻辑
- 初始化说明

### `05_3_登录后主界面与权限守卫闭环.md`

负责：
- 登录后跳转
- 主界面访问
- 未登录拦截
- 受保护路由访问规则

### `07_DemoModule端到端贯通.md`

负责：
- Demo Module 的菜单、路由、权限点、页面

### `07_1_最小可运行平台验证.md`

负责：
- 收敛验证
- 检查闭环有没有打通

### `12_验证与修复.md`

负责：
- build/test/lint/type 的最后收口

## 三、推荐执行方式

如果一次只做一个任务，建议：
- 每次只用一条主提示词
- 大任务可配合 `13_通用subagents触发模板.md`
- 多任务并行可配合 `14_通用Worktree任务模板.md`

如果要并行，优先拆成：
- worktree A：后端 Host + Identity Lite
- worktree B：前端 Shell + 登录页 + 登录态
- worktree C：Demo Module + 验证

## 四、第二阶段完成后应看到什么

第二阶段做完后，至少应该能看到：
- 平台能启动
- 有登录页
- 能登录
- 登录后进入主界面
- 主界面有菜单
- 能进入 Demo 页面
- 退出登录后受保护页面不可直接访问

如果做不到这些，就不要进入第三阶段。
