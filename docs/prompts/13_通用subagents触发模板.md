请把当前任务按“主线程 + 少量子代理（subagents）辅助”的方式执行，但不要把它变成多人同时乱改代码的局面。

你的目标不是“多开几个线程显得很忙”，而是：
- 让主线程保留架构判断和最终决策权
- 让子代理并行补足探索、审查、文档核对、测试修复
- 在不扩大范围的前提下，提高任务推进速度

## 一、何时适合触发 subagents

只有在满足以下至少 2 条时，才建议触发：
- 当前任务已经有明确边界
- 主线程已知道自己要产出的结果是什么
- 任务中存在可并行的只读探索或审查工作
- 任务不是纯单文件小改
- 任务存在“摸底 + 审查 + 实施 + 验证”这几类天然可拆分的子工作

以下情况不建议触发：
- 任务本身非常小，只改 1 到 2 个文件
- 主线程自己都还没搞清楚问题
- 多个子代理会同时改同一批文件
- 任务本身还在大范围摇摆

## 二、主线程必须先做的事

在触发任何子代理前，主线程先完成以下动作：

1. 阅读并遵守以下文件：
- `AGENTS.md`
- `Plan.md`
- `docs/scope-v1.md`
- 与当前任务直接相关的模块边界文档

2. 用 3 到 6 句话写清当前任务：
- 任务目标是什么
- 本轮不做什么
- 预期产出是什么
- 需要哪些子视角辅助

3. 明确本轮边界：
- 是否在 V1 范围内
- 是否会涉及登录、权限、配置、审计或 Demo Module
- 是否涉及旧平台资产导入

## 三、推荐子代理分工

默认最多同时使用 2 到 3 个子代理，通常不要超过 4 个。

### 1. `platform_explorer`

适合负责：
- 只读扫描目录、项目、入口文件
- 列出影响范围
- 找关键类、关键接口、关键配置
- 对旧平台能力做定位

典型提问方式：
- 请只读扫描与当前任务相关的目录，列出入口、关键类、依赖方向和风险点。
- 请不要改代码，只输出文件路径、类名和你认为必须读的文件。

输出要求：
- 文件路径
- 关键类或接口名
- 影响范围
- 可能风险

### 2. `contract_reviewer`

适合负责：
- 审查模块边界
- 审查 Host / Kernel / Module / SDK 是否越界
- 审查兼容层是否污染主干
- 审查契约设计是否可扩展

典型提问方式：
- 请只审查当前方案的契约边界和耦合风险，不要给样式建议。
- 请指出哪些地方会让后续模块难以扩展或导致跨模块耦合。

输出要求：
- 问题点
- 风险等级
- 建议修正方向
- 哪些地方可以接受，哪些地方不应继续

### 3. `docs_researcher`

适合负责：
- 核对版本行为
- 核对框架配置
- 核对认证、授权、路由、构建等官方文档
- 确认某项实现是否符合当前技术栈

典型提问方式：
- 请核对当前技术方案对应的官方文档行为，不要改代码。
- 重点核对登录、认证中间件、路由守卫、构建行为等。

输出要求：
- 结论
- 依据
- 是否与当前方案冲突
- 建议保留或调整的点

### 4. `test_fixer`

适合负责：
- 最后阶段跑 build / test
- 修复编译、类型、lint、测试问题

典型提问方式：
- 只允许修复 build/test/lint/type 错误，不允许新增功能。
- 请输出失败原因、修复点和剩余问题。

输出要求：
- 哪个命令失败
- 失败原因
- 修复摘要
- 剩余问题

## 四、严格并行规则

必须遵守：
- 主线程负责最终方案与最终改动
- 子代理尽量只做只读探索、契约审查和文档核对
- 真正写代码的线程尽量只有一个
- 不允许两个 live thread 同时修改同一批文件
- 不允许子代理绕开 `scope-v1` 擅自扩大范围

如果发现以下情况，立即收敛：
- 子代理开始建议引入 WinApp、Studio、文件服务重写
- 子代理开始把任务扩展为完整身份平台
- 子代理开始混做架构重构、功能新增、迁移改造三件事

## 五、主线程的执行顺序

建议按这个顺序推进：

1. 主线程明确目标和边界
2. 子代理只读探索
3. 子代理契约审查
4. 主线程汇总，做最终方案
5. 主线程实施代码或文档修改
6. `test_fixer` 在最后统一验证与修复
7. 主线程输出最终摘要

## 六、输出格式要求

任务完成后，主线程必须统一输出：
- 本轮目标
- 实际改动
- 哪些子代理参与了
- 每个子代理提供了什么价值
- 验证结果
- 剩余风险
- 下一步建议

## 八、贴近本项目的示例

### 示例 1：最小登录能力

当前任务：
- 建立 `Identity Lite / LocalAuth`，实现登录页、登录接口、当前用户接口、退出登录接口、默认管理员种子账号

本轮明确不做：
- 完整用户中心
- 组织树
- 单点登录
- 外部统一认证集成

建议分工：
- `platform_explorer`：查找当前 Host、前端 Shell、路由守卫、当前用户上下文接入点
- `contract_reviewer`：审查认证与授权是否分层清晰
- `docs_researcher`：核对当前技术栈下认证中间件与前端登录态方案
- `test_fixer`：最后修复构建与验证问题

### 示例 2：ConfigCenter 导入 POC

当前任务：
- 选择 `Setting` 或 `Dictionary` 作为首个导入 POC，打通从旧资产到新配置模型的最小闭环

本轮明确不做：
- 全量元数据导入
- 所有 `.generator/.page/.view` 兼容
- 工作流和报表配置迁移

建议分工：
- `platform_explorer`：定位旧配置资产目录与格式
- `contract_reviewer`：审查导入逻辑应放在模块内还是迁移层
- `docs_researcher`：核对当前配置加载方案与格式处理库
- `test_fixer`：最后修复验证问题
