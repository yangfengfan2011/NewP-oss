# 界面文案在呈现时按当前语言解析

本决定确立当前正式功能的完整界面中英文本地化目标，覆盖登录、公共交互、模块页面及预期业务错误；它是已确认的目标边界，不表示现有实现已满足。API 提供稳定错误码、结构化参数和诊断文本，前端在呈现时解析用户提示；API 的诊断文本不承诺按请求语言翻译。这样同一错误事实可以在语言切换后重新展示，无需再次执行业务请求。

界面文案包括菜单、页面与分组标题、新建／编辑表单字段 label、列表列名、查询标签、详情标签、按钮、必填与校验说明、占位文字、帮助说明、tooltip、可访问名称和消息提示。表单和视图标签沿既有解析路径与 View 词典完整适配，缺失的词条按所属能力补齐；不把消息提示适配等同于完整界面本地化，也不自动翻译用户录入的业务名称。

平台拥有公共文案与统一解析机制；业务错误语义及词条继续归所属模块，与 [ADR-0036](0036-standard-crud-actions-use-one-shell-execution-lifecycle.md) 一致。语言切换后，已显示的字段错误、提示和打开的弹窗按新语言更新，并保留尚未提交的输入。

本决定不强制每个 Model 配套词典，不翻译用户录入的业务内容，也不替代 [ADR-0040](0040-model-fields-own-raw-and-display-projection.md) 的服务端显示投影及其语言变化后重读要求。前后端共用模块 authoring 词典作为译文真源。后端通过只读查词能力消费已激活的运行时词典，首先用于现有系统操作者显示值；后端生成的显示文本与前端交互提示遵循各自的呈现职责。API 错误诊断文本继续不承诺本地化，其他后端输出面的采用范围按真实需求明确。

语言选择保存在当前浏览器，刷新、退出及同一浏览器切换账号后沿用；无已保存选择时使用平台配置的默认语言，不自动匹配浏览器语言，也不增加账号级语言偏好。当前请求 locale 继续由受支持语言定义解析，不写入认证会话。

语言选择提供明确的用户入口，覆盖登录页、首次改密页和业务 Shell 的全局栏。各入口共用语言状态与选择行为，按受支持语言清单显示语言名称及当前选项；正常运行不另行硬编码语言集合，启动降级沿用同源生成的最小语言定义。用户选择后立即更新当前界面及后续请求的 locale，并保存浏览器偏好；切换不依赖整页刷新，不清空表单输入，也不重新提交业务操作。

无法识别的错误或缺少对应词条的错误显示当前语言的通用提示，并保留用于排查的错误码和诊断信息；后端原始诊断文本不直接作为普通用户提示。正式功能中的可预期业务错误必须提供准确译文，不能以通用提示替代完整适配。

运行时词典请求失败时，登录与故障重试使用从同一 authoring 词典生成的最小内置文案；业务页面等待词典成功加载并提供重试入口。最小内置文案是生成产物，不构成第二份手写译文真源。authoring 词条缺少平台支持语言时继续拒绝生成运行时候选；运行时网络故障的恢复规则不放宽词典完整性校验。

回退时将错误传输适配、提示解析与对应消费者作为同一变更范围恢复，保留原有错误码、参数和业务行为；不通过重放写入恢复提示。后续若要求 API 直接提供本地化文案，需要重新明确文本生成方与客户端消费契约。
