请在新平台中实现一套“最小可运行平台”所需的登录能力，不要把它扩展成完整身份平台。

## 一、开始前先阅读

请先阅读并遵守：
- `AGENTS.md`
- `docs/scope-v1.md`
- `docs/identity-lite-module-boundary-v1.md`
- `docs/module-boundaries-v1.md`

## 二、本轮目标

本轮只解决：
- 平台能登录
- 登录后前后端都能识别当前用户
- 退出登录后受保护资源不可直接访问

不要把任务扩展成完整身份平台。

## 三、本轮必须产出的能力

请实现：

### 后端
- 本地登录接口
- 当前用户接口
- 退出登录接口
- 最小会话或 token 方案
- 当前用户上下文解析

### 前端
- 登录页与登录请求接入
- 登录成功后的状态保存
- 当前用户获取
- 退出登录动作

## 四、推荐最小实现方式

如果没有现成身份基础设施，优先采用最简单、最稳定的方式：
- 本地用户名密码
- 明确的默认管理员
- 简单可验证的 token 或 cookie 方案
- 当前用户接口返回最小字段集

请避免过度设计。

## 五、本轮明确不做

这轮不要做：
- 完整用户中心
- 用户注册
- 密码找回
- 复杂密码策略
- 单点登录
- LDAP / OAuth / OpenID Connect 深度接入
- 组织树与岗位体系

## 六、与其他模块的边界

- 登录负责“当前是谁”
- Authorization 负责“当前用户能做什么”
- ConfigCenter 不负责登录
- Audit 可以记录登录相关事件，但登录模块不负责实现审计存储

## 七、建议实施顺序

建议按这个顺序推进：

1. 定义登录请求、登录结果、当前用户模型
2. 实现本地登录校验
3. 实现登录态存储方案
4. 实现当前用户接口
5. 实现退出登录
6. 让前端登录页接上接口
7. 验证登录前后受保护页面的访问差异

## 八、验证要求

至少执行：
- 后端 build 成功
- 前端 build 成功
- 能打开登录页
- 能使用默认管理员登录
- 登录后能获取当前用户信息
- 退出登录后受保护页面不可直接访问
- 未登录状态下当前用户接口返回合理结果

## 九、输出要求

完成后请明确说明：
- 登录方案是 cookie 还是 token
- 当前用户信息包含哪些字段
- 登录态保存在什么位置
- 默认管理员如何配合种子数据落地
- 哪些地方是故意保持最小实现
- 验证结果

## 十、常见误区

请避免：
- 在没有默认管理员的情况下做登录能力
- 把授权判断直接塞进登录模块
- 把前端和后端分别做出两套不一致的当前用户模型
- 先做大量用户管理页面，再回头补最小登录闭环
