# Identity Lite / LocalAuth 模块边界 v1

## 1. 模块定位

`Identity Lite / LocalAuth` 模块负责新平台 V1 的最小登录能力。

它解决的问题是：
- 平台能否登录
- 登录后如何识别当前用户
- 如何提供一个默认管理员入口，支撑开发与验证

它不负责：
- 完整用户中心
- 完整组织架构
- 外部统一身份认证平台深度集成
- 多租户身份隔离体系

## 2. 当前边界

### 纳入范围

- 本地登录接口
- 退出登录接口
- 当前用户信息接口
- 会话或 token 的最小实现
- 默认管理员种子账号
- 前端登录页
- 登录态恢复与跳转

### 排除范围

- 密码找回全流程
- 注册中心
- 单点登录
- LDAP / OAuth / OpenID Connect 深度接入
- 完整用户管理后台

## 3. 输入与输出

### 输入

- 用户名与密码
- 登录凭证
- 当前请求上下文

### 输出

- 登录成功结果
- 当前用户信息
- 登录态失效结果
- 退出登录结果

## 4. 推荐内部结构

- `IdentityLite.Contracts`
  - 登录请求与响应模型
  - 当前用户模型
  - 登录服务接口

- `IdentityLite.Core`
  - 登录校验
  - 当前用户解析
  - 默认管理员种子逻辑

- `IdentityLite.Infrastructure`
  - 本地用户存储
  - 密码哈希
  - token 或 cookie 实现

- `IdentityLite.Web`
  - 登录 API
  - 当前用户 API
  - 退出登录 API

## 5. 与其他模块的边界

### 对 Host

- Host 负责接入认证中间件和上下文
- Host 不负责实现登录逻辑

### 对 Authorization

- Identity Lite 提供“当前是谁”
- Authorization 负责“当前用户能做什么”

### 对前端 Shell

- 前端 Shell 负责登录页、登录态守卫、登录后跳转
- 不应把登录实现散落到各个模块页面

## 6. 最小可交付版本

V1 最小可交付版本应包含：
- 登录页
- 登录接口
- 当前用户接口
- 退出登录接口
- 默认管理员账号
- 登录后进入主界面

## 7. 风险与提醒

- 不要把 Identity Lite 直接膨胀成完整身份平台
- 不要把认证和授权混成一个模块内部的隐式逻辑
- 必须提供可重复使用的本地种子数据方案，否则本地验证会很痛苦
