# NewP 样式推进策略

## 目的

这份文档用于统一 `NewP` 的样式推进节奏，避免后续模块开发过程中反复讨论“现在要不要做样式”。

核心原则只有一句话：

**不是等全部功能做完再统一样式，也不是现在就做最终视觉精修，而是先定基础样式，再随功能推进模块样式，最后统一做视觉 polish。**

## 三个阶段

### 阶段一：基础样式层

目标：
- 统一颜色、间距、圆角、边框、阴影、字体等基础 token
- 统一登录页、Shell、首页门户、Header、Sidebar 的基础结构
- 统一按钮、输入框、卡片、表格外壳、标签页、状态徽标等首批共享元件

边界：
- 只解决“风格不再漂移”和“后续页面有统一落点”
- 不追求品牌感、动效、微交互等最终 polish

执行时机：
- 现在就开始
- 在模块大规模扩张之前完成

### 阶段二：模块级可用样式

目标：
- 随功能开发，把列表页、筛选区、详情区、状态区逐步收敛到统一样式
- 让 Authorization、ConfigCenter、Audit、Files 等模块页面具备一致的信息密度和结构层次

边界：
- 以“可用、一致、可继续扩展”为目标
- 不为单个页面做重品牌化或过度精修

执行时机：
- 与功能开发并行推进
- 不需要等所有模块开发完成后再开始

### 阶段三：视觉精修层

目标：
- 统一品牌感
- 增加必要动效、微交互、图标/插画系统
- 处理页面细节、空状态、节奏感和高级视觉表达

边界：
- 放在主要结构稳定之后
- 避免在页面和模块还频繁变动时提前投入

执行时机：
- 主要功能稳定后再集中处理

## 执行口径

- 新模块开发默认复用阶段一已经定义的 Shell 与共享元件
- 新页面开发时优先接入阶段二的统一页面结构，不允许各自发明一套风格
- 如果某个页面只需要“能用”，做到阶段二即可，不要提前进入阶段三
- 如果遇到是否要做视觉精修的争议，默认回到这份文档，以“三阶段顺序”作为判断依据

## 当前结论

`NewP` 当前处于：

**阶段一已开始并应优先落实，阶段二随后与模块开发并行推进，阶段三暂不提前启动。**
