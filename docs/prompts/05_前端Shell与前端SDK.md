请在新平台前端中实现第一版 Shell 和前端模块接入 SDK。目标不是做完整后台，而是建立“可登录、可进入主界面、可挂载模块页面”的前端基础壳。

## 一、开始前先阅读

请先阅读并遵守：
- `AGENTS.md`
- `docs/scope-v1.md`
- `docs/module-boundaries-v1.md`
- `docs/identity-lite-module-boundary-v1.md`
- `docs/authorization-module-boundary-v1.md`

## 二、本轮任务目标

本轮只解决 4 件事：

1. 建立前端平台壳（Shell）
2. 预留最小登录页与登录态接入点
3. 建立模块通过 SDK 接入菜单、路由和页面的基础机制
4. 给 Demo Module 提供一个可挂载位置

## 三、本轮必须产出的内容

请实现：

### 1. 登录相关前端基础
- 登录页
- 未登录跳转逻辑
- 当前用户状态接入点
- 登录成功后的跳转位置预留

### 2. 主界面壳
- 登录后基础布局
- 左侧菜单容器
- 顶部导航
- 路由容器
- 全局错误边界

### 3. 权限与路由基础
- 路由权限守卫
- 菜单权限守卫
- 页面挂载入口

### 4. 前端 SDK 契约
- 前端模块元数据契约
- 路由注册契约
- 菜单注册契约
- 权限点声明契约
- 国际化资源注册契约

### 5. Demo Module 的前端接入
- 通过 SDK 注册一个最小页面
- 菜单中可见
- 可通过路由访问

## 四、本轮明确不做

这轮不要做：
- 复杂视觉设计
- 完整门户首页
- 复杂导航系统
- 大规模菜单系统
- 旧 `.aspx` 页面兼容
- 多语言全量实现
- 完整状态管理平台

## 五、结构要求

请保证：
- 壳负责组合，不负责业务逻辑
- 模块通过 SDK 注册，不要直接改壳内部私有实现
- 登录态管理集中，不要散落在各个页面
- 路由守卫和菜单守卫不要各写一套完全不同的权限判断

## 六、建议实施顺序

建议按这个顺序推进：

1. 建立前端启动结构
2. 建登录页和未登录跳转
3. 建登录后主界面壳
4. 建当前用户状态接入点
5. 建菜单和路由容器
6. 建前端 SDK 契约
7. 接入 Demo Module
8. 补全错误边界和基础守卫

## 七、验证要求

至少执行：
- 前端依赖安装成功
- 前端 build 成功
- 登录页可访问
- 未登录访问受保护页面会跳转
- Demo Module 能在菜单和路由中出现

如果已经有登录接口，则建议继续验证：
- 登录后可进入主界面
- 当前用户状态可获取

## 八、输出要求

完成后请明确说明：
- Shell 由哪些部分组成
- 登录页和主界面的关系
- 当前用户状态怎么接入
- 模块如何通过 SDK 注册菜单与路由
- Demo Module 如何接进来
- 当前仍是占位的点有哪些
- 验证结果

## 九、常见误区

请避免：
- 直接在 Shell 内部手写 Demo 页面，不走 SDK
- 登录态逻辑散落到多个组件
- 先做复杂 UI，再回头补结构
- 用旧页面兼容逻辑污染新壳
