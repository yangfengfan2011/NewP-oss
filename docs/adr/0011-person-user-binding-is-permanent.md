# 人员账号绑定一经提交即永久有效

Organization 只允许启用人员与尚未绑定、未删除且非本地管理员的账号建立永久一对一绑定；账号可以处于启用或停用状态，停用账号绑定后仍保持停用。绑定前必须展示双方关键标识、要求二次确认和原因，并在提交时重新验证状态、唯一性与版本。绑定后产品功能和服务器维护工具都不提供解绑、重绑或误绑定修复，已绑定人员和账号均永久禁止删除；数据库通过 Person 上非空 User EID 的唯一约束保证一个账号最多绑定一个人员，重复提交同一绑定才可幂等成功，任何不同组合都返回稳定的冲突结果。

这一决定接受误绑定只能通过恢复数据库备份或受控数据迁移处理的运营代价，换取业务模型中不存在可解除或可替换绑定状态。绑定不建立独立 Link 模型，也不产生 LID；Organization 在 Person 上保存一次性写入且不可修改的 User EID，以及绑定时间、操作者和原因。Identity 不保存 Person EID，只在 User 上保存初始为否、绑定后永久为是的 `IsPersonnelBound` 单调标记，使 Identity 无需反向依赖 Organization 即可独立禁止已绑定账号删除。

Person 的 User EID 与绑定元数据不进入标准 CRUD 的创建或更新契约，只能由专用绑定命令写入。`PUT /api/organization/persons/{personEid}/user-binding` 在同一数据库事务中原子写入 Person 的绑定字段、User 的人员绑定标记和 Identity 安全事件；同一人员与账号的重复请求返回既有结果，不创建新事实，人员或账号任一方与其他对象组合时返回稳定的 `409 Conflict`。任一验证、并发检查、持久化或事件写入失败时全部回滚。

绑定入口只出现在 Personnel 的人员详情页，并分别展示 Person.Name、User.ECODE、User.ENAME、账号状态和绑定元数据；绑定建立、Person.Name 修改或 User.ENAME 修改都不会在两个名称之间复制或同步。Identity 管理页只展示账号是否已永久绑定人员，用于解释删除为何被禁止，不反向查询或展示 Person 详情。Identity 账号目录暂时不可用时，人员详情仍展示 Organization 自有的 User EID 和绑定元数据，并将账号信息标记为“暂不可用”；此时绑定命令安全关闭并返回稳定的 `503`，不得使用缓存或猜测状态完成绑定。

人员详情通过 Organization 专用候选接口按 ECODE 或 ENAME 搜索可绑定账号，每次最多返回二十条，只包含未删除、未绑定且非本地管理员的 Enabled 或 Disabled 账号，不提供完整账号枚举。人员已停用或已绑定时不开放候选查询；客户端不能绕过该入口直接把任意 User EID 提交为候选事实，最终绑定命令仍须重新验证全部条件。
