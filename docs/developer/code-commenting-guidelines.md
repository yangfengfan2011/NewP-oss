# 代码注释规则

本规则适用于仓库中的全部代码，不按目录、模块、语言或测试代码区分。

注释的目标是让人和 agent 在小上下文内理解实现意图、边界、失败信号和验证方式。

## 默认规则

- 所有方法默认写注释，包括公共方法、内部方法、私有方法和测试方法。
- 注释优先说明方法职责；存在非直观逻辑时，继续说明“为什么”、“边界在哪里”、失败信号、验证方式或回滚思路。
- 关键的宿主装配、跨模块协作、状态切换、迁移、投影、冲突处理、安全保护和回滚流程，在相关代码块前补充高价值注释。
- 修改代码时同步更新注释；已失效的注释直接删除。
- 新增注释默认使用简体中文。文件长期使用英文注释时保持文件一致；协议名、接口名、字段名和错误字面量保留原文。

## 注释形式

- 公共 Contracts 和 SDK 的 `public` 方法使用 XML 注释，说明职责、关键参数语义和非直观的返回结果。
- 其他方法在方法前使用简短注释说明职责或实现意图。
- 代码块注释通常使用 1 到 3 行，放在相关代码块前。
- 术语与当前 Context、ADR、Contracts 和代码保持一致。

## 价值标准

注释应提供代码本身不能直接表达的信息。避免逐句翻译赋值、条件、循环和返回语句，也不写“开始处理”、“返回结果”这类没有新增信息的说明。

简单方法仍需要方法注释，但只需要一句说清职责，不为了长度重复方法名或实现细节。

## 修改自检

完成代码修改前检查：

- 每个新增或修改的方法都有与当前行为一致的注释。
- 关键边界、状态切换、失败信号和回滚路径没有依赖隐性知识。
- 注释没有逐句翻译代码，也没有与实现失配。
