# 人员停用与关联账号停用原子提交

人员档案停用时，Organization 必须在同一个数据库事务中原子提交人员停用、关联用户账号停用、人员停用阻断以及该账号全部认证会话撤销；任一写入或校验失败都回滚全部变更，调用方可以幂等重试，不能留下部分成功的补偿状态。Person 不声明 `Revision`，人员生命周期命令也不接受人员版本；User 作为独立安全聚合仍按 Identity 契约使用自身 `Revision`。若 Identity 账号版本冲突，协调器返回稳定的 `409 LIFECYCLE_CONFLICT`，不得覆盖账号上的其他操作。

人员恢复与解除人员停用阻断也必须在同一事务中提交，任一失败全部回滚；账号仍保持停用，旧会话仍保持撤销。该决定要求这些状态继续处于同一共享事务边界，禁止把此流程实现为远程调用或最终一致联动；如果未来拆分数据库，必须先重新设计这一不变量。人员与账号启停只能经过专用生命周期命令，普通 CRUD 更新不得绕过该事务。关联人员停用期间，Identity 必须拒绝启用账号；人员恢复后账号恢复仍须显式执行。受保护的本地管理员不得建立人员账号绑定。

该用例由 Organization 应用层的专用协调器拥有并编排；协调器只依赖 Identity.Contracts、Authentication.Contracts 和不含业务规则的平台事务执行器，Host 只负责装配。各参与模块在共享事务中登记变更但不自行调用 `SaveChangesAsync`，由事务执行器统一保存并提交；这条专用命令路径不得复用当前会立即保存的通用 CRUD 仓储方法。
