# Authorization

Authorization 上下文拥有角色、用户角色关系、功能点索引和角色功能授权，把已认证主体、完整活动功能目录与端点执行绑定解析为服务端访问决策。它不拥有登录凭据、Cookie、业务数据或前端可见性状态。

## Language

**认证（Authentication）**：
验证请求由哪个主体发起，并建立服务器可信的主体标识。认证成功不表示主体有权执行任意业务操作。
_Avoid_: 授权、角色检查、登录后全放行

**已认证主体（Authenticated Subject）**：
由认证机制建立、具有稳定 subject ID 的请求主体；判权只使用服务器可信标识，不接受请求体或查询参数提供的用户 ID。
_Avoid_: 当前用户参数、前端用户对象、角色名

**Endpoint Access Rule**：
一个服务端 endpoint 的终态访问分类：公开、仅认证、Host policy、显式功能位置或拒绝。模块业务 endpoint 和 Standard CRUD 不允许缺少终态规则。
_Avoid_: 前端路由 guard、Controller 内手写 if、默认登录即可

**授权决策（Authorization Decision）**：
一次可信主体、已登记功能位置及其绑定行为的结果：Granted、Denied 或 Indeterminate。Indeterminate 表示依赖故障，必须 fail closed，但不伪装成业务拒绝。
_Avoid_: bool 默认 true、前端可见性、异常即放行

**本地管理员（Local Administrator）**：
沿既有初始化机制建立的受保护角色及其主体。角色获得当前完整功能目录的显式授权，仍执行正常功能判权；普通管理入口不能修改其受保护定义或分配。
_Avoid_: root、权限通配符、角色名硬编码放行

**当前主体功能投影（Current Subject Feature Projection）**：
返回给 Shell 的当前已认证主体有效功能位置，用于菜单、Tab 和动作体验；它不替代服务端 endpoint 授权。
_Avoid_: 任意用户权限查询、授权事实源、Cookie 权限快照

**功能授权点（Feature Authorization Point）**：
角色直接授予的功能单位，包括导航、Tab 和动作；页面承载内容，不是单独勾选的功能授权点。
_Avoid_: 独立业务权限代码、页面权限、接口权限

**功能授权树（Feature Authorization Tree）**：
按导航、Tab 与动作的声明位置组织功能授权点的树；标准页面和自定义页面的功能采用同一授权模型。
_Avoid_: 页面实现注册表、接口调用树、角色继承树

**授权位置（Authorization Placement）**：
功能授权点在所属入口及声明结构中的位置；不同位置的动作分别授予，即使名称或业务实现相同。
_Avoid_: 按钮显示名称、屏幕坐标、共享实现身份

**入口依赖（Entry Dependency）**：
一个功能授权点所依赖的本分支入口授权；角色授权集合必须满足该依赖，其他分支的入口不能替代。
_Avoid_: 隐式连带授权、任意可达路径、跨角色依赖补齐

**入口归属（Entry Ownership）**：
页面内容及其读取所属的导航或 Tab 授权位置；没有独立可见入口的详情直链也有明确归属，弹窗沿用发起位置。
_Avoid_: 来源页、浏览器访问历史、独立页面权限

**节点类型分组（Node Type Group）**：
功能授权树内用于区分不同树节点类型操作的展示分组，本身不单独授权；具体业务记录不是该分组的子授权点。
_Avoid_: 记录授权、每条记录的权限节点

**授权管理员（Authorization Administrator）**：
通过角色显式获得授权管理动作的可信主体，按获授动作在全局范围内管理角色功能或用户角色关系；该资格不专属于 LocalAdmin，也不自动包含未授予的其他管理动作。
_Avoid_: 角色名特判、只能授予自身已有功能、自动获得全部管理权限

**功能点索引（Feature Point Index）**：
正式功能目录的持久化索引投影，用于关联角色授权和识别目录变化；它不拥有独立的业务权限含义或可编辑的功能定义。
_Avoid_: 第二份权限目录、功能声明真源、完整页面结构副本

**功能授权工作台（Feature Authorization Workbench）**：
供授权管理员选择角色、查看完整功能树并配置该角色功能授权的独立入口；只读访问与保存授权分别授予。
_Avoid_: 角色详情授权弹窗、角色基础信息编辑、用户角色分配

功能位置的身份、入口依赖和切换边界见 [ADR-0048](../../adr/0048-functional-authorization-uses-entry-positions.md)。

### 数据范围授权（已确认目标，按 #227 分片交付）

以下术语属于 [正式规格 #227](https://github.com/yangfengfan2011/NewP/issues/227) 的已确认目标，来源讨论 [#226](https://github.com/yangfengfan2011/NewP/issues/226) 已关闭；职责边界见 [ADR-0052](../../adr/0052-data-scope-authorization-keeps-management-and-action-boundaries.md)。

**数据范围授权（Data Scope Authorization）**：
决定某主体的某个动作可以作用于哪些资源对象的授权，不替代认证、功能授权、系统强制隔离或业务必需约束。
_Avoid_: 功能入口授权、列表筛选、字段授权

**数据授权动作（Data Authorization Action）**：
数据范围裁决所针对的独立动作定义，可被多个功能入口引用，与功能授权点的声明位置分别表达对象操作含义和入口资格。其启用状态只决定是否执行该动作自身的数据范围裁决，不表示业务动作或功能入口停用。
_Avoid_: 按钮位置、对象操作扩展点、资源名称、功能入口启停

**规则授权（Rule Authorization）**：
以条件及其层级限定适用对象，并由匹配主体授权项表达动作意见的授权配置。
_Avoid_: 主体基础资料、对象 ID 清单、展示顺序

**对象授权（Object Authorization）**：
针对明确资源类型及对象身份配置的主体动作授权，其明确结果优先于同一对象、同一动作的规则授权结果。
_Avoid_: 功能授权点、只有裸 ID 的授权、每个对象一棵规则树

**对象授权管理资格（Object Authorization Management Eligibility）**：
管理某个对象整份授权配置的独立资格，要求相应功能资格及该对象的最终读取和授权动作允许；可管理自身及他人的授权项、调整优先级和转授授权动作，不以操作者自身已有业务动作权限为上限。
_Avoid_: 对象编辑资格、授权项创建者所有权、只能授予自身已有权限、整类规则管理资格

**规则管理资格（Rule Management Eligibility）**：
由独立功能授权授予的规则维护资格，LocalAdmin 具备，普通用户也可获授；它与具体对象上的授权管理资格分别授予。
_Avoid_: LocalAdmin 专属身份、对象编辑资格、对象授权的自动附带资格

**数据范围豁免（Data Scope Exemption）**：
LocalAdmin 不受规则授权及对象授权限制，且无需执行该层条件的特定资格；它不豁免其他访问与业务约束，也不豁免授权配置的有效性校验。
_Avoid_: 普通授权管理员资格、功能权限绕过、任意故障放行

**授权主体目录（Authorization Subject Directory）**：
在相应授权管理资格与系统强制隔离约束下，提供配置所需主体身份、名称和必要层级的最小目录；它允许识别业务页面不可读的主体，不授予主体业务记录的读取权。
_Avoid_: 业务 Lookup、完整主体档案、对象读取授权

**读取条件（Read Condition）**：
授权条件中明确用于读取范围裁决的部分；未提供读取条件不等于授权条件执行故障。
_Avoid_: 完整业务判断、缺失即恒真、故障即未配置

**读取依赖（Read Dependency）**：
某个动作要求目标对象的最终读取权限同时允许的前置关系；动作同意不自动补授读取权限。
_Avoid_: 自动补权、入口依赖、所有动作的隐含共同前提

**公司主体（Company Subject）**：
按人员当前公司归属匹配该公司全部人员的授权主体，不另外区分公司本级与下级部门人员。
_Avoid_: 直属公司人员、租户、公司节点可见性

**部门主体（Department Subject）**：
按人员当前部门归属匹配的授权主体；授权项选择仅本部门或同时包含其下级部门，默认仅本部门。
_Avoid_: 部门资源的数据条件、公司全体人员、组织准入

## 角色管理与事务性功能配置

角色维护的确定性业务拒绝由 `RoleValidationException` 表达，HTTP 只将此类拒绝翻译为既有 400 Problem Details，保留原文案；持久化、审计来源等依赖故障及取消继续传播，不伪装成请求校验失败。角色删除的 HTTP 禁用规则保持不变。

- 角色列表与详情普通字段复用 Standard CRUD 的查询与显示计划，但 Authorization 不映射通用写入端点。角色创建和编辑仍须保护 LocalAdmin、角色代码与系统字段，遗留内部删除还承担历史引用测试，因此普通写入由 RoleService 直接持有，不为形式统一注册对象行为或纯转发类；角色删除 HTTP 继续明确拒绝。
- 角色功能授权和普通账号角色分配是 Authorization 拥有的两个完整业务用例。Controller 分别直接调用 RoleFeatureAssignments 与 IUserRoleAssignments；它们不经 RoleService 转发，也不拆成关系逐行 CRUD。两者继续复用平台事务、可信审计和同一授权模块持久化边界。
- 角色读取、创建、编辑、角色功能配置和用户角色分配分别按声明位置判权。普通主体可以显式获得这些管理动作，获授动作在全局范围生效，不以操作者自己的功能集裁剪可配置目录。拥有一个管理动作不自动获得其他动作。
- LocalAdministratorCatalog 收敛受保护角色定义及模块内存中的规范身份比较；共享 Contracts 只公开 Host 与模块共同使用的稳定角色代码。FeatureCatalogSynchronizer 在完整候选准备后同步功能点与 LocalAdmin 全集。管理员不通过角色名绕过正常功能判权，也不重建旧 Permission 目录。
- FeatureCatalogSynchronizer 在事务成功后发布不可变活动目录。历史或失效功能行不能成为授权源；停用角色可以配置，但不进入有效授权。
- RoleFeatureAssignments 统一读取目标角色的当前活动功能集合，并在角色主键写锁内读取实际旧集合、校验完整新集合及本分支入口依赖，通过平台事务统一保存关系和 role.features.changed 审计。相同集合或排列变化不产生分配记录，不引入 Revision 或自动重放。
- Authorization 只引用 Audit.Contracts，由 Audit 登记稳定 authorization.role 目标和字段差异；不形成反向模块加载依赖。缺少 recorder 或登记、写入、保存、确定未提交的提交失败都不会返回成功。当前角色名称由 Authorization 批量提供，删除目标后记录保留 ID。
- 角色列表与详情复用 StandardCrudService 的 Entity display 计划：用户字段批量解析，时间按请求 locale/timeZone 显示，原始审计值保持不变。角色页面未声明删除动作，遗留删除 HTTP 入口继续明确拒绝。
- 独立工作台拥有数据库分页角色选择、完整虚拟功能树和当前角色草稿。节点独立勾选，分支全选是显式操作；搜索保留祖先，筛选保留隐藏选择。保存一次提交完整集合；切换角色和离开页面均保护未保存草稿，失败保留草稿，未知写入结果先查询实际状态。
- 工作台查看和保存分别授权。原角色列表及详情快捷入口只跳转并选中角色，采用目标导航资格，不生成额外授权点或第二套编辑状态。角色基础信息与用户角色输入继续使用共享 CRUD 动作宿主。

## 普通账号角色分配

- 普通管理通过 Identity 稳定账号目录校验全部目标；Disabled 可引用，Deleted 和受保护账号拒绝。现有 LocalAdmin 角色成员独立受保护，整组越界整体失败；内部初始化路径保持。
- Authorization 用户角色替换使用事务级账号应用锁，覆盖首次空集合。锁内读取实际旧关系、完整校验全部角色并登记 user.roles.changed；关系和记录由平台事务统一提交，异常不自动重放。停用角色允许配置但不产生有效权限。
- 差异以规范角色 EID 的 reference 前后值表示增加或移除，目标为 identity.account EID。Identity 和角色目录批量解析当前名称，缺失时保留历史 ID。集合相同或顺序变化不登记。
- 正式角色详情及行操作中的账号角色动作复用共享弹层；账号有界搜索、角色数据库分页，页外已配置选择保留到完整集合保存。

## 当前授权消费与界面同步

- 单次正式判权先将完整位置解析为活动功能点 EID，再以当前主体、用户角色、启用角色和功能授权的一次数据库关联存在性查询判断；不逐角色查询，也不读取用户全部授权来判断单次动作。Shell 的完整功能位置投影是独立读取需求。
- 移除全部启用角色来源才算撤权。同一认证 Cookie 的后续请求使用新授权，已经通过判权的在途请求允许提交，不添加提交前复判或服务端权限版本。
- Shell 页面导航重取当前主体；浏览器刷新沿用启动认证读取。共享请求收到明确 401/403 后触发同一认证 owner 刷新，菜单与按钮只消费返回投影。权限集合变化重建主体查询 scope；写拒绝同时清空旧查询，读拒绝清空自身失败结果，避免重复的读拒绝/刷新循环。本地 query scope 计数只用于缓存失效，不是授权事实或跨请求版本。
- 认证/授权依赖故障保持原始失败及现有认证不可用边界，不将 503 等故障解释成撤权。明确业务拒绝不重放，网络异常或成功写响应无法读取时提示先查询实际结果；只有业务执行前稳定防伪失败仍允许一次令牌恢复。

## 旧授权退出与回退

旧 Permission 和 RolePermission 存储模型仅为既有迁移历史兼容及切换清理保留。完整功能目录、端点绑定及 runtime staging 准备成功后，功能目录同步事务清理旧分配与旧目录；准备失败不清理，事务失败整体回滚。旧行是否存在表示清理是否仍待完成，清空后的启动不再对旧表执行写入，也不清空已经重新配置的普通角色功能授权。

旧权限目录、角色权限读写、任意用户权限查询和旧判权消费者退出正式接口；认证响应和 Shell 使用功能位置投影。用户、角色、用户角色关系、业务数据、审计及迁移历史保持。普通角色切换后通过工作台重新配置，不反推或迁移旧权限含义。

回退须同步恢复目录、前后端授权消费和模块接入。代码回退不能恢复已清空的旧授权，恢复旧机制后仍须重新配置；不改写业务数据、审计或迁移历史。


## 数据范围读取、主体、条件、规则树与对象授权（#228—#232）

- 独立 `dataActions` 由 Capsule 声明并经正式候选编译，开关属于动作目录；默认启用、停用保留配置，启动装配后生效。规则保存后的下一次请求直接读取已提交配置，不建立权限版本或跨请求缓存。
- `DataScopeResource` 从全部显式 Standard CRUD 描述符取得资源键、模块、模型和 ID 字段，包含 Identity 账号资源，不从页面或裸模型名猜测身份。Authorization.Contracts 暴露可组合读取计划；公共查询在 Count、排序、分页前应用谓词，详情在同一数据库比较规则下核对可读性，拒绝返回 404。LocalAdmin 跳过该层配置和条件执行；认证与功能资格保持原流水线。
- 固定 Instant 条件在保存时按既有可信时区规范为 UTC，读取只解释已存规范值；CalendarDate 不作时区转换。管理入口 `/authorization/data-scope` 编辑一棵根规则及子树，支持组合条件、固定值或有类型当前身份值、多主体显式优先级与读取三态。节点和主体项身份稳定，根/父关系及资源一致且无环。整树 PUT/DELETE 复用平台事务及根目标锁，实际旧配置与 `dataScope.rule.changed` 审计共同提交；失败保留旧配置，无变化不登记。
- `DataScopeRuleNode`、`DataScopeRuleSubject` 的模型 owner 是 Authorization；物理迁移沿现有 `platform.foundation` 载体追加 `20260922094146_AddDataScopeRules`，不改写旧 migration、业务数据或历史。将来独立 bundle 的迁移不属于本片。
- `IDataScopeIdentityProvider` 是主体、最小管理目录与当前身份值的稳定扩展契约；Identity 注册用户/当前账号，Authorization 注册所有已认证用户（界面显示“所有用户”）与当前有效角色，Organization 注册公司、部门及当前人员/公司/部门。模块通过既有 `ConfigureServices` 接入，核心不识别模块业务字段。资源 owner 用 `DataScopeContextBinding` 显式绑定直接字段的规范身份域；CLR 类型相同不能使账号、公司、部门身份混用。
- 可信账号来自服务端认证主体；每次读取计划为实际引用的 provider 解析一次事实，各规则及 SQL 业务行复用结果。Organization 读取 `IOrganizationQuery` 已发布当前关系，角色读取当前启用角色和用户角色关系，不写入登录快照。合法缺失不命中/不贡献当前值条件，事实源故障继续传播，不能伪装为正常拒绝。
