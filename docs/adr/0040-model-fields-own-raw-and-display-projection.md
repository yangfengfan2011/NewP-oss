# Model 字段拥有原始值与显示值投影契约

Standard CRUD 的关联名称、枚举文本、人员名称和时间文本曾分别由资源 descriptor、DTO、列表、详情或前端 renderer 补齐，导致同一字段在不同读取入口采用不同命名与转换规则。平台决定由 Model 的字段显示规则统一拥有显示语义；原始字段值继续承担持久化、排序、筛选、写回和系统集成，显示值以 `<Field>_DisplayValue` 作为输出专用伴随字段，并在被请求时与原始字段值成对返回，不能覆盖或替代原始值。

列表、单条读取、写入成功结果、选项和用户可读导出共用同一展示投影。关联、用户、枚举和时间采用同一字段级契约，但由各自策略解析；模块只为其拥有的业务数据提供批量解析，不在页面或 Adapter 中重复字段别名。显示目标缺失或非关键依赖不可用时保留原始值并让显示值降级为空；违反声明字段集合、覆盖原始字段或返回错误行对应关系必须稳定失败。源资源字段的读取授权和显式字段显示规则只允许返回声明的显示值，不隐式授予目标资源管理权限或暴露其他字段。

Model 至少区分日历日期、时间点和本地日期时间。字段显示规则只允许“日期”和“日期时间到秒”两种标准时间显示格式，不接受任意 formatter 或 metadata 格式串；日历日期只使用日期格式，时间点与本地日期时间默认使用日期时间到秒并允许显式选择日期格式，显示格式不改变字段的原始时间语义。时间点原始值使用 UTC；服务端依据请求展示上下文生成最终显示文本，该上下文使用登录时固定的规范 IANA 时区和当前请求 locale。日历日期与本地日期时间不按查看者时区转换；时间点输入和范围筛选按同一会话时区解释并转为 UTC，DST 无效或歧义输入稳定拒绝。显示值不参与当前阶段的排序和筛选；需要按显示值执行数据库级查询时必须作为独立查询投影能力设计，不能在分页后内存处理。

用户账号显示名称按读取时的当前 ENAME 解析，不建立历史名称副本；系统 actor 使用平台稳定显示值，已删除或无法解析的账号回退原始 EID。用户可读导出默认输出显示值，面向系统交换的原始导出需要独立显式入口。切换必须同时收口 Model 投影、生成 DTO、查询与详情结果、前端消费和现有手工别名，不保留第二套运行时 fallback。

展示投影按字段收集并去重原始值，再通过批量策略解析为原始值到显示值的受控映射；不继续使用逐行 fallback 或依赖返回数组顺序。第一阶段只支持 reference、user、group、enum 和 instant 等结构化策略，复杂业务文本使用模块拥有的计算字段，不开放任意 formatter key。Runtime Column 只能继承所引用 Model 字段的显示规则，或声明由计算型行数据提供的伴随显示字段，不能返回前端 formatter 或 UI 节点。

伴随显示字段使用保留后缀 `_DisplayValue`，类型固定为字符串或空值且只允许出现在输出中；客户端在创建、更新或导入请求中提交该字段必须稳定拒绝。现有 `CompanyName` 一类资源别名一次性迁移为规范伴随字段，候选编译必须拒绝命名冲突，不保留双字段、deprecated alias 或运行时兼容 fallback。展示结果按认证会话、有效时区和 locale 隔离，语言变化必须重新读取；第一阶段只做请求内批量去重，不建立跨请求显示值缓存。

认证会话持久化登录时确定的有效 IANA 时区；登录未提交时使用平台配置的合法默认时区，显式提交非法时区时稳定拒绝，登录响应返回最终有效值。现有活动会话通过 migration 回填平台默认时区，会话轮换继承该值；locale 继续由当前请求提供。服务器保存 zone ID 而非固定 offset 或时区规则快照，并使用当前部署环境的时区数据库解释历史时间。

现有 Entity 审计时间根据其服务端 UTC 不变量迁为时间点，authoring `date` 迁为日历日期；其他既有 `datetime` 必须逐字段声明为时间点或本地日期时间，不能自动假定 UTC。已证明为 UTC 的数据只修复读侧 UTC Kind 和带 `Z` 的传输语义，不重写值；无法证明语义的历史数据必须另行评估。字段显示规则作为当前 Model 协议的可选能力演进，不建立平行协议版本；未声明规则的旧 Model 继续只返回原始值，采用新能力的插件通过 Host 最低兼容版本表达要求。

任何读取入口丢失原始值、同一字段在不同入口使用不同显示规则、逐行目录查询、前端资源特判、显示解析覆盖原始字段、UTC 传输无明确时区、日历日期或本地日期时间被错误转换、活动会话时区可被普通请求覆盖、跨展示上下文复用缓存、旧别名与规范伴随字段并存，或显示值进入写请求，都属于交付失败信号。回滚必须把 Model 协议、认证会话 migration、请求展示上下文、展示投影、资源 metadata、生成 DTO、前端消费和本 ADR 作为同一发布边界恢复。

最小纵向可行性验证由功能示例模块新增独立的真实 Standard CRUD display-value sample 资源承担，现有 runtime-columns 只读动态列表保持不变。样例 Model 至少以 User 字段验证 EID/ENAME 伴随值，并以时间点字段分别验证“日期”和“日期时间到秒”两种标准显示格式；List View 与 Detail View 只引用原始 Model 字段，不手写伴随字段、formatter 或 renderer。标准列表、单条读取、创建与更新成功结果、options 和用户可读导出读取同一投影；同一账号的两个真实认证会话使用不同时区读取同一 UTC fixture，必须得到相同原始值和不同显示值。该证据形成前不得批量迁移业务资源或展开完整实施图。
