# 组件化护栏

## 目标

这份文档用于把“组件化”从架构口号收紧成新增模块默认必须遵守的实现护栏。

适用范围：

- 新增后端模块
- 新增前端模块
- 新增模块接入 Host / Shell
- 新增迁移或导入链路

本轮不要求据此重构所有既有模块，但后续新增内容默认都要遵守这里的规则。

## 公共能力归属

### 必须进入 `Kernel / SDK / Contracts`

- 模块元数据契约
- 菜单、路由、权限、配置声明契约
- 迁移或导入钩子契约
- 模块注册帮助器
- 可复用的模块接入约束

### 可以留在模块内部

- 模块私有 DTO
- 模块私有服务
- 模块私有页面与页面状态
- 模块私有映射规则
- 模块私有查询或命令逻辑

### 禁止直接进入 `Host / Shell`

- 模块私有业务规则
- 模块私有状态管理
- 模块私有数据访问实现
- 临时迁移逻辑
- 为单个模块特制的宿主内部改造

## Host / Shell 护栏

### Host 只负责

- 启动
- 组装
- 模块加载
- 全局中间件
- 统一认证与宿主级接入

### Shell 只负责

- 布局
- 全局 Provider
- 菜单聚合
- 路由聚合
- 模块受控注册

### 禁止行为

- 不要把模块私有业务流程直接放进 Host / Shell。
- 不要为了接一个模块，直接修改 Shell 内部结构实现。
- 不要让迁移期临时方案固化成长期宿主结构。

## 前端受控接入点

前端模块正常接入时，唯一允许修改的 Shell 级入口是：

- `frontend/packages/shell/src/builtin-runtime-plugins.ts`

如果一个新增模块任务需要修改 Shell 的其他内部文件，应先补单独设计，说明为什么现有契约或受控清单不够用。

## 模板要求

### 后端模板默认应满足

- `*Module.cs` 只做模块声明与服务注册。
- `Controllers/*` 只做轻量接口入口。
- `Services/*` 只做模块内部服务。
- README 必须说明边界、禁改区和最小验证路径。

### 前端模板默认应满足

- `src/index.ts` 只做模块声明。
- `src/pages/*` 只做页面入口与最小加载逻辑。
- `src/services/*` 只做接口访问。
- README 必须说明边界、禁改区和最小验证路径。

## 脚手架要求

`new-module` 脚手架默认只允许自动更新以下受控接入点：

- `apps/host-api/HostApi.csproj`
- `frontend/packages/shell/src/builtin-runtime-plugins.ts`

脚手架不应引导开发者直接修改 Shell 其他内部结构。

## AI 执行提示

后续 agent 执行新增模块任务时，默认先判断：

1. 这次改动是否只触达允许的接入点？
2. 这次新增能力是否能通过现有 `Contracts / SDK / 模板` 完成？
3. 如果不能，是否已经补了新的设计文档？

如果以上任一问题答案是否定的，则不应直接进入实现。
