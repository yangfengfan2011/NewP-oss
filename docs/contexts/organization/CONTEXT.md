# Organization

Organization 上下文管理组织主数据与人员档案。它描述人员属于哪个组织，不拥有登录账号、凭据或授权分配。

## Language

**人员档案（Person）**：
组织中的业务人员记录，拥有独立人员标识，并可在组织结构能力可用后建立组织归属；它不等于可登录的用户账号。
_Avoid_: 用户、账号、员工账号

**公司（Company）**：
人员和部门所属的顶层组织主体。
_Avoid_: 租户、客户、法人账号

**部门（Department）**：
隶属于一个公司的组织单元，可具有上级部门。
_Avoid_: 团队、用户组、授权组

**组织归属（Organization Affiliation）**：
人员档案可选的公司与部门组合。公司和部门可以同时为空，使人员维护不依赖尚未就绪的组织结构能力；一旦填写归属，两者必须成对出现，部门必须属于该公司，且二者都处于启用状态。岗位仍是可选的补充归属。
_Avoid_: 用户组成员关系、授权归属、原始组织 ID

**岗位（Position）**：
部门内的组织岗位，可供人员选择；它不等于授权角色。
_Avoid_: 角色、权限角色

**任职状态（Employment Status）**：
人员的任职类型，例如全职、兼职、合同工或实习；它不表达记录是否可用，也不等同于离职流程。
_Avoid_: 在职状态、启用状态、账号状态、离职状态

**启用状态（Enablement Status）**：
人员档案当前是否启用的独立状态；停用不改变任职状态，但必须同时停用通过人员账号绑定指向的用户账号，恢复人员则不会自动恢复账号。
_Avoid_: 任职状态、账号状态、删除状态

**用户账号（User）**：
由 Identity 拥有、可被认证机制识别的账号；Organization 最多通过显式关联引用其标识。
_Avoid_: 人员档案、员工

**人员账号绑定（Person-User Binding）**：
启用人员与用户账号之间由 Organization 拥有的永久一对一关系；账号可以在启用或停用状态下完成绑定，停用账号绑定后仍保持停用。绑定后双方都不能删除、解绑或改绑，人员停用会强制停用账号，但人员恢复不会自动恢复账号；Person.Name 与 User.ENAME 始终分别维护，不因绑定自动同步。
_Avoid_: 可解除关联、用户角色、组织成员关系、账号归属

**人员中心（Personnel Center）**：
围绕人员档案查询、查看和维护提供的管理入口，不代表完整组织树或身份管理系统。
_Avoid_: 账号中心、人力资源系统
