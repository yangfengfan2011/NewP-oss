# CalendarDate 范围筛选使用显式标量边界

Standard CRUD 的 List View 已拥有查询字段和高级筛选结构，但现有列表状态、URL 与 API 过滤参数只承载标量值，查询内核也只执行等值与包含条件。人员中心需要按出生日期范围查询；出生日期是 ADR-0040 定义的日历日期，不能伪装为时间点，也不能通过人员专用筛选 UI、复合 JSON 参数或分页后的内存过滤绕开公共边界。

## 决策

List View 以一个逻辑 `dateRange` 查询字段声明日历日期范围筛选，并同时绑定原始 Model 字段、显式起始参数名和结束参数名。Shell 把它呈现为单个日期范围控件，但列表 URL 和 API 请求继续使用两个独立标量参数；人员出生日期采用 `birthDateFrom=YYYY-MM-DD` 与 `birthDateTo=YYYY-MM-DD`。只填写一端时只发送该参数，清空或重置时同时删除两端，URL 恢复、前进和后退必须还原同一已应用范围。

模块查询 customizer 把两个稳定筛选参数分别映射为同一原始字段上的 `gte` 和 `lte` 条件；平台查询内核拥有类型安全的比较、值转换与数据库下推。两端均为包含边界，只有一端时形成单边范围；提交非法日历日期或起始值晚于结束值必须稳定拒绝。未知或不适用于字段类型的操作符不得静默忽略。范围只筛选原始字段，不筛选 `<Field>_DisplayValue`，也不得在计数、排序或分页后进行内存过滤。

第一阶段只允许 `CalendarDate` 字段声明 `dateRange`。查询内核建立的比较机制不得按模块或字段名特判，但 List View 暂不公开 `Instant` 或本地日期时间范围控件；出现真实采用者后再决定 `dateTimeRange` 的输入、时区和 DST 契约。旧 List View 未声明范围筛选时行为不变；采用新能力的插件必须通过其 Host 最低兼容版本声明要求。

## 取舍

未把范围编码为逗号拼接字符串、JSON、数组或字段名推导的隐式参数。这些形状会破坏现有标量 URL 模型、降低链接可读性，或让参数命名成为未声明约定。未为 Personnel 增加自定义筛选组件或 Shell 资源特判；List View 继续是列表筛选结构的唯一 authoring 事实源，模块只负责把自己声明的筛选键映射到业务字段。

## 验收与失败信号

公共契约测试必须覆盖完整范围、两个单边范围、清空、重置、URL 往返、非法日期、反向范围、未知操作符与不支持的字段类型。查询测试必须证明条件在数据库计数和分页之前执行。Person 作为首个真实采用者，必须证明可空 `BirthDate` 的闭区间查询、空值排除、闰日、服务端分页、列展示和用户可读导出保持规范原始值与显示值边界。

出现模块注入范围筛选 UI、Shell 或查询内核出现 Person/`BirthDate` 特判、使用显示值筛选、复合参数形成第二套 URL 状态、非法操作符被忽略，或范围在分页后内存执行，均表示本决策失败。

## 回滚

回滚以 List View authoring 契约、解析后查询模型、Shell 范围状态与 URL、平台比较操作符、Person 采用 metadata 和对应测试为同一边界整体恢复。Person 的 `BirthDate` 数据列与 CalendarDate 基础语义不属于筛选协议的回滚单位；如需删除业务数据，必须另行评估迁移影响。
