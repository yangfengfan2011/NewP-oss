# 对象操作按职责复用并由对象拥有者开放动作横切

状态：已接受；[#215](https://github.com/yangfengfan2011/NewP/issues/215) 完成首期机制与 Organization 采用，[#222](https://github.com/yangfengfan2011/NewP/issues/222) 收窄采用职责。本决策保留首期历史事实，并以当前边界指导后续使用。

对象操作是按职责选择的复用机制，不是全部正式写入的唯一入口。普通 CRUD 可复用默认对象行为；只有存在对象级定制时才建立自定义行为。改密、生命周期、永久绑定、授权集合替换等完整业务用例由明确的业务服务拥有，并直接组合唯一业务核心。无论入口形态，页面与内部调用都必须复用同一业务规则，现有平台事务执行器与缓存提交机制继续承担提交和发布。

Example 普通 CRUD 的数据要求已由正式执行合同装配，默认写入器在原有候选和旧值保护位置消费有效要求；该合同只集中数据权限下限，不接管对象行为、扩展、审计或事务职责。未迁移资源按具体执行显式登记旧路径，不能因缺少入口声明而自动绕回旧判权；后续内部调用采用可信绑定时仍须保留每个目标执行自身的规则与必要要求。

轻量对象行为基类集中承载对象标识、支持操作及横切开放声明，并提供默认创建、更新、删除能力。继承是可选方式；默认行为足够时只登记定义，不编写空类或纯转发类。专用业务服务不为形式统一注册行为对象，也不通过行为类转发。业务服务与对象行为都可以组合已有业务核心，规则不复制为第二份实现。

默认创建与更新负责接入 Entity 审计四字段赋值：创建时初始化两组相同的创建和修改信息，更新时保持创建信息不变并更新修改信息。可信主体、服务端 UTC 时间、非空及更新时间下界继续遵循 [ADR-0026](0026-entity-audit-fields-are-non-null.md)。专用业务核心复用同一可信审计规则；同一次实际写入在持久化结果和缓存中使用相同最终值，不信任调用方伪造审计字段。统一审计规则不要求统一业务入口。

未迁移对象继续保留现有持久化层审计保障，并复用同一规则，不能因 Organization 先行采用而撤掉其他模块的保障。绕过普通 EF 跟踪的专用写入也须复用该能力；物理删除不先修改即将删除记录的审计四字段。业务审计记录与安全事件继续保持原有所有权，四字段赋值不替代业务日志。本实现调整赋值接入位置，不修改 ADR-0026 的公共不变量，也不把其他模块尚未迁移的目标记为当前事实。

对象拥有者决定哪些整个对象动作允许横切扩展，不逐阶段分别开放。动作支持、横切开放和横切实现是三项独立决定；登记业务动作不自动产生扩展点，也不为没有具体需求的专用服务新增横切。任意组件可以向已声明的扩展点贡献实现，目标和依赖在启动期装配时校验，对象拥有者不维护逐个实现的接纳名单。

同一扩展点允许多个实现及显式先后依赖。无依赖时采用稳定顺序，但扩展不得据此假定其他扩展已经执行；不可满足的扩展执行顺序依赖及其循环在装配阶段拒绝，不依赖扫描或注册的偶然顺序。扩展可以明确拒绝操作或补充处理，但不得替换、绕过对象必需规则，或跳过核心操作后报告成功；不同业务含义由对象拥有者提供明确动作。

操作前、操作后横切与核心操作共用同一数据库事务；操作后表示核心操作完成后、数据库提交前，任一环节失败整次回滚。本期不提供提交成功后发送邮件、调用外部系统等横切，这类副作用的可靠交付不由本契约承诺。

操作前扩展可通过受控上下文补充或修改业务输入，最终输入仍由对象拥有者在对应操作实现中、实际写入前执行必需规则校验。扩展不能任意改写主键、审计主体等受保护字段；操作后不能通过修改输入隐式触发第二次保存。

扩展可以调用另一个对象已声明的对象操作，目标操作仍完整经过自身规则和横切，并加入同一事务。扩展显式声明可能调用的对象操作，平台在外层开始前汇总所需协调范围。专用业务服务在同一平台事务中组合时，由服务声明并取得其模型协调范围；跨模块写入仍通过拥有者的稳定契约，不能直接修改其他模块数据。

同一事务中，后续对象操作的规则读取必须反映前序已完成操作的新增、修改和删除，包括尚未提交的新对象。操作内部使用事务内有效视图，不能混用导致规则失真的旧缓存结果；事务外读者仍只见已发布结果，不通过提前发布公共缓存提供事务内可见性。

本决策不复刻旧平台的数据容器和继承体系；除已确定的轻量行为基类职责外，不预设实体、关系等多层继承、具体签名或注册格式，也不把业务规则转移给 EF 变更跟踪或缓存基类。本期不处理横切递归调用及多个扩展修改同字段的冲突裁决，不增加相应检测、限制或冲突机制；这不改变已确认的扩展执行顺序依赖校验。

首期 #215 曾让 Organization 的公司、部门、岗位、人员普通 CRUD 以及人员 `enable`、`disable`、`bind-user` 专用命令都接入对象行为。#222 调整后的当前范围只保留四类对象普通 CRUD 的对象定义与扩展能力；人员启用、停用和永久账号绑定由 Organization 业务服务直接组合原有核心、可信审计和平台事务，不再声明对象动作或横切开放点。Identity、Authorization、Authentication 等模块按各自职责选择是否复用对象能力，不以“迁移完成率”作为目标。

回退按职责边界恢复：普通 CRUD 可恢复对应对象定义或自定义行为，专用业务可恢复原服务组合；任何回退都必须保留业务规则、可信审计、事务一致性及已确认缓存发布语义。已公开扩展点若迁移必须显式处理其依赖，不能静默跳过。ADR-0050 的数据库提交与缓存发布保证继续成立。
