# 用户账号使用显式且带终态的生命周期

User 以单一 `Status` 字段表达 `Enabled`、`Disabled` 和 `Deleted` 三种状态，并使用 Revision 保护生命周期命令的乐观并发；`Deleted` 是不可恢复终态。所有写命令携带 `expectedRevision`：如果生命周期命令的目标状态已经满足，则返回当前结果实现目标收敛；否则版本不一致返回 `409 IDENTITY_REVISION_CONFLICT` 和最新安全快照，由客户端刷新并重新确认，不自动重放原命令。人员停用阻断与永久的 `IsPersonnelBound` 是独立约束事实：前者在存在时阻止账号启用，后者永久阻止账号删除，二者都不能被折叠为新的账号状态值。

账号启用必须显式执行，且只允许从 `Disabled` 转换为 `Enabled`；账号停用会撤销全部会话，人员恢复只解除人员停用阻断，不改变账号状态。账号删除只允许从未绑定人员的非本地管理员账号进入 `Deleted`，清除认证凭据并撤销全部会话，之后任何恢复、登录或绑定命令都必须拒绝。相比多个可组合的启用、停用和删除布尔值，单一生命周期状态避免产生“既启用又删除”等无效组合，同时保留人员联动约束的独立语义。

账号启用或停用前，管理界面必须展示 ECODE、ENAME 与当前状态，要求填写原因并显式确认；删除采用更强的手工输入完整 ECODE 确认。所有确认之后，服务端仍按当前 Revision 与保护不变量重新裁决。
