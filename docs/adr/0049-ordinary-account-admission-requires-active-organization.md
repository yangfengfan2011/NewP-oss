# 普通账号准入要求完整且启用的组织归属

状态：已接受并实施。来源：[讨论 #207](https://github.com/yangfengfan2011/NewP/issues/207)。实施规格：[Spec #208](https://github.com/yangfengfan2011/NewP/issues/208)。

普通账号登录必须永久绑定人员，人员必须具有相互匹配的公司与部门归属，且账号、人员、所属部门、全部上级部门和公司均启用；任一对象停用均阻止进入系统。LocalAdmin 沿用独立初始化与维护身份例外，仍禁止绑定人员。本决策不新增其他账号例外，也不把组织归属解释为功能授权或数据隔离。

使用临时凭据建立仅允许首次改密的受限会话，同样要求满足上述准入条件。管理员先完成绑定与组织分配，用户再首次登录并改密；选择这一顺序，是为了避免正常登录与受限登录具有两套组织准入条件。

停用成功后，已有会话的下一次受保护请求必须拒绝访问，不等待主动退出或自然过期；已经执行中的请求不追溯撤回。此处规定访问生效边界，缓存更新与发布边界由 [ADR-0050](0050-organization-cache-holds-full-records-and-fails-closed.md) 约束。

公司或上级部门可以直接停用，无须先逐个停用下级；停用保留既有组织归属，不批量改写下级部门、人员或账号自身的启用状态，但阻止整个下属范围的普通账号进入系统。恢复上级不改变下级自身状态，原本单独停用的对象继续停用；这项目标替代 Organization ADR-0002 中“存在启用部门或启用子部门时不得停用”的限制，不改变人员停用强制停用账号的既有规则。

通过正式写入路径造成的普通账号任何一次已生效准入资格中断，均使该账号此前的全部会话永久失效，即使中断期间没有请求也一样。恢复组织、补齐归属或其他恢复资格的操作只允许重新登录，不复活旧会话；仅在下一请求检查当时状态、从而漏过两次请求之间的资格中断，不满足本决策。一次成功变更直接调到另一完整且启用的组织时，准入资格连续有效，保留仍有效的会话，后续请求使用新归属；先清空并保存、再补齐并保存则属于资格中断。

新增或改变人员组织归属、调整部门父级时，目标公司、目标部门及其全部上级部门必须启用；既有归属可以保留，允许将人员或部门移出停用范围，但目标仍须满足这些条件。该决定将原有归属校验扩展到完整上级链，不改变部门不得跨公司迁移的既有边界。

造成准入资格中断的组织或人员变更，必须与受影响账号此前全部会话的永久失效原子提交；任一部分失败，整次操作回滚并保留原状态，不得报告停用或归属变更成功。该要求覆盖公司、部门停用和人员归属清空等路径，并沿用 ADR-0002 的人员账号生命周期原子性；具体缓存发布协议不得削弱此要求，也不得将已提交的数据库变更伪称为回滚。

准入判定后创建会话的操作必须与准入资格变更形成明确的提交顺序：会话先创建成功，后续资格中断须将其撤销；资格中断先提交，会话创建不能依据旧准入结果放行。该约束覆盖普通登录、首次改密及其他会话轮换路径，不能仅协调登录控制器；Authentication 继续拥有会话登记与撤销，缓存基类不承载认证业务。已经取得完整只读结果的普通请求仍按既定边界完成，不因此把协调范围扩大为整个业务请求。

保留 ADR-0025 的人员准备阶段：人员可以先建档而没有公司、部门，随后补齐归属。登录资格与建档资格分开，关联普通账号在归属不完整时不能登录；本决策不收紧人员存储必填，也不改变 ADR-0011 的永久绑定和 ADR-0002 的人员账号停用联动。

停服直接改库后的旧会话处理暂不纳入本次范围；不新增统一会话撤销，也不保证识别维护期间发生后又恢复的资格中断，范围见 ADR-0050。

实现边界：Organization 实现 `Identity.Contracts.IIdentityAdmissionPolicy`，Authentication 在会话登记与验证时消费该契约；首次改密及其他轮换在统一事务内重新检查来源会话和准入条件。Organization 提交参与者计算资格中断范围，调用 Authentication 批量撤销契约，与组织变更原子提交。Host 只负责认证接入，缓存基类不拥有准入规则。

回退边界：人员可选归属和永久绑定保持原决策；若撤回本决策的登录限制，须显式重新评审准入规则，不通过缓存降级或登录旁路隐式放宽。
