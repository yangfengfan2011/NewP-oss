# ADR-0056：可移动组件源码根与聚合发行保留成员独立身份

NewP 将组件声明、元数据与前端实现合并为可移动的组件源码根，后端实现及迁移工程在 `server/modules` 内按组件身份定位；开发者通过组合 JSON 和目录归组生成完整聚合发行包，部署到不预装成员实现的固定 Host/Shell，保留成员独立身份、版本、数据与迁移归属。本决定采用[规格 #267](https://github.com/yangfengfan2011/NewP/issues/267) 已确认的交付边界：平台提供通用发现、构建、可信接纳、显式选版、启动激活及精确集合卸载，文件恢复与数据库前沿恢复各自保留事实；接入目标不逐组件修改 Host/Shell 或重新构建。

## 源码根与交付身份

首版先支持 NewP 本仓受控组件的可移动源码根和独立发行，不同时承诺完整的仓外代码组件开发 SDK。组件源码根仍指前端与声明目录：声明、metadata、资源和迁移清单与前端实现集中在 `frontend/modules` 内；后端实现及迁移工程位于 `server/modules` 内。前后端仅保留 `example/platform/infor-center` 与 `Example/Platform/Infor-Center` 三个顶层分组，其他组件分别归入其下。分组不成为模块身份，模块 ID、包名和 behavior key 保持不变；仅有声明或元数据的模块不补建空前端包或行为入口。后端移动时一并维护实际工程引用与 solution 路径，但不迁移数据或重写 migration 历史。

位置相关的资源读取、工作区发现和打包映射由通用机制处理，以稳定组件身份关联前端与声明目录、归组后的后端工程及正式构建产物；归组不增加 Host / Shell 逐模块接线，生成映射不得成为人工同步的第二份组件或成员清单。JSON 是组合关系事实源，前端与声明目录界定本次打包的组件集合；完整交付资产还包括后端 owner 工程的产物，不要求全部源码物理同目录。发现器和打包器核对成员声明与嵌套组件的一致性；嵌套成员仍各自拥有源码根，父组件自己的资产边界排除成员的独立资产，父后端工程也排除嵌套独立工程源码。目录 owner 由最近 Capsule 根识别，不要求固定的中间目录名；普通中间目录只归组文件，既有 Platform 角色声明保持现有 owner。以组合根发起完整集合检查时要求声明成员完整嵌套。当前入口见[内建模块开发指南](../developer/componentized-development.md#可移动组件源码根与构建)。

目录合并本身保持现有运行时输出结构、模块身份、数据归属和资产消费职责；metadata 仍由实际消费者校验和使用，不因位于 `frontend` 就一律成为浏览器静态资源。后续聚合发行按正式交付契约收集完整前后端产物，验证范围由文件类型与实际消费者决定。

聚合发行包以整个包的内容摘要标识一次交付，不另增人工维护的包版本。包索引从声明及构建产物生成，记录根组件和包内各组件的精确版本、内容摘要与相对位置；它不成为第二份组合声明或活动状态。D 的声明未变、只有 A 升版时，可以保持 D 的组件版本并生成内容摘要不同的新聚合包。每个组件内部仍遵守同 ID、同版本、同内容可复用，同 ID、同版本、不同内容拒绝覆盖；目录移动及确定性构建不得用新绝对路径、时间戳或整体仓库提交号无故改变成员内容身份。

正式发行使用既有 `modules/<ModuleId>` transport 布局以复用模型与 Capsule 消费者。原始 Capsule 保留在组件 `authoring/newp.plugin.json`；派生 `plugin.json` 只映射受控资产相对位置，静态检查必须与原声明和程序集嵌入声明严格对应。平台运行时发行声明由平台发行方维护并与实际目标框架、共享程序集/前端依赖版本和存储契约核对，不从业务 HEAD 生成。检查器只读取 PE metadata 和正式声明/模型投影；有效 checksum 或候选来源字符串不能代替可信接纳。

## 选版、启用与兼容

组合组件与成员保留各自版本，成员可以独立选版升级，不必仅为成员升级重新发布父组合。实际活动组合由各组件的明确期望选择和完整候选校验决定；独立升级不免除依赖、契约、模型及迁移前沿校验，也不引入自动依赖版本求解。

安装只增加完整库存，不改变 desired 或启用状态。明确选定并启用整个包时，新成员一并启用，已有成员保留自己的启用或停用选择；若保留的选择使活动依赖不闭合，报告冲突，不能偷偷启用依赖。整包选版遇到已选成员版本与包内版本不同，先列差异，由调用方明确选版，未明确前不写 desired，不默认覆盖、回退或选择最高版本。批量选择必须合并并保留所有未涉及组件的选择，复用现有整份 desired 的原子保存。

首版原生组件包严格匹配平台运行时发行身份，即公共运行时契约和共享依赖的受控发行版本；它不等于每次业务代码提交或根组件版本。单独发布 A/B/C 不要求重新构建 Host。跨平台运行时发行版本的包兼容不在首版承诺内。

## 可信原生交付与运行时消费

本仓原生组件包不受 ExternalPluginsEnabled 第三方插件开关影响；外部插件继续受该开关控制。原生成员的库存和期望选择不得因开关切换形成两份分叉事实。旧状态中存在冲突选择时，升级前显式核对和裁决，不能静默丢弃。

首版沿用受控本机部署授权边界：具备部署权限的操作方通过专用原生包安装入口明确接纳发行物，平台完成结构、路径、身份、兼容与内容校验后登记固定资产。普通外部插件安装入口不能授予原生身份，包内 SourceKind、profile 字段或 checksum 不能自行授予可信资格。checksum 证明内容一致，不证明发布者身份；本次不新增发行者密钥、签名与证书管理体系。聚合包不能自行授予平台组合角色或绕过必需组件保护。

运行时复用统一 Canonical Plan 和激活会话，同时明确区分可信来源、物理存储身份及前端交付方式。保留原生成员的可信身份不能强迫其继续使用 Shell 构建期内建导入表；可部署前端必须从本次验证的包资产生成 URL 入口并沿受控注册装载，保持共享前端运行时和既有 behavior binding 契约。后端必须从候选固定的程序集字节及受控依赖装载。验收目标发行物不能预先包含待装成员的静态工程引用或前端实现，以免把已有接线误认为独立安装能力。

## 数据、安装事务与恢复

目录移动和发行容器变化不得修改成员组件 ID、模型技术名称、模型及迁移 owner、已确认物理映射和已提交迁移历史。当前按可信内建来源选择 dbo、按外部来源派生 np_* 的路径不能因换运输容器而重新归类既有成员。保留已发布 migration manifest、canonical source 和可信资产；重建时以稳定构建路径及实际摘要验证既有前缀。纯组合不为打包伪造数据模型、空迁移或前后端入口。

聚合安装复用已有安装根租约，新增跨成员目录与库存的可恢复文件事务。整批校验与暂存先完成，提交前写入可恢复事实；未完成事务在下一次离线操作或 Host 读取库存前必须恢复或失败关闭，不能消费半安装集合。同一份包重复安装应幂等。此事务不连接数据库，不另建聚合数据库迁移事务，也不能以文件恢复清除 PersistenceDeploymentStore 的 pending 或保留资产。

成员自己的启用选择、单父无环校验、能力依赖闭合、停用保留和唯一 Host 迁移入口继续沿用 ADR-0055。包升级不再携带某个成员，不等于卸载该成员。整包卸载由调用方明确待卸载组件集合；单组件与集合入口在删除前整批检查必需组件保护，并用同一 Canonical 编译器验证卸载后的完整候选。保留组合的引用即使停用仍须成立，活动依赖继续按已有有效启用规则裁决；出现阻塞则保留代码、库存、选择和恢复材料，不隐式扩大或缩小集合、不先删除部分组件再发现冲突。合法代码退出仍保留全局模型身份、业务数据和 Link、迁移历史及必要可信恢复资产；归档不代替已安装库存或业务注册。不扩大为通用跨目录卸载事务。

源码或安装状态回退不得自动 Down 或重写已提交历史；存在数据库前沿变化时，使用相容的组件资产与恢复输入，不能仅按聚合包身份推断数据库可回退。

## 范围与证明

本决定扩展 ADR-0055 将聚合安装包排除在外的边界；该 ADR 的其他保护继续成立。将后端实现或迁移工程搬入 `frontend`、拆分或复制第二份 metadata 真源、完整仓外代码组件 SDK、任意第三方代码型 profile、运行期热切换、多父组合、模型改名、持久化 owner 转移和组件数据永久删除不属于本次目标。

目录归组需证明原始业务资产、现有前端包、组件身份及迁移归属保持，后端 owner 与工程引用可被正确解析，实际元数据读取、前后端构建和受影响的脚手架/检查可用，且没有两处 authoring 真源残留。纵向证明使用真实 InforCenter / Part，并覆盖 Workspace / Document：前后端归组后经通用构建映射关联，独立成员不被父工程编译或重复打包；聚合发行仍从完整前后端产物进入未预装成员实现的目标发行物，验证实际后端、前端与已有 SQL 数据及迁移历史。文件安装中断、批量选版冲突、外部插件开关、独立成员升级和聚合包重打均有对应最低层证据；最终按仓库指南集中完成适用的完整验证与 Workspace Gate。100 个组件、5 层作为已确认的规模回归场景，不据此新增硬性容量限制。
