# 对象操作统一正式写入并由对象拥有者开放动作横切

状态：已接受并由 Organization 完成首期实施。实施规格：[#215](https://github.com/yangfengfan2011/NewP/issues/215)。本决策记录已逐项确认的职责、执行语义、非目标与首期采用范围；其他模块尚未迁移。

正式业务写入统一经过对象操作入口执行适用规则，页面、导入、后台任务和模块内部调用不能因来源不同绕过对象规则。首期覆盖创建、修改、删除和具有明确名称的专用写操作；读取继续沿用现有查询、缓存和展示投影边界。对象拥有者保留业务规则与核心行为所有权，现有平台事务执行器与缓存提交机制继续各自承担提交和发布。

提供轻量对象行为基类，集中承载对象标识、支持操作及横切开放声明、默认创建更新删除行为和专用动作注册能力。业务校验直接在相应操作实现中完成，不要求对象实现成套独立的校验与核心方法；对象内部可组合已有服务。基类属于本次交付内容，继承仍是可选的开发方式，无定制行为的对象无需编写空类。横切和事务等必经流程由统一执行器保证，不依赖派生类记得调用基类方法；单次操作状态放在操作上下文，不作为行为实例的共享可变属性。

基类默认创建与更新负责接入 Entity 审计四字段赋值：创建时初始化两组相同的创建和修改信息，更新时保持创建信息不变并更新修改信息。可信主体、服务端 UTC 时间、非空及更新时间下界继续遵循 [ADR-0026](0026-entity-audit-fields-are-non-null.md)。审计值来源和赋值规则只有一份公共实现，基类默认写入与专用写入共同复用；同一次实际对象写入在行为层、持久化层、返回结果和缓存中使用相同的最终审计值，持久化层不另取时间重复覆盖，也不信任调用方提供的审计字段。

未迁移对象继续保留现有持久化层审计保障，并复用同一规则，不能因 Organization 先行采用而撤掉其他模块的保障。绕过普通 EF 跟踪的专用写入也须复用该能力；物理删除不先修改即将删除记录的审计四字段。业务审计记录与安全事件继续保持原有所有权，四字段赋值不替代业务日志。本实现调整赋值接入位置，不修改 ADR-0026 的公共不变量，也不把其他模块尚未迁移的目标记为当前事实。

对象拥有者决定哪些整个动作允许横切扩展，不逐阶段分别开放。任意组件可以向已声明的动作扩展点贡献实现；目标和依赖显式登记并在组件装配时校验，满足契约的实现随组件装配自动接入，对象拥有者不维护逐个实现的接纳名单。沿用现有启动期组件装配规则，不增加运行中热装配。这一选择允许扩展组件独立演进，同时使可扩展动作仍由对象拥有者控制。

同一扩展点允许多个实现及显式先后依赖。无依赖时采用稳定顺序，但扩展不得据此假定其他扩展已经执行；不可满足的扩展执行顺序依赖及其循环在装配阶段拒绝，不依赖扫描或注册的偶然顺序。扩展可以明确拒绝操作或补充处理，但不得替换、绕过对象必需规则，或跳过核心操作后报告成功；不同业务含义由对象拥有者提供明确动作。

操作前、操作后横切与核心操作共用同一数据库事务；操作后表示核心操作完成后、数据库提交前，任一环节失败整次回滚。本期不提供提交成功后发送邮件、调用外部系统等横切，这类副作用的可靠交付不由本契约承诺。

操作前扩展可通过受控上下文补充或修改业务输入，最终输入仍由对象拥有者在对应操作实现中、实际写入前执行必需规则校验。扩展不能任意改写主键、审计主体等受保护字段；操作后不能通过修改输入隐式触发第二次保存。

扩展可以调用另一个对象的正式操作，目标操作仍完整经过统一入口及自己的规则和横切，并加入同一事务。扩展显式声明可能调用的对象操作，平台在外层开始前汇总所需协调范围，不允许运行到横切时任意扩大写入范围；跨模块写入不能通过直接修改其他模块的数据绕过拥有者。

同一事务中，后续对象操作的规则读取必须反映前序已完成操作的新增、修改和删除，包括尚未提交的新对象。操作内部使用事务内有效视图，不能混用导致规则失真的旧缓存结果；事务外读者仍只见已发布结果，不通过提前发布公共缓存提供事务内可见性。

本决策不复刻旧平台的数据容器和继承体系；除已确定的轻量行为基类职责外，不预设实体、关系等多层继承、具体签名或注册格式，也不把业务规则转移给 EF 变更跟踪或缓存基类。本期不处理横切递归调用及多个扩展修改同字段的冲突裁决，不增加相应检测、限制或冲突机制；这不改变已确认的扩展执行顺序依赖校验。

首期完整采用范围为 Organization 的公司、部门、岗位和人员现有正式写操作，包括人员停用与恢复、永久账号绑定等专用命令。当前四类对象的普通 CRUD 及人员 `enable`、`disable`、`bind-user` 已通过正式模块装配接入；人员专用直接 DML 复用公共可信审计值并登记实际持久化变化。Identity、Authentication、Audit 等模块的独立写入口未借此迁移，本期不宣称完成全平台写入统一，也不新增导入、后台任务或其他模块的业务功能。现有跨模块事务协作仍须保持原有不变量。

回退此目标能力时，保留或恢复原有模块业务入口及其规则、审计和事务一致性；已接入的扩展依赖须随入口迁移明确处理，不得通过静默跳过扩展或允许绕过业务规则来兼容。现有 ADR-0050 的数据库提交与缓存发布保证继续成立。
