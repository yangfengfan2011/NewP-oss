# 本地正式密码只使用简单长度规则

本阶段不建设可配置密码策略引擎。用户设置的正式密码按 Unicode 字符计数，长度只要求 8–64 个字符；服务端按输入原样验证和哈希，不自动裁剪首尾空格、不转换大小写也不做 Unicode 规范化，但拒绝全空白值。不设置大写字母、小写字母、数字、符号或其组合要求，不使用常见或泄露密码黑名单，也不要求定期修改；这明确接受 `12345678` 等满足长度的常见密码可能被设置的风险。自助修改时新密码与当前密码相同则拒绝并返回稳定错误 `CREDENTIAL_UNCHANGED`，不更新凭据、不撤销会话。系统生成的临时凭据不属于正式密码，首次认证只能进入受限会话，并必须在进入 Shell 或业务页面前修改。

Development 可以继续显式使用共享临时凭据 `123456`，它是只用于开发环境的临时凭据例外，不能通过密码修改入口保存为正式密码。生产环境仍按账号生成独立随机临时凭据。该决定优先保持当前平台使用简单；密码泄露检查、历史密码、复杂度评分和可配置策略继续留待后续独立能力设计。
