# ADR-0055：组件组合独立于模型身份和已部署持久化状态

规格：[Issue #258](https://github.com/yangfengfan2011/NewP/issues/258)。

产品需要把 Workspace、Part、Document 组合到 InforCenter 下，同时保留成员的独立身份、版本与生命周期。本决策定义目标契约：组合组件形成可多级嵌套的单父无环层级，组合关系独立于实际能力依赖；组件模型以平台范围内唯一的技术名称寻址，模型 owner 仍是唯一拥有该模型的组件。成员移组不改变组件身份、模型身份、物理映射或迁移 owner，父组件不继承成员的数据所有权。

组合图采用每个组件本次期望选定版本的声明，先校验完整组合图再计算有效启用；停用组件仍参加组合校验，仅安装但未选中的新包不改变组合关系。组合声明版本与已部署持久化版本分别承担各自职责，停用期间选定新版本不推进数据库。移组或明确解除归组后保留成员自身启用选择，按新祖先关系重新计算资格；解除屏蔽不需要再次启用，若希望继续停用须在同一候选中显式关闭该成员。

可选组件卸载后仍被当前选定组合声明引用时，拒绝完整候选，即使父组件已停用；离线卸载须同时解除相关组合引用并使有效活动依赖闭合。为验证已部署数据库而保留的可信资产不代表成员仍已安装，卸载代码不删除数据、释放仍保留的模型身份或改变迁移 owner。

平台发布物指定一个平台组合，其成员声明是必需基础能力集合的唯一来源。本期复用既有 Platform 身份，初始成员为 Identity、Authentication、Authorization、Organization、Audit、ConfigCenter、MetadataConfigCenter、Files、PluginOps；组合自身及成员后代必须存在并有效启用，拒绝直接停用、卸载或祖先屏蔽，不静默改写启用选择。Platform 保留既有语言与字典贡献，成员继续各自拥有身份、版本、模型和迁移流；平台机制识别声明的组合角色，不按 Platform 名称特判。

业务组件可以省略对平台基础集合的逐项 dependencies，跨组件引用仍须满足平台基础可用或显式业务依赖，并继续核对资源、归属与实际授权。Workspace 保留对 Part、Document 的硬依赖，任一缺席而 Workspace 仍有效启用时拒绝整个候选；父组合恢复也不豁免依赖闭合。本次不新增独立的组件顺序元数据。

平台归组保留各能力现有产品入口边界，不因必需性开放冻结入口或新增在线运维；PluginOps 的候选排除规则须与新的必需身份一致，部署变更继续遵守 ADR-0032。Organization 的平台必需定位调整 ADR-0021 中的可选模块决定；Identity、Authentication 既有可信来源、模型和迁移前沿约束继续有效。Workspace、Part、Document 归入 InforCenter，Example、Demo、ModuleTemplateSample 不纳入平台必需集合；platform.foundation 仍是独立迁移流身份，不因归组变为 Platform 的成员迁移所有权。

父组件停用屏蔽全部后代的活动资格，但不改写各成员自身的启用选择；父组件恢复后按各自原选择计算有效启用。依赖缺失、重名模型或无效组合引用仍拒绝完整候选，不通过自动停用依赖者或跳过声明修复配置。停用且仍有持久化对象的模型继续占用其全局名称。

活动能力集合与已部署持久化集合分别投影，并属于同一次完整启动候选。停用组件退出业务服务、端点、页面、菜单及授权入口，其最后成功部署的表、数据和迁移账本仍参加数据库一致性校验。平台保留验证这些部署事实必需的资产；存储目标的保留不授予业务读取或写入资格。停用期间安装新版本不推进其数据库结构，重新启用时由 Host 执行正式前向迁移，成功后才提交活动状态。

各 owner 的 migration stream 独立保持线性前缀，统一账本保存实际提交顺序及不可变事实；当前候选不得按 MigrationId 重新排列已应用历史。停用组件恢复或首次启用时，不得仅因其待执行 ID 排在其他 owner 已提交步骤之前而拒绝；执行仍须满足实际依赖、Provider Target/Transition、归属、摘要和目标 frontier。该目标调整 ADR-0027 的全局有序目标前缀约束，以支持其他组件升级后再执行延期迁移；统一账本、全局迁移锁、owner 内前缀及严格一致性校验继续保留。

迁移仍按步骤提交，不承诺整轮自动回滚。在首个可能提交的数据库变更之前，必须可靠保存恢复所需的可信候选资产；进程中断后依据真实 history、目标及 frontier 核对已应用步骤，不依赖上次进程完成异常处理。首次部署尚未形成成功记录但已有步骤提交时，已落库的模型名称、物理目标及 owner 也继续被占用，不允许其他组件接管。后续迁移、校验或活动提交失败时保留已应用前缀及必要资产，阻断活动提交，不把失败候选标为成功部署，也不自动 Down 或回退；最后成功部署目标不能掩盖已应用步骤或数据库超前。

该边界选择全局名称唯一与显式 owner 校验，以换取组件重新归组不改变业务引用；选择保留已部署状态，以使独立停用不会被未知迁移或多余表校验误判。InforCenter 首次作为无自有模型和迁移流的组合组件落地，平台机制不得特判其名称。

非目标包括多父组合、模型技术名改名、持久化 owner 转移、组件数据永久删除、聚合安装包、外部代码型 profile、在线热切换和对已替换开发基线的兼容。继续遵守 ADR-0032 的停服部署与重启生效、ADR-0042 的显式实验基线重建，以及唯一 Host Up 入口、事务、迁移锁与严格历史校验。

回退不通过移组重命名表、改写 owner 或自动 Down。只涉及组合声明时可恢复原组合和启用选择；模型身份或开发基线已切换时，只能恢复配套代码与兼容数据库备份，或对经确认可丢弃的开发 catalog 显式重建，不能让旧 Host 越过新 schema frontier。
