请把当前新平台收敛到“登录后可进入主界面，并通过权限守卫访问页面”的状态。

## 一、开始前先确认

在执行前请确认以下能力至少已有雏形：
- Host 能启动
- 前端能启动
- 登录页已存在
- 登录接口已存在
- 当前用户接口已存在

如果这些前提还不存在，请不要跳过前置任务。

## 二、本轮目标

本轮只解决：
- 登录前只能看到登录页
- 登录后进入主界面
- 未登录不可访问受保护页面
- 登录后能看到受权限控制的菜单和页面
- 退出登录后会回到未登录状态

## 三、本轮必须产出的内容

请实现：
- 登录成功后的默认跳转
- 主界面基础布局
- 当前用户状态接入
- 路由权限守卫
- 菜单权限守卫
- 未登录跳转到登录页
- 退出登录后清理登录态

如果 Demo Module 已存在：
- 登录后能通过菜单进入 Demo 页面
- Demo 页面受守卫保护

## 四、本轮明确不做

这轮不要做：
- 复杂 UI 美化
- 完整门户首页
- 大规模菜单系统
- 复杂工作台
- 旧页面兼容
- 复杂权限后台

## 五、与其他模块的关系

- `Identity Lite / LocalAuth` 提供当前用户
- `Authorization` 提供权限判断
- `Demo Module` 提供最小受保护页面
- Shell 负责组合，不负责模块业务逻辑

## 六、建议实施顺序

建议按这个顺序推进：

1. 接入当前用户状态
2. 建立未登录跳转逻辑
3. 建立登录成功后的默认跳转
4. 建立主界面基础布局
5. 接入路由权限守卫
6. 接入菜单权限守卫
7. 联调 Demo Module
8. 验证退出登录后的拦截

## 七、验证要求

至少执行：
- 登录页可访问
- 默认管理员登录成功
- 登录后进入主界面
- 未登录直接访问受保护路由会被拦截
- 退出登录后再次访问受保护路由会被拦截
- 登录后能看到至少一个受保护菜单
- 登录后能进入至少一个受保护 Demo 页面

## 八、输出要求

完成后请明确说明：
- 主界面包含哪些区域
- 当前用户状态如何传递
- 路由守卫如何生效
- 菜单守卫如何生效
- 登录与退出后的跳转路径是什么
- 还有哪些地方只是占位
- 验证结果

## 九、常见误区

请避免：
- 登录成功后没有统一跳转路径
- 菜单和路由各用一套不同的权限判断
- 退出登录后仍然能访问缓存下来的受保护页面
- 先做复杂主页布局，反而拖慢闭环
