请不要直接大规模写迁移代码。先根据旧平台中的运行时元数据资产，设计“元数据迁移与兼容策略”。

背景：
旧平台可能包含大量 `.page`、`.view`、`.model`、`.schema`、`.generator`、`.dic` 等资产。
这些资产不是普通源码文件，不能简单按模块重写处理。

请完成：

1. 识别主要元数据资产类型
2. 分析它们分别承担什么职责
3. 判断每一类更适合：
- Retire
- Rewrite
- Wrap
- Import
- Postpone

4. 输出一份策略文档，至少包含：
- 资产类型
- 当前用途
- 在新平台中的目标承载形式
- 是否需要转换脚本
- 是否需要临时兼容层
- 风险与优先级

5. 如果你认为某一类资产适合先做 POC，请指出最适合先验证的一类

限制：
- 不要一口气实现全部转换器
- 先做设计和边界判断
- 不要把旧元数据机制原样复制为新平台核心机制
- 当前阶段不要把文件服务、WinApp、Studio 相关资产作为优先 POC
