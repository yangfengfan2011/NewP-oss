# 生产临时凭据按账号独立生成

生产环境为每个新建或重置的普通账号生成独立随机临时凭据，并只在设置 `Cache-Control: no-store` 的受保护成功响应及当前一次性结果弹窗中展示；弹窗允许管理员显式复制，但关闭后前端立即清除明文，不提供再次查看、导出或历史查询，响应丢失后只能再次显式重置。管理员可以重置 Enabled 或 Disabled 普通账号的凭据；Disabled 账号重置后继续保持停用，不创建会话，仍需另行显式启用才能登录，Deleted 账号拒绝重置，本地管理员继续只允许本机维护命令重置。任何系统生成的临时凭据都只能建立受限会话，用户首次登录后必须将其修改为符合 8–64 字符规则的正式密码。Development 环境可以显式配置统一的 `123456` 方便测试，作为临时凭据不受正式密码最小长度约束，但密码修改入口不得接受它作为正式密码；非 Development 环境发现共享默认凭据配置时必须拒绝启动。如果未来业务坚持在非开发环境使用公共初始码，则它不能单独建立认证会话，必须另有每账号唯一的一次性激活令牌。

管理员重置凭据前必须展示 ECODE、ENAME 与当前账号状态，要求填写原因并显式确认；服务器重新校验 Revision、账号状态和本地管理员保护。该确认不改变一次性响应语义，也不能让前端重放已经生成的秘密。
