# ConfigCenter 模块边界 v1

## 1. 模块定位

`ConfigCenter` 模块负责新平台中的统一配置、字典和枚举承载能力。

它解决的问题是：
- 配置项如何统一定义与读取
- 字典和枚举如何统一管理
- 哪些旧配置资产适合先导入新平台

它不负责：
- 复杂审批式配置发布
- 大而全的配置后台平台
- 所有旧元数据的一次性收编

## 2. 当前边界

### 纳入范围

- 配置项模型
- 配置读写接口
- 字典模型
- 枚举承载入口
- 轻量配置导入能力
- 环境级扩展位

### 排除范围

- 所有旧元数据全量导入
- 复杂规则引擎
- 可配置开发平台整体迁移
- 工作流、报表等领域配置收编

## 3. 输入与输出

### 输入

- 新平台模块声明的配置项
- 旧平台的 Setting / Dictionary / Enumeration 资产
- 环境级或部署级配置值

### 输出

- 配置查询接口
- 配置修改接口
- 字典查询接口
- 枚举导入或映射结果

## 4. 推荐内部结构

- `ConfigCenter.Contracts`
  - 配置项定义
  - 字典模型
  - 配置查询接口
  - 导入接口

- `ConfigCenter.Core`
  - 配置聚合逻辑
  - 覆盖规则
  - 配置校验

- `ConfigCenter.Infrastructure`
  - 持久化
  - 缓存
  - 导入器

- `ConfigCenter.Web`
  - API
  - 配置管理页或调试页

## 5. 与其他模块的边界

### 对 Host

- Host 只负责装载和注入
- Host 不应自行维护模块配置

### 对 Authorization

- 权限模块可以读取配置开关
- ConfigCenter 不负责权限决策

### 对 Audit

- 配置变更可以触发审计事件
- 审计记录的写入由 Audit 模块负责

### 对迁移层

- 旧配置导入器优先放在导入层或基础设施层
- 不把旧配置文件结构直接暴露给业务层

## 6. 旧平台参考来源

当前最值得参考的旧资产和模块：
- `Source\7_Business\12_SystemSettings\*`
- `Source\7_Business\09_Enumeration\*`
- `Runtime\1_Server\Config\Setting`
- `Runtime\1_Server\Base\Config\Dictionary`

参考原则：
- 提炼配置项模型和字典/枚举语义
- 优先导入，不优先复制旧配置系统实现

## 7. 最小可交付版本

V1 最小可交付版本应包含：
- 配置项定义和查询
- 最小配置修改能力
- 字典承载入口
- 枚举导入或映射样例
- 一类旧配置资产导入 POC

## 8. 风险与提醒

- 容易把 ConfigCenter 做成“大而全”的平台，导致范围失控
- 容易把所有旧元数据都塞进来，导致第一阶段过重
- 如果没有统一模型，后续模块会继续各自存配置
