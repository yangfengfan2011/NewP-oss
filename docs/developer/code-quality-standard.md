# AI 代码生成规则

本规则适用于 AI 新增或修改生产代码、测试、脚本和模板。首次编辑前完成“生成前”，生成过程中按最小可验证切片推进；编译、lint、测试和审查只确认结果。

## 生成前

1. 读取当前任务、相关调用链、相邻实现、对应测试和目标项目配置。
2. 明确一个行为变化、必须保持的不变量、非目标、失败信号和最小验证。
3. 确认代码所有者、状态归属、依赖方向和跨边界数据形状；触及设计门禁时先取得已确认设计。
4. 判断是否位于启动、逐请求、逐渲染、循环、数据库、网络或批处理等成本路径，并确认输入和工作量上界；无法从当前契约或配置证明上界时，按无界处理。

准备完成：能够简要说明改什么、在哪里改、如何失败、成本在哪里、用什么证明。

## 生成中

- **切片**：每次只生成一个可独立解释、验证和回退的行为。改变生产行为时，先形成可复现 RED 或等价失败证据，再生成最小实现。
- **清晰**：名称表达领域职责；类型和函数保持单一内聚职责；状态、依赖和副作用局部且显式。简洁以需要同时理解的概念更少为准，不以行数更少为准。
- **边界**：实现放在职责所有者内。共享抽象只承载多个真实调用者共同拥有的不变量；兼容路径只来自明确需求，并带退出条件。
- **失败**：只在能够恢复或在边界翻译为稳定结果时捕获异常；取消继续传播，重试具备幂等语义和次数上限。日志提供稳定诊断信息并排除秘密与敏感数据。
- **规模**：上界未知的输入使用分页、显式限制或流式处理，避免先完整物化再裁剪。
- **数据访问**：可下推的筛选、排序和分页由数据源执行。循环处理前批量读取所需数据或调用批量接口；保留逐项访问时必须能证明固定且足够小的上界。
- **异步并发**：使用现有异步 I/O API 并沿调用链传递取消，不使用 `.Result`、`.Wait()` 或等价阻塞。并发必须有显式上限和失败聚合；不对无界集合直接使用 `Task.WhenAll`、`Promise.all` 或等价操作。
- **启动**：Host 和 Shell 初始路径只装载启动必需能力，模块业务实现保持可裁剪和按需装载。
- **缓存**：为性能引入缓存时必须已有性能证据，并同时明确容量上限、生命周期、失效和一致性语义。
- **测量**：任务包含性能目标或触及现有 Gate 时，在生成实现前确定基线、指标、环境和复跑入口。没有指标时明确报告，只能说明已规避哪些结构性风险。预算及执行规则读取当前配置、runner 和测试；超限时报告实测值、预算来源和可选处置，由任务发起者决定。
- **证明**：行为与最小充分证明在同一切片生成，覆盖成功路径、任务关心的失败路径和被修改边界的不变量。
- **注释**：按[代码注释规则](code-commenting-guidelines.md)解释原因和边界。生成资产从生成器、模板或其他上游事实源修改。

## 每个切片完成条件

- 行为、所有者和边界与当前事实源一致。
- 每个修改的类型或函数都能用一句话说明职责，状态和副作用可从签名与局部调用链识别。
- 适用的失败、取消、重试、回滚和成本语义已经明确。
- 随输入增长的工作量有上界、分页或流式边界，没有对无界输入逐项远程访问或启动无界并发。
- 没有无依据的公共抽象、兼容或缓存；交付行为与最小充分证明一起生成。

验证用于证明以上条件成立。同类问题反复到检查阶段才出现时，修正本规则、生成入口或模板，让后续代码在生成时满足要求。
