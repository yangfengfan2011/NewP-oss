# 常规关系树使用配置驱动的 Provider，自定义树保留业务实现

常规主外键树不需要每个模块重复实现根、直属读取、搜索、路径和变更映射。平台提供 `platform.relations`，模块在 Tree View 的 `relationSource` 中声明节点来源与父关系；特殊业务继续通过稳定 `providerKey` 注册完整自定义 Provider。这扩展 ADR-0046 中“Provider 实现均归模块”的边界，不改变树宿主的布局、页面组合或写入协调职责。

## 边界

- Tree View 的 `nodeTypes` 拥有页面呈现，`relationSource` 拥有静态读取映射。两者节点类型必须一一对应；配置不得包含 SQL、脚本或请求拼接表达式。
- 第一版消费已签发内建模块的冻结 metadata，与活动计划使用同一份字节。节点引用本模块已注册的 Standard CRUD 资源，复用其模型、列表读取字段与查看权限；物理表列由 EF 模型决定。该资源的 Query Customizer 条件与静态条件相交，无法翻译的条件拒绝执行，不能省略约束。
- 平台 CRUD 查询侧拥有标准关系读取和 API。Host 只负责装配；Shell 选择通用或自定义 Provider，不解释公司、部门等业务字段。Organization 是真实采用者，业务模型、生命周期及内容页面输入仍由 Organization 拥有。
- 通用性由代码中的查询编译器承担：按配置生成物理外键条件、子表 EXISTS 和原生字段投影，不为通用化引入全局父键分组、逐行父表回查或数据库 JSON 组装。单字段父关系无需额外父集合连接；复合外键在读取时保留完整匹配。结果列映射每个结果集解析一次，上下文由代码组装。
- 父关系显式指向模型外键，复合外键全部分量参加匹配。多个候选父关系按顺序取首个非空外键，后备关系必须显式标记；这不表示多父级。单模型层级可显式允许空父级作为根。
- 根及直属读取仍按层返回完整集合。搜索在数据库中匹配、计数、稳定分页，再批量解析该页祖先；不在应用端预载全树。节点存在性与祖先完整性分别判断，断链和环不伪装成不存在。
- API 每棵树要求其全部节点资源的查看权限，请求只能选择已配置的树和提交范围、节点身份、关键词及分页值。第一版只接受显式全局范围；配置过滤不能替代业务授权，也不自动把被过滤父节点的后代提升为根。
- 变更位置按同一关系配置推导；缺少快照、重复实体投影或过滤可能改变成员资格时，使用现有未知变化协调，重新读取已加载范围，不重放写入。

## 非目标

不引入新的业务模型、通用关系存储、任意图、多父级、人员入树、同级分页、任意表达式、跨模块数据直读或外部插件树 authoring。当前 SQL 实现面向 SQL Server；不宣称固定往返次数等于数据库成本有界，也不声明未经规格确认的容量保证。

## 回退

回退标准 Provider、服务端装配与 Organization 配置时必须配套恢复前端 Provider 注册和胶囊引用。现有组织专用 API 保持原有行为，本次不改变业务数据及数据库结构；业务模块的自定义 Provider 契约保持可用。字段契约与接入方式见 [配置指南](../developer/relation-tree-configuration.md)。

## 后续决定（2026-09-11）

组织专用树 API（`/api/organization/tree/*`）、`OrganizationTreeReader` 与 `Organization.Tree.Read` 策略已退役。核实结果：前端与验收旅程均只消费 `/api/trees/organization.structure/*`，旧端点没有受支持的调用方，也没有版本化兼容承诺；其权限拒绝、参数校验与四类读取的等价断言已由标准端点测试覆盖。上文回退段中「现有组织专用 API 保持原有行为」不再适用；回退标准 Provider 时需恢复该 API 的实现与前端 Provider。`DepartmentHierarchyQuery` 承担父级候选与防环校验，职责不同，继续由 Organization 独立拥有。
