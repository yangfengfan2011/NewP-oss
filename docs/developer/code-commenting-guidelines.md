# 代码注释规则

本规则定义仓库全部代码的注释要求。逐方法强制范围是手写生产 C# 代码，不按目录或模块区分。

## 方法级强制规则

- 新增或修改的手写生产 C# 方法必须有与当前行为一致的注释。未触碰的历史方法不阻塞当前任务，历史注释债务按模块单独治理。
- 强制范围包括普通方法、构造函数、本地函数和运算符重载。
- 公共 Contracts 和 SDK 的 `public` 方法使用 XML 注释，说明职责、关键参数语义和非直观的返回结果。接口实现和重写方法可使用 `/// <inheritdoc/>` 继承已有说明。
- 其他方法在方法前使用简短注释说明职责或实现意图。简单方法只需一句，不为了长度重复方法名或实现细节。

## 非逐方法强制范围

- 测试代码不强制每个方法写注释。历史回归、复杂前置条件、异常顺序和回滚路径在测试块前说明测试意图。
- 脚本不强制每个函数写注释。凭据处理、破坏性操作、迁移、回滚和环境前提必须说明安全边界。
- 前端 TypeScript/JavaScript 不强制逐函数注释。模块接入、关键状态关系、兼容假设和非直观的错误处理在相关代码块前说明。
- Lambda、匿名方法以及简单的属性或事件访问器不强制单独注释；存在非直观逻辑时在所属代码块前说明。
- 生成器、模板或工具产出的代码和构建产物不手工补注释。生成的公共契约需要注释时，修改其生成器或模板。
- 工具生成的 Migration 方法不强制逐方法注释。手写数据迁移、兼容处理、不可逆操作和特殊回滚逻辑必须说明原因和恢复边界。

## 高价值注释

注释优先补充代码本身不能直接表达的信息：

- 实现为什么存在，以及哪些边界不能被打破。
- 关键的宿主装配、跨模块协作、状态切换、投影、冲突处理、安全保护和回滚流程。
- 失败时的可观测信号、验证方式和恢复思路。

代码块注释通常使用 1 到 3 行，放在相关代码块前。新增注释默认使用简体中文；文件长期使用英文注释时保持一致，协议名、接口名、字段名和错误字面量保留原文。

修改代码时同步更新相关注释，并删除已失效的说明。注释不逐句翻译赋值、条件、循环和返回语句。

## 修改自检

完成代码修改前检查：

- 每个新增或修改的手写生产 C# 方法都有与当前行为一致的注释。
- 不强制逐方法注释的代码已按本文档的条件规则补足高价值说明。
- 关键边界、状态切换、失败信号和回滚路径没有依赖隐性知识。
- 注释与实现、Context、ADR 和 Contracts 使用一致术语。
