# 第二阶段实施计划：最小可运行平台

## 1. 阶段定位

第二阶段的目标不是继续“补框架”，而是把新平台推进到“最小可运行平台”状态。

这里的“最小可运行”必须同时满足：
- 后端可启动
- 前端可启动
- 有登录页
- 能用默认管理员登录
- 登录后能进入主界面
- 主界面有基础菜单与路由容器
- 至少有一个受保护的 Demo 页面可访问
- 前后端都能识别当前用户

如果做不到以上闭环，就还不能算平台雏形成立。

## 2. 阶段目标

第二阶段必须完成以下 6 件事：

1. 固化 Host 和前端 Shell 的最小启动路径
2. 实现 `Identity Lite / LocalAuth`
3. 建立默认管理员和本地种子数据
4. 打通登录后进入主界面的闭环
5. 接通 Demo Module 与权限守卫
6. 完成一轮最小 smoke 验证

## 3. 明确纳入范围

### 必做

- `apps/host-api` 启动入口可运行
- `frontend` 或 `apps/admin-web` 启动入口可运行
- 登录页
- 登录接口
- 当前用户接口
- 退出登录接口
- 本地登录态机制
- 默认管理员种子账号
- 前端登录态守卫
- 主界面壳布局
- Demo Module 菜单和页面接入
- 一个受保护页面的访问闭环

### 建议同步补齐

- 健康检查接口
- 基础错误处理
- 未登录跳转
- 登录成功后的默认跳转页
- 最小 smoke 验证文档

## 4. 明确不纳入范围

第二阶段默认不做：
- 完整用户中心
- 组织树
- 租户体系
- 单点登录
- LDAP / OAuth / OpenID Connect 深度接入
- 文件服务重写
- WinApp / Studio
- 工作流、报表和设计器
- 大规模旧页面兼容

## 5. 推荐拆解任务

### Task 2.1：固化最小启动主干

目标：
- 后端启动路径清楚
- 前端启动路径清楚
- 启动脚本和 README 不误导

产出：
- 可运行的 Host
- 可运行的前端启动入口
- 更新后的启动说明

完成标准：
- 后端可启动
- 前端可启动

### Task 2.2：实现最小登录能力

目标：
- 存在 `Identity Lite / LocalAuth`
- 支持本地登录、退出登录、当前用户查询

产出：
- 登录 API
- 当前用户 API
- 退出登录 API
- 认证上下文接入

完成标准：
- 默认管理员登录成功
- 当前用户可返回

### Task 2.3：建立种子数据与默认管理员

目标：
- 本地开发环境第一次启动即可验证登录

产出：
- 默认管理员账户
- 种子初始化逻辑
- 账号说明

完成标准：
- 无需手工造数即可登录

### Task 2.4：前端登录闭环

目标：
- 登录页可访问
- 登录成功后进入主界面
- 未登录时无法访问受保护页面

产出：
- 登录页
- 登录表单提交
- 登录态存取
- 登录后跳转
- 未登录跳转

完成标准：
- 登录与退出流程完整跑通

### Task 2.5：主界面与 Demo Module 联调

目标：
- 登录后主界面可见
- Demo Module 在菜单中可见
- Demo 页面可通过路由访问

产出：
- 主界面布局
- 菜单容器
- Demo 路由接入
- 权限守卫联动

完成标准：
- 登录后能访问一个受保护的 Demo 页面

### Task 2.6：阶段验收与 smoke

目标：
- 用固定步骤验证第二阶段闭环

产出：
- 验证步骤
- 验证结果
- 剩余问题清单

完成标准：
- 可以按文档重复完成一次登录到页面访问的闭环

## 6. 推荐执行顺序

建议严格按下面顺序推进：

1. `Task 2.1` 固化最小启动主干
2. `Task 2.2` 实现最小登录能力
3. `Task 2.3` 建立种子数据与默认管理员
4. `Task 2.4` 前端登录闭环
5. `Task 2.5` 主界面与 Demo Module 联调
6. `Task 2.6` 阶段验收与 smoke

不要跳着做。
特别不要在登录闭环没打通前就急着做复杂模块。

## 7. 阶段交付物

第二阶段至少应交付：
- `Identity Lite / LocalAuth` 第一版
- 登录页
- 登录、当前用户、退出登录接口
- 默认管理员种子账号
- 主界面壳
- Demo Module 菜单与页面
- 最小 smoke 验证文档

## 8. 阶段完成判定

只有同时满足下面条件，第二阶段才算完成：

- 后端构建通过
- 前端构建通过
- 后端可启动
- 前端可启动
- 登录页可访问
- 默认管理员可登录
- 当前用户接口可用
- 退出登录后受保护页面不可访问
- 登录后可进入主界面
- Demo Module 菜单可见
- Demo 页面可访问

## 9. 风险提醒

- 第二阶段最容易被拉歪成“完整身份平台”，要避免
- 最容易被忽略的是默认管理员和种子数据，没有这两个本地联调会很痛苦
- 最容易出现的伪完成是“接口有了，但登录闭环没跑通”
- 第二阶段做完前，不要宣称平台“已经能用了”
